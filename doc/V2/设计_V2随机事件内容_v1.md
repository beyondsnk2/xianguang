## 二、事件 Schema（落地版）

基于文档 §7.1，**裁掉未实现维度**（称号/势力/节令/钱粮/战斗/小游戏），新增关系咬合字段。

```
event:
  tag, name, type(①见闻/②遭遇/③二选一/④奇遇/⑥地盘),
  title, text,                    # 支持 {city} {npc} {skill} {item} 变量
  # ── 触发条件（标签筛选）──
  condCity, condFacility,         # 地点：城市 tag / 设施 tag（空 = 不限）
  condNpc, condFavorMin,          # 人物：武将 tag / 最低好感阶段
  condSkill, condSkillLv,         # 技能 tag + 最低等级（Q11 技能偏向）
  condItem, condPrev,             # 持有物 / 前置事件
  onceOnly,                       # 是否一次性（见闻多为一次性）
  # ── 权重 ──
  weightBase, weightSkill,        # 基础权重 / 技能命中加成
  ttl(秒), coolDown(秒),
  # ── 结算 ──
  attr(主属性), attrXpMin, attrXpMax,     # 属性经验（★ 兼作「展示属性」走事迹传播）
  favorNpc, favorDelta,                   # 指定武将好感（0 关系时视为初识）
  spreadDeed(0/1),                        # 是否按 attr 触发事迹传播（默认 1）
  giveItem, giveItemNum, giveMingpin,
  jianwen,                        # 见闻条目 tag
  # ── 交互 ──
  optionRef(none/binary/multi),
  logHigh(是否进 highlights), rarity(事件流档位 0/1/2), note
```

`eventOption`（二选一 / 多选项分支）：
```
eventOption: tag, eventTag, text, attr, attrXp, skill, skillXp, favorNpc, favorDelta, item, itemNum, jianwen, note
# 方案2：skill/skillXp = 本选项给「技能经验」（与 attr/attrXp 二选一或并存），须与事件主题贴合
```

## 三、双源触发与权重闸门（落地版）

### 3.1 触发（沿用文档 §3.1，挂到现有 tick）

| 源 | 机制 | 落地位置 |
|---|---|---|
| 时间源 | 仅「赶路(moving)」阶段累积事件点（working / 回城 / 空闲不累积，离线冻结）；每次触发后间隔在 **5~15 分钟**间均匀随机、期望 **10 分钟**；每日上限 `EVENT_DAILY_CAP` 已放开（实际不封顶） | `tick.ts` 仅在 `phase.kind==='moving'` 时调用 `advanceEventClock`（见 §3.3） |
| 行为源 | **到达新城市**（已定 Q-C4 包含）/ 首次造访设施 / 完成品质 ≥7 的任务 → 立即触发一次机会 | `settleTask` + 移动结算到达处 |

> 密度对齐文档实测：单任务 ~8.8 分钟 → 约每 7–8 个任务 1 个事件，不打断挂机节奏。

### 3.2 权重闸门（去掉称号与势力，保留三路）

```
候选池
 ↓ ① 标签筛选（城市 / 设施 / 武将 / 技能 / 持有物 / 前置 / 已解锁）
 ↓ ② 类型基础权重（见 §五每类表头）
 ↓ ③ 偏向修正：技能(Q11) + 属性补偿(F19c) + 人物好感
 ↓ ④ 冷却去重（同 tag 冷却、同类连出抑制）
 ↓ 加权随机抽取
```

| 闸门 | 落地方式 | 参数 |
|---|---|---|
| **技能 Q11** | 9 技能按 cls 归三组，命中则 `weight += weightSkill` | A组(采掘/采药/猎奇)→武力向+见闻；B组(锻造/丹鼎/机巧)→智力向+地盘；C组(访道/结义/出使)→政治向+奇遇/人物 |
| **属性补偿 F19c** | 四维落后预期 → 提高对应"给属性"事件权重 | ≤ 当日事件总数 ×10%，只给属性，不追平 |
| **人物好感** | `relations[npc]` 越高 → 该武将专属事件权重越高 | 让关系变"钥匙"而非装饰 |
| ~~称号~~ | 未实现 | 预留字段，本轮不参与 |

### 3.3 时限与离线（沿用文档 §3.5 建议 A）

> **已定（Q-C3）**：首版**不做分层时限**，全部事件统一 **4 小时**；容器上限 **10**。
> （分层时限与"①见闻无限"留待数值调优时再开。）

| 层 | 时限（首版统一） | 过期后果 |
|---|---|---|
| ①风土见闻 / ②路人遭遇 / ③二选一 / ④奇遇 / ⑤地盘事件 | **4h** | 失去机会（只失去"这次机会"，不倒扣） |

- 容器容量 **≤10**；超限 = 失去内容（**明示**被挤掉者）。
- **离线冻结**：事件只在线生成，下线后不再计时（不惩罚离线）。
- 三条红线落地：过期/溢出只失去"这次机会"，**永不倒扣**已有属性/物品/好感；错过的事件进事件流明示。

## 四、与现有系统的接口（★ 本轮新增的关系咬合）

| 现有能力 | 接口 | 本设计如何用 |
|---|---|---|
| `addAttrXp` | 属性经验唯一入口 | 事件给属性经验。**已定（Q-C2）不切换来源**：任务侧 `gainTaskAttrXp`（T7 临时桥）**保留**，事件**另给一份**，二者并存；待事件密度稳定后再评估是否下调任务侧 |
| `propagateDeed` | 事迹传播 | **事件结算后按 `attr` 作为展示属性走一次事迹传播**（`spreadDeed=1`），一对多涨相关武将好感 |
| `maybeFirstMeet` | 初识事件 | 事件带 `favorNpc` 而该武将 `relations==0` 时 → **视为初识**，注入 `REL_FIRST_MEET` 并发「初识」事件 |
| `state.relations` / 阶段 | 分武将好感 | `favorNpc + favorDelta` 直接加好感；高好感提高该武将专属事件权重 |
| `emitEvent` / 事件流 | 稀有度 0/1/2 | 事件的处理结果进事件流；`logHigh` 者额外进 highlights |
| 物品 / 名品 / 图纸 | `addItem` + `state.blueprints` | 奇遇给名品、地盘给图纸 |
| 23 武将 `GENERALS` | 人物池 | `{npc}` 变量与 `condNpc` 的来源 |

> **关系咬合的意义**：文档 §九 写明"事件产生事迹 → 一对多影响好感，是 C 类任务给好感的**补充渠道**"。
> 落地后，事件的展示属性（如"夜遇老者授书" = 智力）会让所有**偏好智力**的武将同涨好感 ——
> 于是"我练访道 → 多遇名士 → 诸葛亮/司马懿/周瑜一起涨"形成闭环，正是文档 §3.3 "挂机→在线的反馈闭环"。

## 八、选项奖励差异化设计（双方案 v1 · 先审稿）

> 问题：当前二选一事件的选项**没有选择依据**——奖励只是把 `force/leadership/intelligent/politics` 随机分给不同选项（或属性经验 vs 好感/物品），玩家只能"挑数字大的"，看不出"为什么选 A 给武力、选 B 给统帅"。
> 现状约束：`EventOptionDef` 仅支持 `attr / xp / favorNpc / favor / item / itemNum / jianwen / jianwenName`，**没有技能经验字段**（事件结算只有属性经验这一条成长轴）。
> 下面给出两份方案，分别对应"纯现有字段差异化"与"引入技能经验作为第二成长轴"。

### 8.1 方案 A — 方向锚定型（纯现有字段，零代码改动）

**核心**：给每个选项挂一个明确的"人设 / 养成方向"标签，奖励严格匹配方向，让选择有叙事依据而非数值盲选。

**方向词典（5 向）**：

| 方向 | 主属性 / 外物 | 语义 |
|---|---|---|
| 武勇 | `force` | 临场搏杀、胆略 |
| 统御 | `leadership` | 调度、治安、行军 |
| 智略 | `intelligent` | 观察、机变、学问 |
| 权谋 / 仁政 | `politics`（+好感/物品） | 谋略、施政、恤人 |
| 机缘 | 物品 / 见闻 / 名品 | 不涨属性，走"外物"线 |

**规则**：
1. 每个二选一选项**必须归属一个方向**；奖励 = 该方向主属性经验（或机缘类的外物）。不允许"两个选项都给属性经验且无叙事区分"。
2. 强 / 弱选项做"叙事一致"的数值微调：高风险高回报选项给更高属性经验，但附代价文本（误程 / 涉险）；低风险选项给平稳属性经验 + 见闻。
3. 保留"属性经验 vs 好感 / 物品"的**硬岔路**（如 `en_fangshi`、`en_beggar_scholar`）作为"人 / 物 / 关系"的价值选择——这是最有依据的一类。

**改写示例（基于现有事件）**：
- `ch_guanroad` 岔口之择 → "稳 vs 险"：
  - 走官道（稳·统御）：`leadership 2-4` + 见闻「盘查关防」
  - 抄小路（险·武勇）：`force 5-7` + 随机 rare 物品（拾得遗物）
- `en_xia_you` 游侠之问 → "武勇 vs 权谋"：
  - 提剑除暴：`force 4-6`；归耕读书：`politics 4-6` + 见闻「耕读之论」
- `ch_hunter` 猎户邀猎 → "动手 vs 观察"：
  - 追之（武勇临场）：`force 5-7`；止步观猎（智略）：`intelligent 3-5` + 见闻「兽迹辨识」
- `en_fangshi` 方士索金 → 保留"机缘 vs 务实"硬岔路：
  - 倾囊求药（机缘/丹道）：`item:'rare'` + 见闻「炼丹之说」；笑而谢之（智略务实）：`intelligent 3-5`

**优点**：0 代码，立刻可落地；选择有叙事依据。
**缺点**：仍是"属性经验"单一成长轴，玩家易只盯数值最高属性（`force/politics` 最常用）导致偏好极化；无法与 V2 已建的 9 技能系统联动。

### 8.2 方案 B — 属性经验 vs 技能经验（新增 `skillXp` 字段，需小幅扩展）

**核心**：把事件结算从"只有属性经验"升级为"属性经验 + 技能经验"双轴。二选一时，**一个选项给四维属性经验（临场应变 / 决断），另一个给技能经验（钻研 / 操练的专长积累）**，且**必须包装贴合该技能主题**。

**落地前提（仅列，不实现）**：
- `EventOptionDef` 与 `EventDef` 新增字段：`skill?: string; skillXp?: [number, number]`（并同步更新本文档 §二 `eventOption` 的 Schema）。
- `resolveEvent` 在结算顺序末尾增加：`if (rw.skill && rw.skillXp) addSkillXp(state, cfg, rw.skill, randInt(state, rw.skillXp[0], rw.skillXp[1]))`（复用 `skill.ts` 的 `addSkillXp`，与任务侧同源）。
- 技能经验数值建议对齐任务侧：参考 `taskGen` 品质 → 技能经验映射，事件单次给固定中值（事件无评价分级）。

**规则**：
1. **贴合格配**：带 `skillXp` 的选项，其 `skill` 必须与事件的 `skill / condSkill` 或文本主题强相关；不相关的事件一律不给技能经验，避免"什么事件都能练技能"。
   - 带 `skill:'hunting'` 的猎户事件 → 观猎选项给 `hunting` 技能经验；带 `skill:'danding'`(丹鼎) 的方士事件 → 求药选项给 `danding` 技能经验。
2. **属性 vs 技能 的语义分工**：
   - 属性经验 = "这次遇事临场应对，长了见识 / 胆略"（通用、四维）
   - 技能经验 = "借此机会钻研 / 操练了某专长"（定向、9 技能）
3. 仍保留"属性 vs 好感 / 物品"的纯价值岔路（机缘类），不与技能轴冲突。

**改写示例（基于现有事件）**：
- `ch_hunter` 猎户邀猎（已 `skill:'hunting'`）→ "临场武勇 vs 钻研狩猎"：
  - 追之（临场）：`force 5-7`
  - 止步观猎（钻研）：`skill:'hunting', skillXp:[6,9]`
- `en_fangshi` 方士索金 → "务实 vs 丹道钻研"：
  - 笑而谢之（务实临场）：`intelligent 3-5`
  - 倾囊求药（钻研丹道）：`skill:'danding', skillXp:[5,8]` + 见闻「炼丹之说」
- `qy_wolong` 草庐昼寝 → "谋略临场 vs 礼贤钻研"：
  - 问天下大计（临场谋略）：`politics 18-22`（奇遇高值保留）
  - 请其出山：`favorNpc:'zhugeliang', favor:10` + `skill:'fangdao'(访道) skillXp:[12,16]`（"请教兵法谋略"的钻研，favor 为主、技能经验为辅）
- `ch_ferry` 渡与绕 → 无强技能主题，保持纯属性岔路不动（说明"非所有事件都适合技能轴"）。

**优点**：真正差异化两条成长线，让"事件（属性 / 关系 / 机缘）"与"挂机任务（技能）"养成互补；呼应 V2 已建 9 技能系统；选择依据清晰（临场 vs 钻研）。
**缺点**：需新增 2 字段 + 扩展 `resolveEvent`（约 10–15 行）；技能经验数值需校准，避免事件技能经验碾压任务侧；需内容校验保证"贴合格配"不被忽略。

### 8.3 对比与取舍

| 维度 | 方案 A 方向锚定 | 方案 B 属性 ↔ 技能 |
|---|---|---|
| 代码改动 | 0（纯内容设计） | 小（2 字段 + `resolveEvent` 分支） |
| 成长轴 | 仅四维属性 | 属性 + 9 技能 双轴 |
| 选择依据 | 人设 / 方向标签 | 临场应对 vs 专长钻研 |
| 与 V2 技能系统联动 | 无 | 强（呼应任务技能线） |
| 落地速度 | 立刻 | 需一轮实现 + 数值校准 |
| 平衡风险 | 低（只调属性分配） | 中（技能经验数值需控） |

**建议**：方案 A 可作"立刻能上"的过渡；若希望事件真正参与 V2 技能养成、避免玩家只刷属性，推荐方案 B，并复用任务侧 `addSkillXp` 与品质 → 技能经验映射以保证数值同源。两方案在"属性 vs 好感 / 物品"的硬岔路上一致，可同时保留。

### 8.6 任务成长定向：抱负 + 节奏（第三轮 · 2026-10-05 已落地）

> 问题：原任务生成「等概率抽全部技能」，9 条技能线无定向，玩家成长全随机、build 无差异化；且地域被城市绑死、品质无玩家可控旋钮。本轮引入**单一口子 `ambition`（抱负）** 做成长定向，**独立旋钮 `pace`（节奏）** 做品质窗口偏移，二者解耦，规避跨抱负品质失衡。

**① 单一口子 `ambition`**：枚举 `free | wen | wu | zong | fang`，默认 `free`（= 旧档纯随机，不破坏既有存档）。仅改 `genTask` 两处（抽技能加权 + 品质窗口交独立旋钮），未来官职/威名系统直接读写同一字段，生成逻辑零改动。

**② 抱负 → 技能映射（每抱负 = 1A 采集 + 1B 制造 + 1C 人物，并集覆盖全部 9 技能，无暗偏）**：

| 抱负 | A 采集（武力·材料） | B 制造（智力·成品） | C 人物（政治·稀有/名品） |
|---|---|---|---|
| `free` 自由 | — 全技能等概率 — | — | — |
| `wen` 文治 | herbalism 草药 | alchemy 炼丹 | visiting 访道 |
| `wu` 武功 | hunting 狩猎 | smithing 锻造 | sworn 结义 |
| `zong` 纵横 | mining 采矿 | crafting 工造 | envoy 使节 |
| `fang` 方外 | herbalism 草药* | alchemy 炼丹* | sworn 结义* |

- 加权：偏好技能相对权重 4，其余 1 → 约 2/3 生成任务的技能落在抱负集合内（留出 1/3 随机扰动，避免完全锁死）。
- `fang` 故意与 `wen`/`wu` 交叉（草药/炼丹/结义），作"跨抱负探索"档，验证映射可重叠。

**③ 成长落点（每抱负对称，杜绝偏科）**：属性 = 武力 + 智力 + 政治（各 1 源）；物品 = 材料 + 成品 + 稀有（各 1 源）；社交 = 1 条名品/好感线（来自 C 技能）；技能经验 = 3 个技能槽。**统帅（leadership）无任务来源**——按既定决议纯由随机事件养成，任务线只管武/智/政三属性，与事件互补、分流清晰。

**④ 独立旋钮 `pace`（稳 / 中 / 搏）**：只调品质窗口偏移（稳 −1 / 中 0 / 搏 +1，钳制在 1–9），**不绑死抱负**，故抱负多选不会引发跨抱负品质失衡。窗口内三档权重形状仍由技能 tier 决定，pace 只平移窗口不扭曲分布。

**⑤ 地域不收口**：城市全图随机（游历核心，赶路不可控即预期），抱负只管"练哪条技能"，不管"在哪练"。

**⑥ UI**：角色面板（menu-char）新增「抱负」「节奏」两个下拉，改动即时写入 `state` 并 250ms 重渲染；旧档缺字段时 `ensureRuntimeFields` 兜底为 `free`/`mid`。

**⑦ 自检（npm run check）**：断言 `AMBITION_SKILLS` 四抱负并集覆盖 `cfg.skillDefs` 全部 9 个技能 tag（防映射漏技能），并校验 `pace` 偏移后窗口始终落在 [1,9]。
