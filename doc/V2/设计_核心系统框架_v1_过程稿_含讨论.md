## 二、成长体系（四层）

### 2.1 四层职责定义（不可推翻）

| 层 | 职责 | 一句话 | 与其他层的关系 |
|---|---|---|---|
| **职业称号** | **刷出什么** | 决定任务池与高品质任务/奇遇的概率 | 解锁高品质任务 |
| **个人属性** | **完成得怎样** | 决定基础产出与成功率 | 由任务与事件积累属性经验 |
| **官职** | **额外加成什么** | 特定任务/互动事件/比试的额外倍率与特殊结算项 | 由品级 + 职业 + 属性共同决定 |
| **个人等级** | **总量** | 提供自由点，玩家自由分配 | 与挂机时长/任务数挂钩 |

> **这条分层是整套系统的地基**：它保证"刷什么"与"有多强"解耦，
> 继承 V1 决策（技能管多强、装备管刷什么，**绝不能让玩家产生"我想把等级降下来"的念头**）。

### 2.2 个人等级

| 项 | 规则 |
|---|---|
| 来源 | 挂机时长 / 完成任务数量，**持续成长，速度随时间放缓** |
| 限制 | **不受其他系统限制**（不因技能卡等级上限而卡住） |
| 产出 | **自由属性点 / 技能点**，供玩家自由分配到其他系统 |
| 设计目标 | 自由点用于**强化倾向性**或**补短板** |
| 数值约束 | ⚠ **必须保证不存在"全点满"的解**——用数值控制（非结构上限）实现 |

> ⚠ **长线隐患（已记录）**：若自由点无限累积至全满，"自由分配"这个卖点会自我消解（全点满 = 无选择）。
> 解决手段是数值而非结构：**任何时点的可用自由点必须始终小于可分配项的需求总量**。

### 2.3 个人属性

| 项 | 规则 |
|---|---|
| 来源 | 主要由**完成任务与事件**积累属性经验 |
| 作用 | ① 提供**成长偏向**；② 影响**完成任务的效果**（基础产出与成功率） |
| 与称号的区别 | 属性**不改变刷出什么**，只改变做得怎样 |

### 2.4 职业称号体系

| 项 | 规则 |
|---|---|
| 作用 | 解锁高品质任务；决定**某类高品质任务 / 奇遇的刷出概率** |
| 上位关系 | ✅ **包含 + 新增**（不替换）——升级只有好处 |
| 切换 | ✅ **可随时切换，一般无代价**（见下方 2.4.1） |

> ✅ **定位修正（2026-10-02）**：称号**不是"身份路线"，而是"已养成成果的可切换加成套装"**。
> 既然是玩家已经获得的东西，就不该限制使用 → **给玩家相当大的自由度**。

#### 2.4.1 ✅ 切换规则（D3 已定）

| 情形 | 规则 |
|---|---|
| 一般情况 | ✅ **随时可切换，无代价** |
| **高品质任务锁定"必须 X 职业完成"时 —— 任务进行中** | ⏸ **暂时不可切换** |
| **高品质任务锁定"必须 X 职业完成"时 —— 任务在列表中未开始** | ⚠ 切换时提示**"XX 任务与职业相关，会消失"**；玩家确认 → **删除该任务 → 走正常的空槽补充流程** |

> 这条与 V1 的任务槽机制天然咬合：删任务 → 空槽 → 按现有规则补新任务，无需新增机制。

**两点配套提醒**：

| # | 提醒 |
|---|---|
| ① | **锁定类任务在接取时就应明确标示"需 X 职业"**，并在与当前职业不符时给出警示——否则玩家会因频繁切换而反复丢任务 |
| ② | 既然可随时切换，"称号管刷出什么"就变成**实时可控**：玩家需要某类任务时切成对应称号即可。
> 这在自动执行下是**好事**——它给玩家多了一个表达意图的渠道（与 §2.5 的过滤机制同类）。

### 2.5 势力好感与官职

**势力好感（功勋前置）**

| 项 | 规则 |
|---|---|
| 前提 | **必须先加入势力**，才会有该势力的相关任务 |
| 变化 | 大部分增加本势力好感的任务，会**降低其他 1–2 个势力**的好感 |
| 是否存在全满 | ❌ **不存在**。设计上就是零和/负和 |
| **格局最优解** | **1 满 + 0.5 中等 + -1 仇恨** |
| 可见性 | ✅ **任务卡上必须前置明示**"此任务将降低 X 势力好感" |
| 过滤 | ✅ **必须提供过滤机制**——玩家可设定"不做会伤害 X 势力的任务" |

> 🔴 **过滤机制是这套设计的必要配套，不是可选项。**
> 在自动执行下，玩家没有"执行时"这个时刻；若好感变化在结算时才发生，
> 玩家就完全无法控制自己的外交格局，只能被动承受刷到什么任务。
> **"设定规则让系统替我筛"是自动执行游戏里玩家表达意图的唯一方式。**

**官职**

| 项 | 规则 |
|---|---|
| 前置 | 在该势力的功勋 → 品级 |
| **品级** | ✅ **上线后才提升**（离线功勋照常积累，上线一次性补结算）；🔴 **品级不带独立数值加成**，只作进度条与官职前置 |
| **授予** | 求官时结合**职业 + 属性**授予，**每次变化给玩家 3 个自选** |
| **触发** | ✅ **必须玩家在线**（官职是势力声望积累后的**强反馈节点**，要让本人在线感受）；见 §15.0-① |
| 作用 | 对特定任务 / 互动事件 / 比试结果有**加成**（✅ **官职是加成的主要载体**） |
| 官职池 | **大量复用**，不按"职业 × 属性 × 品级"全展开（控制配置量） |

## 三、任务链

### 3.1 三层结构

```
上层：玩家自选目标（按职业引导，提升对应能力/积累资源）
中层：随机任务（由职业称号决定池与品质概率）
下层：执行 → 任务评价 → 多线结算
```

### 3.2 玩家自选目标

| 项 | 规则 |
|---|---|
| 定位 | **做一件事，得两份结果**（随机任务收益 + 自选目标额外奖励） |
| 惩罚 | ❌ **不完成不做惩罚** |
| 周期 | **常驻 + 定期更换** |
| 在线价值 | 需玩家**在线确认结果与更换新目标** → 兼作拉动在线的定时器 |
| 🔴 兜底 | **到期未更换时自动续期上一个同类目标**（或按默认继续） |

> 🔴 **"在线的理由"必须是"能做得更好"，永远不能是"不做就没了"。**
> 这条直接继承自 V1 红线（在线离线收益一致）。到期不换就断收益 = 惩罚离线，禁止。

### 3.3 任务评价与「波动外置」原则

**评价档位**：随机分档（示例基准：50% C / 30% B / 15% A / 5% S）。
属性 / 技能 / 官职 / 装备可**提高高档位概率**（提升后 B/A/S 概率提高，C 减少）。

**🔴 波动外置原则（本项目核心原则之一）**

> **随机性只作用于外层进阶成长线，绝不污染底层基础进度。**

| 成长线 | 受评价影响程度 | 说明 |
|---|---|---|
| 个人经验 | **无影响** | 最基础，挂机即得 |
| 属性经验 | 小 | |
| 职业经验 | 中 | |
| 功勋 | **大（最高翻倍）** | 最外层，允许波动制造惊喜 |

**实现方式（保底 + 增量）**：
```
实际奖励 = 保底(1×) + 增量(0 ~ 1×，由评价决定)     → 最高 2×
```
保底 1 与"最高翻倍"不冲突：增量最高即为 1，合计 2 倍。

**UI 要求**：
- 浅层：**模糊叙事化提示**（"不费吹灰之力" / "前途未卜"）
- 深层：**完整概率与影响因素**

> ⚠ 挂机游戏里，**不可见的概率等同于不存在的设计**。影响因素必须至少在深层可见。

## 四、家臣（执行者 → 分配者）

> 决策：**不做城主、不做打破体制（无举兵/谋反）**。
> 用"家臣"以约 20% 的成本拿到骨架 3 的核心价值（从执行者变分配者）。

| 项 | 规则 |
|---|---|
| 人物池 | ✅ **与关系人物共用同一池**（关系达到某阶段 → 可招募为家臣） |
| 队列 | ✅ **每个家臣有自己的任务队列**（并行多队列；多一个家臣 = 多一个人打工） |
| 与主角的关系 | **并行，非替代**。家臣产出与主角产出不同类，不构成竞争 |
| 产出 | ⚠ **倾向方案：家臣产出一种独立新资源**，供"分配者玩法"使用（而非从任务奖励抽成） |
| 数量上限 | ✅ **从 3 人扩展到 15 人**（随养成进度提升，见下） |
| **人物池总规模** | ✅ **30 人**（含可招募家臣与纯关系人物） |
| 边际 | ✅ **成本递增或产出递减**，防止线性滚雪球 |
| 强度 | 家臣自身成长（打工与战斗提升）+ 主角技能加成 |
| 培养 | 玩家**花费额外资源定向培养**（细节待定，见 §7 消耗） |
| 上交比例 | 由**关系**决定 |
| **维持成本** | ✅ **只要是你的家臣，无论是否派出去、是否上阵，都要发俸禄**（见下） |
| **派遣机制** | ✅ **长期派驻**，不是"每件任务派人"。只在**获得新家臣**或**改变目标**时才需要重新分配 |

### 🔴 家臣线必须防的滚雪球

**🔑 配套比例提醒（D6 定稿后新增）**：

| 项 | 值 | 说明 |
|---|---|---|
| 家臣上限（终局） | **15** | 初期 3 人起步 |
| **上阵数量** | ⚠ **必须明显小于家臣上限**（建议 **1/3 ~ 1/2**，即 3–6 人） | 若上阵数接近 15，"派遣队 vs 战斗队"的**调度冲突就消失了**，家臣池的策略深度会直接归零 |
| 初期（3 人） | 小队制尚不成立（只能凑 1 支 3 人队） | 属渐进解锁，可接受；**但需确保 3 人时也有可玩的组合** |
"多一个家臣 = 多一份产出"是**线性叠加**，产出又能养更多家臣——这正是两款原作共同崩溃的模式。
**必须用「数量上限 + 成本递增/产出递减 + 俸禄」三道闸。**
**且"不做事也要发俸禄"是这三道闸里最直观的一道**——它把"多收一个人"从纯收益变成一笔持续支出。

### 4.1 家臣 = 策略应对的池子（战斗侧，详见 §13）

> **拥有的家臣是一个"策略应对池"：池子越深，能应对的战斗场景就越多。**
> 硬限制 = 数量上限；软限制 = 俸禄。二者共同保证规模不会爆炸，
> 同时又因为**战斗与任务需要不同特点的家臣**，自然形成"收集 → 应对 → 反馈"的体验。

**战斗侧的设定见 §13（战斗系统备忘），等讨论战斗时展开。**

## 五、与历史人物的关系

### 5.1 提升方式（核心改进）

| 方式 | 说明 |
|---|---|
| **完成任务 / 达成自选目标** | 体现为"XX 听说你的事迹，对你表示赞叹" |
| **属性匹配的事迹传播** | 体现武力的行为 → **所有重视武力的人物**关系都会提高（一对多） |
| 随机事件 | 与 XX 的遭遇、互动 |
| 比试较量 | 形式待定，🔴 **不能重度** |

> **这是对两款原作的一次改进**：San13 靠送礼、太阁靠每月茶席，**两边都被批评"刷关系机械"**。
> 改为**行为的自然副产品**，且一对多，效率与体感都远好于一对一灌溉。

### 5.2 玩家的意图表达

- ✅ 玩家可从**已解锁人物中选定"拉拢/攻略对象"** → 刷出该人相关随机事件的概率提升

### 5.3 人物偏好标签

- ✅ 每个人物需有**"看重什么"的偏好标签**（对应 San13 的才爱/勇爱/义理）
- 建议：**1 个主偏好 + 1 个次偏好**（枚举，可批量复用）

### 5.4 关系的衰减与扩散

| 项 | 规则 |
|---|---|
| 关系值 | **不衰减**（保留累计） |
| "最新事迹" | ✅ **有时效**——影响是否触发互动事件，避免"刷满即毕业" |
| 介绍朋友 | ✅ **限次**（每个关系只能介绍 1–2 次，或只解锁不赠送），防关系网指数爆炸 |

### 5.5 关系的反馈

- 有机会**向谁学习什么技能**
- 让谁**训练你的什么属性**
- 向你**介绍谁的朋友**
- **提升战斗属性**
- （达到阶段后）**招募为家臣**

### 5.6 🔴 比试较量的形态

**绝对不做实时小游戏**（违反挂机友好）。
建议：**离线可结算的属性对抗 + 在线可选的简短演出**。

## 七、资源层与消耗侧

### 7.1 设计原则

- **成长维度只增不减**（等级/属性/称号/品级/关系），靠**多维度拉长周期**
- **有增有减集中在资源层**

### 7.2 资源梯度

| 层 | 资源 | 消耗场景 | 特征 |
|---|---|---|---|
| 一 | **盘缠** | 每次出行 / 任务 | 日常小额、高频、随任务数放大 |
| 二 | **金钱 → 俸禄** | 每周期 × 家臣数量与强度 | **周期性、随规模同步放大** ← 地基 |
| 三 | **矿产 / 名品** | 家臣培养、✅ **商路 / 商队升级**（常驻出口）、**装备打造**（第一个大版本内，排在战斗之后） | 一次性大额、可囤积 |
| 四 | **粮草** | 出战，规模相关 | 战略级、决定打得动与否 |

> 🔴 **第二层（俸禄）是整个消耗侧能否成立的地基**：
> 玩家等级越高产出越多，**只有"随规模同步放大的消耗"才追得上产出增长**。
> 其余消耗是一次性的，不构成持续压力。

### 7.3 家臣培养的消耗（方向已定，细节待定）

| 消耗 | 理由 |
|---|---|
| **时间** | 培养期间该家臣不能打工 → **机会成本**。最符合挂机品类，零配置成本 |
| **名品 / 信物** | 复用关系系统的物品层，**不新增资源类型** |

## 八、已定设计决策（本轮新增，不可推翻）

| # | 决策 | 理由 |
|---|---|---|
| V2-1 | 四层职责：**称号管刷出 / 属性管完成 / 官职管加成 / 等级管总量** | 保证"刷什么"与"有多强"解耦 |
| V2-2 | 个人等级**不受其他系统限制**，但自由点**数值上永远不够全满** | 不卡等级，同时保住"自由分配"的价值 |
| V2-3 | **必须先加入势力**才有势力任务；势力好感**零和/负和，不存在全满**；最优格局 = 1满+0.5中+-1仇 | 让"站队"成为真实取舍，并造出"敌人"叙事 |
| V2-4 | 势力好感增减**任务卡前置可见** + **提供过滤机制** | 自动执行下玩家表达意图的唯一方式 |
| V2-5 | 任务评价遵循**「波动外置」**原则；实现为**保底 1 + 增量(0~1)** | 随机只加在外层，不污染基础进度 |
| V2-6 | 自选目标**常驻 + 定期更换**；**到期自动续期**，不惩罚离线 | 在线的理由是"做得更好"，不是"不做就没了" |
| V2-7 | **不做城主、不打破体制**；用**家臣**实现"执行者→分配者" | 用约 20% 成本拿到骨架 3 的核心价值 |
| V2-8 | 家臣与关系人物**共用人物池**；**并行多队列** | 内容复用最高 |

## 十、长线定位与 V1 范围

### 10.1 长线（社交版，非 V1）

**长线拉动玩家持续游玩的是社交。** 后续形态：

- 引入 **SLG 玩法**：玩家之间组成一个个势力，**从属于魏蜀吴**
- 在大地图上打**势力战**，以**占领城池**为结果
- 玩家养成自己、收集养成武将、积累资源，**最终都是为了在社交中取得势力首领地位，并在势力战中验证战斗能力**

### 10.2 V1 范围

| 项 | V1 目标 |
|---|---|
| 内容 | **只做单人养成 / 成长内容** |
| 时长 | **约前 30 日**；前期约 2 小时/天，后期约 20 分钟/天，**总计 15–30 小时** |
| 社交 | ❌ **不做** |

### 10.3 🔴 V1 必须为社交版预留的接口

社交版虽然不做，但以下两项**必须在 V1 就存在**——事后补会很痛：

| 接口 | 为什么必须预留 |
|---|---|
| **势力归属（魏 / 蜀 / 吴）** | 它是后期社交的组织骨架。V1 的势力好感系统直接挂在这三个势力上 |
| **战力的可量化** | 势力战要"验证战斗能力"，就必须有可跨玩家比较的战力值。V1 的战斗可以简化，但战力必须可算 |

> ✅ **2026-10-02 修正**：战力"可算"的用途被重新定义——
> **战力只给玩家自己看（自我成长反馈）+ 供势力战内的实际结算**，
> **不做跨玩家排行榜**。跨玩家比较改由 §10.8 的两层榜体系承担。

> 其余（攻城、势力战、首领选举、资源供奉）全部后置。

### 10.4 🔴 V1 内容目标的建议定义

> **30 天内让玩家"看完全部系统、但没练满"。**

理由：如果不这样定义，第 31 天玩家将无事可做——而社交版尚未上线，只能靠无限爬升续命，
**那正是两款原作共同崩溃的模式**。
让养成线在 30 天时"已见全貌但未封顶"，可以自然过渡到社交版。

### 10.5 时长预算需要区分的两个数字

| 概念 | 说明 |
|---|---|
| **必要操作时长** | 不做就会有损失的操作。**必须极短**，这是挂机友好的底线 |
| **自愿观看时长** | 看过程、看日志、逛界面。**可以长**，这是内容的价值体现 |

> ⚠ 前期 2 小时/天对挂机品类是偏高的数值。需要确认其中"必要操作"占多少——
> 若必要操作过长，说明存在"必须盯着"的设计，违背挂机友好。

### 10.6 由时长预算推出的硬约束

**后期 20 分钟/天** → 这是**决策点配额**的上限（见因果 C）：
所有前置决策（排序 / 装备 / 自选目标 / 势力过滤 / 攻略对象 / 家臣分配）
**合计必须在 20 分钟内可完成**。

### 10.7 🔴 排行榜体系：两层榜（2026-10-02 用户提出）

> **核心结论：战力不做排行榜。** 战力是"给玩家自己看的成长反馈"，不适合做跨玩家比较。
> 由此 **D17（战力口径）被消解**——可比性的压力不再落在战力上。

| 层 | 定位 | 例子 | 特点 |
|---|---|---|---|
| ① **细分榜**（大众向） | **多而细**：分得够细 → **大部分人都有榜可上** | "出战最多的郝昭""智力最高的赵云" | 参与感；榜位数量巨大 |
| ② **荣耀榜**（行为 × 实力） | **少而重**：突出成就感与荣耀 | "本周蜀国势力获得功勋最多的玩家" | 含金量；周期长、有展示位与奖励 |

**为什么这个解法成立**：

- 战力是**场景相关**的（§13.4-③），天然不适合跨玩家比；
- 但**"某个具体人物的某项数值"**与**"某段时间内的行为结果"**都是**单一标量**，天然可比。
- → 把"比什么"从**综合强度**换成**具体维度**，可比性问题直接消失。
- 社交版的势力战是**具体的、有地形有对手的一仗**，"谁更强"由那一仗的结果回答，
  **也不需要一个跨场景的综合值**。

**🔑 最大优点：人物池 = 榜单生成器**

历史人物是**有名有姓**的：20–30 个家臣 × 3–5 个指标 ≈ **60–150 个榜位**，**几乎零额外内容成本**，
且比抽象战力榜更有叙事质感（"我的赵云是全服最聪明的赵云"）。

> 这是两款原作都不具备的结构优势——**它们压根没有跨玩家榜**，因为它们的角色是"无名部将 + 有限名将"
> 且无在线结构。我们把"人物池"直接变成了榜位供给源。

**三条必须预先定的规则**：

| # | 规则 | 原因 |
|---|---|---|
| ① | **两层榜的周期与奖励必须显著不同** | 细分榜刷新快（周）、无实体奖励；荣耀榜周期长（月 / 赛季）、有展示位与奖励。否则细分榜会稀释荣耀榜的含金量 |
| ② | **细分榜要有最低样本量门槛** | 全服只有 1 个人有郝昭 → 榜毫无意义。至少 N 人拥有该人物才开榜；不足则隐藏或降级到更粗粒度 |
| ③ | **榜的名目是配置表，不是动态生成** | 预先定义"人物 × 指标"组合，避免空榜与榜位数量失控 |

**由"按势力分榜"引出的注意点**：

"本周蜀国功勋最多"这类榜按势力分 → 各势力的任务供给不同，**横向不可比**。
→ 分榜本身是**正确的**，但**必须在玩家选势力时就讲清口径**，
否则玩家会产生"我被分到人少的榜了"（占便宜 / 吃亏）的错觉，这会污染势力选择的决策。

**仍然保留的一条硬约束**：

战力只给自己看 → 它必须**单调不减**（与 V2-14「成长维度只增不减」一致）。
若将来引入伤兵 / 损耗，**战力展示要用"满编战力"口径**，避免玩家看到数值下跌而困惑。

### 10.8 由社交版反推的收敛

- **D11（势力数量）倾向 3**（魏 / 蜀 / 吴）。
  在 3 势力下，§2.5 的格局最优解由"1 满 + 0.5 中 + -1 仇"收敛为
  **「1 满 + 1 中等 + 1 仇恨」**——三个势力各有明确状态，非常干净。
- 人物规模（D6）也随之收敛：只需覆盖三个势力的核心人物即可。

## 十一、过程内容与随机事件

### 11.1 定位

> **既不是需要全程集中精神的在线游戏（三国志13 式），也不是纯离线挂机游戏。**
> **目标场景：在用电脑上班的人、上班摸鱼时的娱乐选项；手机端可方便"收菜"（处理事件）。**

→ 因此**可以存在较长的在线时间**，不追求"越少操作越好"。

### 11.2 统一框架：随机事件

过程内容**统一纳入「随机事件」框架**，承担两个作用：

| 作用 | 说明 |
|---|---|
| ① 充实跑路的意义 | 路上不再是空转 |
| ② 填充"离线回来要做什么" | 上线有事可做 |

### 11.3 七类清单（已确认采用）

| 类型 | 形式 | 奖励性质 | 频率 | 内容成本 |
|---|---|---|---|---|
| **风土见闻** | 文本 + 小图（类名所卡） | 纯收集，非数值 | 高频 | 低（模板） |
| **路人遭遇** | 短暂互动 | 关系（结构不同） | 中频 | 中 |
| **旅途二选一** | 遇到事，选 A / B | 总量同、结构异 | 低频 | 中 |
| **奇遇** | 稀有、解锁性 | 解锁 / 称号线索 | 极低频 | 高 |
| **随行家臣** | 带家臣时触发对话 | 家臣关系与成长 | 中频 | 低 |
| **地盘事件** | 经过某势力地盘 | 好感微调 | 中频 | 低 |
| **盘缠波动** | 路上花钱/省钱 | 资源层（第一层） | 高频 | 极低 |

### 11.4 🔴 时限分层（「时限外置」原则）

| 事件倾向 | 持续时间 | 说明 |
|---|---|---|
| **越偏向数值** | 越长，**可无限**，仅受随机事件总数上限约束 | 基础收益不因不在线而损失 |
| **越偏向收集** | 越短（**1 ~ 4 小时**） | 制造 urgency，拉动在线 |

> **这是「波动外置」原则在事件层的第二次应用**：
> **越基础的越不受时限伤害，越外层的越受时限约束。** 两处原则完全一致。
>
> 手机版本可据此做 **push 提醒**（"你有一处见闻即将错过"）。

### 11.5 触发密度：挂在「格数」上

- 密度按**移动格数**而非时间 → 直接复用 V1 路网数据，零新增配置
- 效果：**长途从"慢"变成"内容更多"**

> 顺带缓解 V1 §8.3 的老隐患："新野相关任务天然低效，玩家会持续想刷掉它"。
> 远途 = 见闻与事件更多 → "远"从惩罚变成特色。

### 11.6 展示规则

| 规则 | 说明 |
|---|---|
| **离线不播放** | 离线 8 小时跑 1200 格，不可能看 100 条 |
| **上线播 highlights** | 只展示本次旅途的摘要与高光 |
| **其余折叠进旅途日志** | ✅ **V1 已有此功能**（§4.5 观察型收集：旅途日志 / 风景图鉴，在线专属）→ 它是过程内容的天然容器 |

> ⚠ **数量级警告**：130 任务/天 × 平均 30 格 ≈ **3900 格/天**。
> 任何"每 N 格触发一次且每次都新"的内容都会被瞬间看穿。
> 必须：① 多数为可重复模板；② 唯一内容由玩家前置选择决定而非随机刷；③ 离线不播放。

### 11.7 初识与攻略对象（对"前置选择"的修正）

| 阶段 | 机制 |
|---|---|
| **初识** | ✅ **随机触发**（包装成偶遇事件）——保留"偶遇"的惊喜 |
| **选定攻略对象后** | ✅ **提高该角色的互动事件概率**（含初识事件的概率） |

> 修正了"唯一内容完全由前置选择决定"的极端：**随机只决定"何时发生"，选择决定"更可能发生什么"。**

### 11.8 🔴 跑路时间占比存在一个「可行区间」（不是越少越好）

| 边界 | 约束来源 |
|---|---|
| **上限** | 路上内容撑不住太久；太久则无聊 |
| **下限** | **V1 最具辨识度的操作是"拖动任务排序（TSP）"。若赶路时间太少，这个操作就失去意义** |

> ⚠ V1 实测的 **91% 是临时品质数据**（地图 / 移速 / 任务时长均为验证用值），**不是最终形态**。
> 但占比即便下降，**仍可能维持在 60% 以上（最优解下）**——因为排序操作需要一个足够高的下限。
>
> → **数值调优目标：把"赶路时间占比"落在上下限之间的区间内，而不是一味压缩。**

### 11.9 🔴 争议项 D13：资源收益上的「离线惩罚」

**提案（用户）**：为前期粘性，资源收益上存在**离线惩罚**，后续通过**养成规避**该惩罚。

| 方案 | 表述 | 玩家感受 |
|---|---|---|
| A（提案） | 离线基准打折（如 80%），养成后回到 100% | **"不养成就被扣"** → 惩罚感 |
| B（建议） | 离线基准 100%，**在线给加成**（如 120%），养成提升离线系数 | **"在线赚到了"** → 奖励感 |

> 非"不回来就被扣"。两者数学上都能拉动在线，但一个是机会、一个是惩罚。

### 11.9-bis ✅ D13 已拍板（2026-10-02）

**用户结论：两种方案数学上等价，采用"奖励感"的叙述。**

| 项 | 结论 |
|---|---|
| 方向 | ✅ **一律使用方案 B 叙述**：离线基准 100%，在线给加成（如 120%） |
| 禁止 | ❌ **不得出现"离线打折 / 不在线就少拿"这类表述与实现** |
| 优先级 | ① 先用 **§11.4 事件时限** 拉在线 → ② 实测拉力不足时，再叠加 B 形式的在线加成 |

> 同一数学效果，叙述换成"在线赚到了"，就不触碰 V1 决策 #6。这条叙述规则适用于**未来所有类似的收益差设计**。

## 十二、决策点配额（因果 C 的落地）

> 因果 C：两款的成果差异来自**执行过程**，我们没有过程 → **技巧点必须前置到"出发前的配置"**。
> 本章解决由此产生的副作用：**前置决策会无限膨胀，而后期每天只有 20 分钟。**

### 12.1 🔴 配额是两个维度，不是一个

§11.4 的收集类事件持续 **1–4 小时**，天然会把玩家的一天切成**多次上线**。
因此"20 分钟/天"必须拆成两个约束：

| 维度 | 建议值 | 违反后果 |
|---|---|---|
| **单次上线必要操作** | **≤ 5 分钟** | 收集事件 1–4h 过期 → 一天要来好几次，单次一长就变成"必须腾出时间" |
| **全天累计必要操作** | **≤ 20 分钟** | 超出即违背"后期每天 20 分钟"的范围定义 |
| 自愿观看时长 | 不设上限 | 这是内容价值，欢迎长 |

### 12.2 决策点清单与预算表（粗估，待实测校准）

| # | 决策点 | 频率 | 单次耗时 | 每天小计 | 类型 |
|---|---|---|---|---|---|
| 1 | **随机事件：二选一 / 处理** | 每次上线 | 15–30s / 个 | 2–4 min（3–8 个） | 🅔 事件型 |
| 2 | **任务队列补单与排序** | 每次上线 | 30–60s | 2–4 min | 🅡 规则型 |
| 3 | **家臣任务分配** | 每次上线 | ~20s / 人 | **⚠ N × 20s × 次数** | 🅡 规则型 |
| 4 | **自选目标：确认结果与换目标** | 每天 | ~60s | 1 min | 🅔 事件型 |
| 5 | **自由点 / 专精分配** | 每天 | ~60s | 1 min | 🅡 规则型 |
| 6 | **资源消耗（俸禄 / 打造 / 粮草）** | 每天 | ~60s | 1 min | 🅡 规则型 |
| 7 | **攻略对象选定** | 每阶段 | ~60s | 摊薄 ~0.1 min | 🅔 事件型 |
| 8 | **官职三选一 / 称号路线** | 每阶段 | ~2 min | 摊薄 ~0.2 min | 🅔 事件型 |
| 9 | **初识与关系互动（回礼 / 求学）** | 触发时 | ~30s | 摊薄 ~0.5 min | 🅔 事件型 |

**不含家臣的合计 ≈ 7–11 min** —— 在 20 min 预算内，但已用掉一半以上。

### 12.3 ⚠ 唯一会爆预算的项：家臣分配

它是**唯一随系统成长而线性膨胀**的决策点：

| 家臣数 | 每天 2 次分配 | 小计 |
|---|---|---|
| 5 人 | 5 × 20s × 2 | 3.3 min |
| 10 人 | 10 × 20s × 2 | 6.7 min |
| 20 人 | 20 × 20s × 2 | **13.3 min → 与其余项相加直接爆表** |

> **结论：家臣数量上限不只是经济平衡参数，它同时是「决策点预算」的硬约束。**
> 这条以前没被识别——§4 只从"产出滚雪球"角度给了上限理由，现在有第二个理由。

### 12.4 解法：把决策分成「规则型」与「事件型」

| 类型 | 定义 | 例子 | 是否计入每日预算 |
|---|---|---|---|
| 🅡 **规则型** | 同质、重复，**可表达为 if-then 规则，设一次长期生效** | 任务排序权重 / 势力过滤 / 家臣分配策略 / 培养策略 / 资源消耗阈值 | ❌ 不计入（一次性设置） |
| 🅔 **事件型** | 每次内容不同，**必须由玩家阅读后判断** | 二选一 / 奇遇 / 初识 / 官职三选一 / 关系互动 | ✅ 计入 |

> **技巧点并没有消失，只是从"每次操作"迁移到了"配规则"。**
> 这与因果 C 完全一致：玩家的技巧表达 = **谁的 rule build 配得更好**，
> 而不再是"手速与临场判断"（后者本来就是我们要自动化的东西）。
>
> 副产品：规则 build 的差异，正好补上调研里"两款都被批评个体差异低"的那块。

### 12.5 规则化的两个必要条件（缺一不可）

| 条件 | 为什么 |
|---|---|
| **配置页必须有「预期产出估算」** | 离线才结算，配完当场看不到效果 → 没有估算就是**盲配**，玩家会焦虑并放弃规则 |
| **必须有默认值 + 一键"沿用上次"** | 否则新玩家第一天就会卡在配置里，与"摸鱼娱乐"定位冲突 |

### 12.6 过期语义：失去选择权，不失去内容

收集类事件 1–4 小时过期，过期时该怎么算？

| 做法 | 判定 |
|---|---|
| ❌ 过期即消失 | 制造"错过"焦虑，与 V1 决策 #6 的精神冲突（虽非数值，仍是惩罚） |
| ✅ **过期 = 失去选择权，内容仍进旅途日志** | 二选一由系统取默认项；见闻仍可补看，只是少了"当时选"的那一层 |

> 这样既保留了"及时处理更好"（有 urgency，可 push），又不惩罚不在线的人。
> **与 §11.4「时限外置」、§11.6「离线不播放但可补看」完全自洽。**

### 12.7 ✅ 用户对本节的结论（2026-10-02）——配额不构成约束

**用户判断：上线的主要时间是"处理随机事件 + 养成家臣"，但只有前者是必要的。**

| 决策点 | 重新定性 |
|---|---|
| **处理随机事件** | ✅ **唯一必要的操作** |
| 替换技能 / 分配自由点 | ❌ 非必要——**只在"技能升级 / 有可用自由点"时才必要**，其余时间是玩家主动行为，不计入 |
| 分配家臣 | ❌ 非必要——**只在获得新家臣时才需要考虑**（家臣为**长期派驻**，见 §4） |

**随机事件的处理量是有上限的**：列表最多 **≤ 10 条**需要处理，
每条"读文本 + 决策"约 **30 秒** → **5 分钟内必然完成**。前期列表更少（< 一条的量级），更不构成压力。

### 12.8 由此收敛的结论

| 项 | 结论 |
|---|---|
| **D14（配额口径）** | ✅ 关闭。不再作为系统约束，改为 **UI 硬指标**：**待处理事件列表 ≤ 10 条，单条处理 ≤ 30 秒** |
| **D15（规则化）** | 🔽 **降级为可选增强**。它原本是为救预算而提的；预算既然不是问题，就不必强制做 if-then 规则 |
| 仍然保留 | **默认值 + 一键"沿用了上次"**（§12.5 第二条）——这与规则化无关，是新手体验的底线，保留 |
| 仍然保留 | **12.2 预算表**作为**校准工具**：若将来某版本必要操作超过 20 分钟，再启用规则化方案 |
| 新增硬指标 | **家臣数量上限**（§4）因此具备第二个理由之外，还要注意：即便上限放开，俸禄也会先于预算爆炸 |

## 十三、战斗系统备忘（D5，待详细设计）

> 本章**只记录已定前提与已识别的问题，不做设计**。等正式讨论战斗系统时从这里展开。

### 13.1 已定前提

| 项 | 内容 | 出处 |
|---|---|---|
| 家臣 = 策略池 | **拥有的家臣是一个"策略应对池"，池子越深，能应对的战斗场景越多** | §4.1 |
| 硬限制 | 家臣数量受**统帅 / 等级**等养成进度限制，**不会很多** | §4 |
| 软限制 | **只要是你的家臣，无论用不用，都要发俸禄** | §4 |
| 上阵数量 | 由 **官职 + 统帅** 决定 | §4 |
| 派遣性质 | 家臣是**长期派驻**，不是每件任务派人 | §4 |
| 战斗操作 | **出战前选人**，属前置决策；战斗本身自动结算（不做实时操作） | 挂机红线 |
| 战力可量化 | V1 战斗可简化，但**战力必须可算**（社交版接口） | §10.3 |

### 13.2 战斗的输入层（已修订）

| 层 | 内容 | 归属 |
|---|---|---|
| **地形** | 山地 / 林地 等 | 战场属性 |
| **兵种克制** | 骑兵 / 枪兵 等 | 家臣携带 |
| **战法** | 火攻 / 水攻 / 伏兵 等 ✅ **地形适应一般包含在战法里** | 家臣携带 |
| **战法 / 军师策略的相互克制** | 战法之间存在一层相克关系（参考友商） | **新增层** |
| **属性压制** | 双方**总属性差**带来的压制 | 保底量 |

→ 出战时从家臣池中挑人上场，挑人的依据就是以上各层。
→ **池子深度 = 可应对的场景数**，这是家臣收集体验的正当性来源。

### 13.3 家臣人物卡的三个维度（✅ 已确认）

> **家臣至少有三个维度的倾向：属性 / 战法 / 兵种。地形适应不单列，包含在战法里。**

| 维度 | 说明 |
|---|---|
| **属性倾向** | 对应个人属性（五维），影响属性压制层与任务结算 |
| **战法** | 携带 1~2 个；**内含地形适应**（"山地战法"这类），不单列地形维 |
| **兵种** | 参与兵种克制层 |
| ✅ **特殊技能**（新增） | 作用于**派遣层**（跑商结果），见 §14.12；建议复用关系系统的技能枚举 |

> ⚠ **内容量提醒（保留）**：家臣若只有 20–30 人，却要覆盖 **兵种 × 战法** 的组合空间，
> 容易变成"每个人什么都有一点，谁也不突出"——这正是 V2-15「人物数量克制、个体差异做实」要防的。
> **建议：每名家臣在三维上都要有明确的强项与弱项，不做全能。**

### 13.3-bis 🔴 战法相克引出的新需求：必须给玩家"情报"

一旦引入**战法/军师策略的相互克制**，出战选人就从"我有什么"变成"我有什么 × 对手用什么"。
**若玩家出战前不知道对手配置，配池就退化成赌博**——池子深度带来的策略价值会直接归零。

| 配套 | 说明 |
|---|---|
| 必须有**情报 / 侦查渠道** | 出战前可知（至少部分可知）对手的兵种与战法倾向，否则不可决策 |
| 情报本身可以是**玩法** | 例如：派家臣去侦查、花钱买情报、关系人物提供线索 → 与关系系统天然咬合 |
| 挂机友好 | 情报是**离线可得的一次性信息**，不需要在线盯着，不违反挂机红线 |

> 这条要等战斗系统讨论时定，但**现在记下来**：相克层不是白加的，它必须配一个信息渠道。

### 13.4 我的四点提示（战斗讨论时需先回答）

| # | 问题 | 我的倾向 |
|---|---|---|
| ① ✅ | **全员俸禄会压制"池子深度"** | ✅ **已达成一致**：俸禄随人数**超线性增长**（第 N 个更贵）+ **待命/闲置打折**，让"深池"成为有意识的高投入选择（D16） |
| ② ✅ | 任务侧"选属性高、技能高的派出去" | ✅ **想法本就一致**：用户原意即"**针对该任务**的属性/技能高"（它影响任务结算奖励），任务天然带维度需求，**不需要新增"需求标签"机制**。我补的只有一条：**任务需在 UI 上明示它吃哪一维**，否则玩家只能猜 |
| ③ | **战力可量化 × 场景相关** | 🔴 见下方 13.4-③ 展开说明（用户要求讲清楚）→ 新开 **D17** |
| ④ ✅ | 家臣卡维度 | ✅ **已确认三维度：属性 / 战法 / 兵种**，地形含在战法内；**另加一层战法/军师策略的相互克制**（见 13.2、13.3-bis） |
| ⑤ | 战斗不能变成实时操作 | 玩家的操作只在"选谁上场 + 用什么战法"，结算自动（与因果 C 一致） |

#### 13.4-③ 展开：为什么说"战力可量化"和"四层输入"打架

**矛盾一句话**：§10.3 要求战力**可跨玩家比较**（社交版势力战要"验证战斗能力"），
但战斗结果由 地形 × 兵种 × 战法 × 属性差 决定 → **战力是"场景相关"的，不是一个数能表达的**。

**举个具体例子**：

| 玩家 | 家臣池 | 综合数值 | 实际表现 |
|---|---|---|---|
| 甲 | 5 个骑兵家臣 | 1000 | **平原强、山地弱** |
| 乙 | 5 个枪兵家臣 | 1000 | **林地强、平原弱** |

两人数字一样，但"谁更强"取决于**这一仗打的是什么地形**。
→ 如果社交版要排行榜、要匹配、要"谁是这个势力最能打的"，**就必须先回答：比的是哪个场景下的强。**

**三个候选口径（需在战斗设计前定）**：

| 口径 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 单一综合战力** | 各场景加权平均（权重 = 场景出现频率） | 简单、可直接比、好做排行榜 | "田忌赛马"式的针对性配池不被体现，最优解退化成堆数值 |
| **B. 分场景战力组** | 山地 / 平原 / 林地 / 水上 各给一个值 | 精确，配池策略被完整体现 | 排行榜该显示哪个？玩家看不懂"我到底多强" |
| **C. 综合值展示 + 场景值计算**（我倾向） | 对外一个综合战力（用于声望/匹配），**战斗内按场景实时算** | 两头都要 | 需明确告诉玩家"综合值不代表某场具体战斗"，否则会有误判落差 |

> **建议：C。** 但无论选哪个，**"对外可比的那个数"必须与"真实的场景强度"在统计上同向**，
> 否则排行榜会变成骗人的东西——这一点是战斗公式设计时的硬约束。

**✅ 2026-10-02 更新：本条已被用户的两层榜方案消解（见 §10.7）。**

> 用户结论：**战力不适合做排行，它只是给玩家自己看的成长反馈。**
> 排行榜分两层：**细分榜**（多而细，人人有份，如"智力最高的赵云"）
> + **荣耀榜**（行为 × 实力，少而重，如"本周蜀国功勋最多"）。
>
> → **可比性的压力不再落在战力上**："某个具体人物的某项数值"和"某段时间的行为结果"
> 都是**单一标量**，天生可比；而社交版的势力战是**具体的一仗**，"谁更强"由那一仗回答。
> → D17 关闭，遗留问题转入 **D18（排行榜体系细节）**。

### 13.5 战斗讨论时的入口清单（D5）

- 兵种 / 战法 的**枚举表规模**（决定组合空间与内容量）
- ✅ **战法 / 军师策略的相克表**（新增层，含相克关系的规模）
- ✅ **情报 / 侦查机制**（相克层的配套，见 13.3-bis）
- 单场战斗的**结算形式**：一次性判定 vs 多回合
- **战力公式**与可量化接口（见 13.4③）
- 战斗的**触发场景**：任务中 / 随机事件 / 势力战
- **主角是否亲自上阵**，还是只作为加成来源
- 家臣在战斗中的**成长与损耗**（伤兵 / 阵亡？与"任务必定成功"决策 #8 的关系）
- 与消耗层的挂钩：**出战需粮草**（§7）、**养人需俸禄**（§4）

## 十四、个人经济线（因果 F）

### 14.1 F 是什么（引自《对比》原文）

> **因果 F｜个人经济线是"不打仗也能玩"的基础设施**
> - 太阁5 有完整经济线 → 商人 / 茶人 / 铁匠路线成立，副职业是主职业的**财源与社交工具**
> - San13 无个人经济 → 在野只能靠 PK 威名补，且**"赚钱"这件事缺乏玩法**
> - → 我们要做"轻松"、要弱化战斗，**经济 / 社交线必须有实质内容，不能只是数字**

一句话：**经济线是"不打仗也能玩下去"的那条腿。** 战斗弱化之后，它必须能撑住日常。

### 14.2 我们现在的状态（仍然只是"部分解决"）

| F 的要求 | 有没有 | 说明 |
|---|---|---|
| 资源层有增有减 | ✅ | §7 四层梯度 |
| 持续消耗（消耗侧） | ✅ | **俸禄是地基**（V2-14 / §7.2） |
| **收入的第二种来源**（非任务、非战斗） | ❌ **没有** | 目前收入**全部来自"做任务"** |
| **经营 / 生产成分**（投入资源 → 产出更多资源） | ❌ **没有** | 只有"做任务得资源，然后花掉" |
| 分化出"不打仗也能推进"的玩法路线 | ❌ **没有** | 战斗简化后，**日常只剩任务链一条** |

### 14.3 🔴 一个连锁推论：V2-17 把 F 从"可选"升级为"必需"

我们刚定了 **V2-17：家臣无论用不用都要发俸禄**，且俸禄**超线性增长**。
→ 玩家从此有一笔**随规模持续膨胀的固定支出**。
→ 若收入仍只有"做任务"一条，玩家就只能靠**刷更多任务**去追俸禄
→ 那就是"**为了养人而被迫刷任务**"——是惩罚感，而且正是 §10.4 要避免的"靠无限爬升续命"。

> **结论：有了全员俸禄之后，经济线不再是锦上添花的第二玩法，而是消耗侧能成立的另一半。**
> **消耗侧（俸禄）我们已经有了，收入侧（经营）还没有——一半的地基是悬空的。**

### 14.4 但不要做重

| 不做 | 原因 |
|---|---|
| ❌ 完整经营模拟（店铺 / 产业 / 雇佣 / 定价） | 会变成另一个游戏；违背"摸鱼"定位；需要高频操作 |
| ❌ 实时物价市场 / 玩家间交易 | V1 无社交；且会引入"不盯着就亏"的焦虑，与挂机红线冲突 |

### 14.5 建议方案：**家臣派遣 × 地区差价**（轻量经营）

> **核心思路：复用 V1 已有的两个资产——跨州结构（决策 #4）与路网。**

| 要素 | 做法 |
|---|---|
| **价差来源** | 各州有**特产与物价差**（一张配置表；V1 已有 16 节点 / 多州府结构） |
| **派遣单位** | ✅ **不是一个人，是一支小队**（见 §14.9） |
| **执行者** | **家臣小队长期派驻**跑商 / 采购，**占用家臣 = 与"上阵打仗"互斥 = 机会成本** |
| **玩家的前置决策** | 派谁（属性 / 特殊技能影响最终结果）、派哪条线（距离与路网）、投入多少本钱 |
| **产出** | 进入资源层（金钱 / 名品），用于俸禄、培养、打造 |
| **风险面（可选）** | 路上遇劫 → 需要护卫家臣 → 把战斗侧的家臣池也拉进经济线 |

**为什么这个形态最划算**：

- **零新增地图、零新增系统骨架**，只加一张"州 × 特产 / 物价"表
- 天然是**规则型低频决策**（§12.4），符合挂机友好
- 让"家臣派遣"**第一次有了真正的取舍**（不再是人多就赢）
- 把 V1 的"**强制跨州依赖**"从**负担**变成**机会**：跨州不再只是跑路成本，还是套利空间
  （顺带二次缓解 §8.3 "新野任务低效"的老问题）

### 14.6 🔴 必须防的一件事

**经营收益不能高到让俸禄压力消失**——否则消耗侧失效，回到两款原作"后期滚雪球"的老路。

→ 经营产出必须与消耗侧**同步受约束**（规模上限 / 边际递减 / 路网距离成本）。
→ **判断标准：「赚的钱刚好不够养所有人」应是常态**——玩家必须持续做取舍，这才是 F 的价值所在。

### 14.7 🔑 与 D7 的关系（建议合并考虑，别做两套资源）

D7 已定方向：**家臣产出一种独立新资源**。
若经济线也产出资源，就容易出现**两套资源、两套数值**的重复建设。

> **建议：让两者成为同一件事的两面**——
> 家臣派遣本身就是经济线的执行方式，其产出的"独立资源"正是经营收益的载体。
> 这样 D7 与经济线合并为一套，既省内容，也让"家臣产出"一开始就有明确用途（而不是先造资源再找出口）。

### 14.8 ✅ D19 / D20 已拍板（2026-10-02）

| # | 结论 |
|---|---|
| **D19** | ✅ **做**，且是轻量形态：**跑商** |
| **D20** | ✅ **跑商替代"派去做任务"**——家臣的派遣玩法就是跑商，不再是泛化的"派人做任务" |

> **由此家臣线与主角线彻底分工**：**主角做任务 → 管成长；家臣跑商 → 管经济；战斗是两边唯一的合流点。**
> 这比"家臣也去做任务"干净得多，也避免家臣产出与主角产出互相稀释。

### 14.9 派遣小队制与跑商机制（用户补充，2026-10-02）

| 要素 | 规则 |
|---|---|
| **派遣单位** | ✅ **一支小队**（不是一个人） |
| **商队行为** | ✅ **用物品换钱** |
| **持续条件** | ✅ **只要有这个物品（持续供给），就可以持续跑商** —— ✅ **货品是消耗品**（见 §14.16） |
| **门槛** | 小队需满足**属性要求** |
| **结果** | 由 **属性 + 角色特殊技能** 共同影响 |

#### 🔑 这条机制最大的价值：物品 = 产能凭证

> 物品不再是"数值道具"，而是**一条商路的开启与维持凭证**。
> → **"收集物品" = "扩充产能"**，物品第一次有了非数值的意义。
> → 且因为"持有即可持续跑"，**一次配置 → 长期自动产出**，
> 决策频率极低（只在获得新物品 / 新家臣 / 新路线时调整），
> **完全符合挂机友好**（离线也在跑，与在线一致）。

#### 由"各州特产不同"推出的连锁（复用 V1 决策 #4 强制跨州依赖）

| 连锁 | 说明 |
|---|---|
| 跨州从**负担**变成**产能结构** | 去产出州取货 → 到高价州卖出，**路网距离 = 商路成本** |
| **V1 的 TSP 排序操作第一次有了经济意义** | "拖动任务顺序减少跑路"同时也是"优化商路" → **V1 最具辨识度的操作与新经济线缝合在一起** |
| 与随机事件咬合 | 奇遇 / 见闻掉落特产 → 收集 → 开新商路 → 产能（见 §14.10 红线提醒） |

### 14.10 🔴 必须守住的一条红线（新风险）

在线专属的收集型事件（§11.4 短时限）若**直接掉落跑商物品**，就构成"在线才有的数值收益"，
触碰 V1 §4.6 红线（在线专属内容必须非数值 / 非进度，或**总量相同但结构不同**）。

| 做法 | 判定 |
|---|---|
| ❌ 只有在线随机事件给特产 | 违反红线 |
| ✅ **离线也能获得（任务 / 家臣产出），在线事件只是更快或给不同种类** | 符合"总量期望相同、结构不同" |
| ✅ 或：在线事件给的是**提前量**，离线也会慢慢攒到 | 同上 |

> **结论：跑商物品必须有一条离线获取途径，在线只是"结构不同"的那一份。**

### 14.11 小队门槛的形式（建议）

| 方案 | 效果 |
|---|---|
| 纯"属性合计达标" | 弱家臣可填位 → **缓解"全员俸禄导致只留高质量"**（与 §13.4① 互补，正好闭环） |
| 纯"关键项最低门槛" | 强 specialization，但弱家臣毫无用处 → 白养 |
| ✅ **建议：合计达标为主 + 关键项最低门槛** | 两头都要：既能凑数（弱家臣有用），又保留专精要求 |

**由此产生的核心取舍**：家臣总数固定 → **派 1 支强队，还是派 3 支弱队？**
→ 这是一个**广度 vs 深度**的经营决策，且与俸禄压力（D16 超线性）叠加，正是 F 想要的那种决策。

### 14.12 家臣的第四维度：特殊技能

§13.3 定了三维度（属性 / 战法 / 兵种），因派遣机制新增第四维：

| 维度 | 作用层 |
|---|---|
| 属性 | 通用 + 压制 + **派遣门槛** |
| 战法 | 战斗层（含地形适应） |
| 兵种 | 战斗层 |
| ✅ **特殊技能** | **派遣层（影响跑商结果）** |

> **分工是清楚的**：战法与兵种管打仗，属性管门槛与压制，特殊技能管跑商。
> 🔑 **省内容的建议：特殊技能复用关系系统的技能枚举**（§5.5"向谁学习什么技能"）。
> 主角能学的技能 与 家臣自带的特技 **共用一张枚举表** → 一套内容两处使用，
> 不增加 V2-15「人物数量克制」的负担。

### 14.13 参考《三国志》外交：可借鉴什么、不能借鉴什么

| 可借鉴的结构 | 说明 |
|---|---|
| 派遣的是**有名有姓的人** | 结果由使者属性 + 对方态度决定 → 与我们的**关系系统**天然咬合 |
| 外交是**对势力**的 | 可扩展为"对州 / 对势力"的派遣 → 把**势力好感线**也拉进经济线 |
| 有失败与被扣的后果 | 制造张力 |

**❌ 不能照搬的：失败 / 被扣 / 损失。**

> 它与 **V1 决策 #8（任务必定成功）** 和**离线结算的确定性**直接冲突——
> 离线跑 8 小时回来发现商队被劫、货全丢了，对挂机品类是灾难性体验。
>
> **改造方式（沿用「波动外置」）**：用"**产出多少**"表达，不用"成功 / 失败"表达。
> 即 **保底（1×）+ 增量（0~1×，受属性与特殊技能影响）**——最差也是赚得少，不会赔光。

### 14.15 ✅ D21 已拍板：跑商品的来源与分层（2026-10-02）

| 物品 | 来源 | 用途 |
|---|---|---|
| **跑商品（特产 / 货品）** | ✅ **玩家挂机做任务时，其中一类任务的「主产物」** | 开商路 / 维持商队 |
| **名品** | ✅ **随机掉落的稀有物品** | 关系送礼（§5）、家臣培养（§7.3）、后期打造装备 |
| **装备系统** | ⏸ **后置**，前几个版本不考虑 | — |

> **由此"主角与家臣"的分工第一次闭合**：
> **主角做任务 = 供货方（产货品）；家臣跑商 = 变现方（货品 → 钱）。**
> 二者互补而非竞争 —— 这也顺带关闭了 D7（不再需要"家臣产出独立新资源"，见 §15）。

### 14.16 ✅ D24 已拍板：货品是**消耗品**（2026-10-02）

> 修正了我原先"凭证（持有即可、不消耗）"的理解。
> **正确理解：只要这个物品"持续供给"，商队就能持续跑——物品本身按趟消耗。**

**由此经济线变成一个「吞吐量模型」，而不是"一劳永逸的凭证"：**

```
主角做任务（一类任务主产物）──供给──→ 货品 ──按趟消耗──→ 家臣商队 ──→ 金钱
        ↑                                                        │
        └────────────── 俸禄 / 培养 / 商路升级 ←───────────────────┘
```

| 要素 | 说明 |
|---|---|
| **供给端** | 主角做任务的产出速率（**做哪类任务 = 供什么货**） |
| **转化端** | 家臣商队（属性要求 + 特殊技能决定转化效率） |
| **产出端** | 金钱，进入消耗侧（俸禄 / 培养 / 商路升级） |

> **这比我原先的"凭证"方案更好**：凭证是一次性解锁、之后躺赚；
> 吞吐量模型则让**主角的任务选择持续影响经济线**，两条线始终咬合，且天然带一个持续消耗出口。

**🔴 由此产生的必答题：商队缺货时怎么办（D26）**

| 方案 | 说明 |
|---|---|
| ❌ 停摆且扣钱 / 有损失 | 惩罚感；且离线缺货会造成"回来发现亏了"，与挂机红线冲突 |
| ✅ **建议：缺货即停摆（产出 0），但不产生任何损失，UI 明确提示"待货"** | 这是**资源约束**不是惩罚，最符合"不惩罚不操作的人" |
| 备选：**空跑**（缺货时产出极低但不为 0） | 更柔和，但会稀释"供给端"的重要性 |

> **关键设计意图**：让玩家的决策变成 **"我的供给够养几条商队"** ——
> 多开商队但货不够 → 商队闲置、白付俸禄。**这正是 F 想要的那类经营权衡。**

### 14.17 ✅ D25 已拍板：装备在**第一个大版本规划内**，排在战斗之后（2026-10-02）

> 修正：装备**不是"不做"**，而是**顺序靠后**——等战斗系统讨论完，再根据战斗内容讨论装备。

| 项 | 结论 |
|---|---|
| 装备系统 | ⏸ **第一个大版本内**，排期在**战斗系统之后**（因为装备要服务于战斗内容） |
| 消耗侧的过渡期问题 | 装备上线前，§7 第三层（矿产 / 名品）的出口偏薄 |

**因此"名品用于商路 / 商队升级"的定位要改**：

| 原建议 | 修正后 |
|---|---|
| 作为装备的**临时替代**出口 | ✅ **作为常驻出口保留**，即使装备上线也不取消 |

> 理由：它是**经济线自己的消耗出口**，与装备是两条不同的消耗线路。
> 一个健康的消耗侧本来就应该有多个出口，而不是等某一个系统来兜底。
> 装备上线后，第三层同时具备"打造装备"与"升级商路"两个出口 → 玩家要在两者间取舍，这更好。

#### 15.0-① ✅ D27 已拍板：品级**也**必须上线后提升（2026-10-02）

> 用户决定：**不只是官职，品级本身也要上线后才提升**——强化"升迁时刻"的在线仪式感。

这本身没问题，但**必须同时满足以下两条，否则就会变成"惩罚不在线"**：

| # | 必要条件 | 为什么 |
|---|---|---|
| ① | **品级不带独立数值加成**，所有加成挂在**官职**上 | 若品级自带加成，离线期间就拿不到 → 违反 V1 决策 #6。品级降级为"**纯进度条 + 官职前置门槛**"后，"离线不升品级"就只是**延后了进度条**，不产生任何损失 |
| ② | **离线期间功勋照常积累**，上线后**一次性补结算到当前功勋对应的品级**（可连升数级） | 若功勋也卡住，就是双重惩罚。**绝不能丢失已积累的功勋** |

**满足这两条后的效果（反而是加分项）**：

```
离线 8 小时 → 功勋持续积累，品级暂不结算
        ↓ 上线
一次性补结算品级（可能连升数级）→ 立刻触发"授予官职（3 选 1）"
        ↓
两个强反馈节点连在一起 = 一个完整的「升迁时刻」
```

> 这正是 D9 想要的"让玩家在线感受节点带来的变化"，而且**没有任何数值损失**。
> 需注意：UI 要能演出"连升 X 级"，否则玩家感知不到补结算的爽点。

**配套（同 D9）**：品级达标时要有明确引导（红点 / push："功勋已足，可升迁"）。
