## 〇、如何验收每一次改动

- 改 `src/` 后**必须**重跑 `npm run check`（它会先 `_bundle` 把 `tools/check.ts` 打成 `node_modules/.sanwalk/check.cjs` 再 `node` 执行）。只跑 `tsc` 不算数——`npm run check` 才实跑模拟。
- 命令：
  - `npm run typecheck` → `tsc --noEmit`，类型门禁。
  - `npm run check` → 全量自检：路网 Dijkstra 基准（按配置文件名取 `DIST_BENCHMARKS`）+ 24h 模拟（tasksPerDay / 四维 / 九技能 / 评价四档 / 缺料）+ 配置告警。✅ 当前基线：路网基准全中、**180 任务/天**、九技能第 1 天 Lv4–7、评价四档有分布、无超容违例。
  - `npm run calib` → 成长校准（1/2/3/7/14/30/60/90/120 天），看「技能档位→品质窗口→最高产出品质→B 缺料率」的长期曲线；**调 SKILL_XP_PER_QUALITY 或投产数值后必跑**。
  - `npm run sim [角色数[,小时数]] [输出路径]` → 批量模拟并导出 xlsx（默认 **100 个角色 × 24 小时** → `out/sim_100char_24h.xlsx`），含「角色汇总」与「任务明细」两个页签，用于数值分布的样本统计。
  - `npm run check:v1` → 回跑 V1（4 城原型）。
- 配置版本：`firstShow` 配置集，**运行时默认加载同集最大版本 = V3**（`firstShow_V3.xlsx`）。V3 = V2 玩法数据 + 新增 `state`（州着色）/ `cityLink`（城际连通，生成器写入）两表 + 连通修正（66 条）。回跑 V2：`SANWALK_CONFIG=firstShow@2 npm run dev` 或 `npm run check firstShow@2`；V1：`firstShow@1`。
- 离线可复现：RNG 用 mulberry32，种子存 `state.rngState`，所有随机走 `randFloat / randInt / rollRange / pickOne`，改调用顺序只会平移序列、不破坏概率。

### T4 评价掷骰钩子（Q19）
- **目标**：`settleTask` 按 `r = 主力属性 / attrBaseline` 算四档权重，掷骰得 evalTier，乘率 `[1, 1.3, 1.6, 2.0]` 作用于主产出数量（及 B 省料 / C 关系维度）。
- **涉及**：`tick.ts::settleTask`, `types.ts`(TaskDef.attrBaseline, cls)
- **算法**：`a = state.attrs[clsToAttr(def.cls)]`；`base = def.attrBaseline`；`r = a / base`；`w0 = clamp(1 - r/3, 0, 1)`；`w2 = clamp((r-1)/2, 0, 1)`；`w3 = w2`；`w1 = 1`；归一化→抽四档→乘率作用于 `mainOutputNum`。
- **硬规则**：`r < 1` 仅拙+平（佳/绝恒 0）；`r ≥ 3` 拙=0。
- **cls→attr 映射**：A→force，B→intelligent，C→politics；统帅不进评价（全局节拍器）。
- **验收**：临时断言——r<1 时 samples 不出佳/绝；r≥3 不出拙；属性越高绝占比上升。属性来源当前为临时桥（T7 删后需另接）。

### T5 产出分层 A / B / C
- **目标**：按 cls 走不同产出分支（A 给量 / B 给效率省料 / C 给关系好感+稀有+图纸）。
- **涉及**：`tick.ts::settleTask`, `types.ts`(mainOutput/subOutput/evalInc), 新增好感/图纸累加字段（GameState）
- **逻辑**：A：主产出 ×(1+evalInc)；B：材料消耗按 evalTier 递减（绝 −25%）+ 残料返还；C：好感 += f(evalTier)，按概率给稀有道具/图纸（蓝图 `fromSkill` 必 C）。
- **验收**：三类分支正确；C 给好感/稀有/图纸；**A 绝不给稀有**（红线①）。

### T6 制作 / 配方系统（🟡 半落地：2026-10-03）

- **逻辑**：`canCraft(recipe, state)`：① `matQualityFloor ≥ quality`（红线④，只正向）② `needRare` 对应稀有料齐 ③ `needBlueprint` 已解锁；`craft()` 扣料→入包。

### T7 属性正式来源预留 + 删临时桥（✅ 已落地 2026-10-04）
- **目标**：保留 `addAttrXp` 为唯一入口；V2 不实装随机事件，删除 TEMP 段（接随机事件时由其调用 `addAttrXp`）。
- **涉及**：`tick.ts`（已**删净**顶部 `TEMP_*` 常量与原临时喂经验段）、新增 `src/game/attrGain.ts`、`constants.ts`
- **落地做法**：
  1. `addAttrXp` **本体迁到 `game/attrGain.ts`**，作为唯一的属性入口；`tick.ts` 只做 `export { addAttrXp }` 再导出，调用侧（含未来的随机事件）不受影响。
  2. `tick.ts::settleTask` 里改调用 `gainTaskAttrXp(state, cfg, def)` —— 这是随机事件接管前的**唯一过渡供给源**（A←武力 / B←智力 / C←政治 + `ATTR_LEAD_CHANCE` 概率给统帅），数值挪到 `constants.ts` 的 `ATTR_XP_PER_TASK / ATTR_LEAD_CHANCE / ATTR_LEAD_XP`。
  3. **接入 F19b 随机事件时**：删掉 `settleTask` 中这一句调用，并删除上述三个常量与本文件的过渡段；随机事件仍走同一个 `addAttrXp`。
- **为什么不直接「删完留缺口」**：直接删会导致四维冻在初始 2–5，`r = a/attrBaseline < 1` 恒只出拙+平，T4 评价钩子与 M5 产出分层全部退化失效。故把供给显式收敛到一个可整段替换的模块，而不是埋在 `tick.ts` 的行内常量里。
- **验收**：✅ `typecheck` 通过；✅ `check` 结果与删改前**逐项一致**（180 任务/天、四维 `{8,5,9,7}`、评价 `56/99/14/11`），说明 RNG 序列未被平移；✅ `check:v1` 全中。

### 5.2 数值实测（`npm run calib`，2026-10-03）

| 天数 | 任务/天 | 技能等级 | 开放品质 | 最高产出品质 | B 缺料率 | 图纸 |
|---|---|---|---|---|---|---|
| 1 | 180 | Lv4–7 | 1–3 | 3 | 11% | 0 |
| 3 | 182 | Lv9–11 | 1–3 → 2–4 | 3 | 4% | 0 |
| 7 | 181 | Lv16–19 | 2–4 | 4 | 10% | 0 |
| 14 | 182 | Lv26–30 | 3–5 | 5 | 22% | 0 |
| 30 | 179 | Lv48–52 | 5–7 / 6–8 | 8 | 47% | 3 |
| 60 | 177 | Lv82–88 | 7–9 | 9 | 59% | 3 |
| 90 | 176 | Lv100（封顶） | 7–9 | 9 | 63% | 3 |

- 技能 Lv30 ≈ **第 14 天**，与既有四维「约 16 天到 Lv29-30」同节奏（这就是把 `SKILL_XP_PER_QUALITY` 定为 2 的依据）。
- 🔴 **Q21 阻塞项（数值，非逻辑）**：`item` 表 A 类产出随**品质升高反而变少**（q1 `1;12` → q9 `1;4`），而 `recipe.needItem1Num` 随品质**升高**（2 → 6），且 B 任务一次要交付 `1;1`~`1;3` 件。结果是高阶 B 类结构性断料，长期缺料率 60%+。要解只能二选一：**抬高 A 的逐品产出**，或**压低 recipe 的投喂量 / B 的单次交付件数**。当前实现已做「能做几件做几件」的部分交付，不会因为缺一件而全停。

### 5.3 已知配置缺口（非代码问题）

- 🔴 **75 条配方缺 `cityBlueprint`**：105 条高阶配方需要 `needBlueprint`，其中只有 30 条填了 `cityBlueprint`（缺的都是 q7–9 那几行）。红线③（三城互异）因此只对已登记的那 30 条生效，其余在 `npm run check` 里以一条聚合告警报出。修补全在配置侧（`recipe` 表补城市名）。

- **离线可复现**：所有随机走 `randFloat/randInt/rollRange/pickOne`，改 RNG 调用顺序会平移序列但不破坏各概率本身。
