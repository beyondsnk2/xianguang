# 界面信息优化方案 v1

> 日期：2026-10-04　范围：V2 当前界面（顶栏 / 地图 / 右侧栏 / 三个弹窗 / 任务板）
> 目标：① 补齐缺失信息 ② 让关键状态突出 ③ 让"惊喜"有反馈 ④ 理顺信息架构
> 本文只定**改什么 + 两版视觉方向**，选定方案后再出实现排期

## 二、需要优化的信息清单

### A. 显示不完整 / 缺失（最影响理解）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| A1 | **物品名未本地化**：`format.ts::itemName` 只认识 `grain/mine`，其余一律回显英文 tag（`iron_3`、`rare_gold_5`） | 背包/仓库/日志满屏英文 tag，V2 有 27材料/54稀有/315成品/3名品，`cfg.itemByTag[].name` 里有真名却没用 | `itemName` 改为接收 `cfg`，回退链 `cfg.itemByTag[tag].name → 中文表 → tag` |
| A2 | **任务卡产物信息是 V1 口径**：用 `getItem/getAttrXp`，而 V2 的真实产出是 `mainOutput` + 品质 + 评价；`getAttrXp` 设计上恒为 null → 退化成「经验 0~0」 | 玩家看不出"这个任务给我什么"，无法决策排序 | 产物列改用 `mainOutput` + 按 cls 语义（A给量/B成品/C好感·稀有·图纸）；补品质(1–9)与类别标识 |
| A3 | **9 技能等级完全不可见**：`src/ui/` 下 `skills` 零引用 | 技能是 V2 核心成长线（决定品质窗口/解锁高品质任务），玩家却看不到 | 角色面板加技能区；主界面给最高/在练技能一个入口 |
| A4 | **图纸 / 稀有料 / 名品无陈列**：`state.blueprints` 有值但界面无呈现；名品只在日志里一句 | 稀有收集品没有"陈列感"，积累感消失 | 背包弹窗加「图纸 / 名品」分区，带数量与来源 |
| A5 | **任务卡缺类别标识（A采集/B制造/C人物）** | 玩家无法把"做任务"与"涨关系/涨技能"对应起来 | 任务卡加类别色标 + 品质角标 |
| A6 | **离线结算无留档**：只有一句 toast，关掉就没了 | 回来看不到"离开期间发生了什么" | 日志/事件流里保留一条离线摘要，或弹一次结算面板 |
| A7 | **关系面板缺筛选与分组**：23 张卡片平铺，无阵营筛选/排序/已结识–未结识分组 | 想找某个武将要滚很久，也看不出"还有多少人没遇到" | 加筛选条（阵营 / 已结识 / 未结识）+ 按好感排序 |

### B. 关键信息不突出

| # | 问题 | 建议 |
|---|---|---|
| B1 | **当前状态（在做什么、还要多久）只是侧栏一张普通卡片**，13px 小字 + 6px 细条 | 提升为全局可见的"当前任务条"，大字号 + 粗进度条 |
| B2 | **背包容量压力只在弹窗里**，满仓前毫无预警 | 顶栏放容量胶囊，≥80% 转警示色 |
| B3 | **任务板队首仅靠金色边框区分** | 队首做成"进行中"大卡片，带状态标签（赶路/作业） |
| B4 | **四维属性 Lv 只在弹窗** | 主界面给一行紧凑四维 + 迷你进度 |
| B5 | **关系值/阶段** 与普通文本同层级 | 阶段名加徽章，进度条按阶段分色 |
| B6 | **中文字段（品质/评价/类别）** 在任务卡里是数字/英文 | 全部中文化并加色阶 |

### C. "惊喜"没有反馈（最影响爽感）

| # | 事件 | 现状 | 建议反馈 |
|---|---|---|---|
| C1 | **初识偶遇**（C类随机） | 仅一行普通日志，无 toast | toast + 事件流"稀有"高亮 + 关系按钮红点 |
| C2 | **获得名品**（极稀有 5%×高品） | 仅一行日志，无 toast | 强反馈：专属 toast（金框+放大）+ 事件流"传说"级 |
| C3 | **习得图纸** | 仅一行日志 | toast + 事件流高亮 |
| C4 | **关系升阶**（初识→相识→…→知己） | 仅攻略对象有日志，无 toast | toast + 事件流 + 关系面板阶段徽章跳动 |
| C5 | **四维属性升级** | **完全没有反馈**（`addAttrXp` 升级静默） | toast「武力 提升至 Lv N」 |
| C6 | **技能升级** | **完全没有反馈** | toast + 技能条高亮 |
| C7 | **评价「绝」** | 日志里一个"（绝）"，无视觉差异 | 任务完成时评价档用颜色/字号区分，绝档高亮 |

### D. 信息架构 / 传达

| # | 问题 | 建议 |
|---|---|---|
| D1 | **开发者信息混在玩家信息里**：「调试/存档」「配置与路网自检」与任务板同级 | 折叠为底部"开发者"抽屉，默认收起 |
| D2 | **顶栏 meta-line 是技术元信息**（文件名、表数、节点数），对玩家无意义 | 移入开发者抽屉；腾出的位置放关键指标 |
| D3 | **顶栏「速度 20 秒/格」与调试区的加速按钮语义重复** | 合并：顶栏只显示当前倍率（×1/×10/×60） |
| D4 | **任务卡无拖拽手柄**，能否排序只靠一行 tip | 加可见手柄图标 + 首屏引导 |
| D5 | **数值格式不统一**：好感 `8.0`、距下阶 `还需 1` 等 | 好感保留 1 位或整数化；"还需"文案按阶段语义重写 |
| D6 | **颜色语义未成体系**：`--green/--red` 只用于自检面板 | 建立语义色：普通/稀有/传说、成功/警示、四阵营 |
| D7 | **弹窗宽度 420px** 对 23 人关系列表过窄 | 关系弹窗加宽 + 内部分组/筛选（见 A7） |

## 三、两版视觉方案

### 方案 A：焦点分层（Focus / 克制）

**理念**：挂机游戏的重心是"此刻正在发生的一件事"。主界面只放大这一件事，其余信息按层级收纳；靠**字号 / 字重 / 间距 / 留白**建立层次，不新增色相。

```
┌────────────────────────────────────────────────────────────┐
│ 闲逛   [进行中] 赶路 · 前往上庸·兵营 训练                    │
│        ▓▓▓▓▓▓▓▓▓▓▓░░░░░░  剩余 2分30秒 · 5格                │ ← 当前任务条（全局最醒目）
│        任务12  背包12/20  已结识5/23  技能最高Lv7  ×10      │ ← 指标胶囊（≥80%转警示）
├──────────────────────────────────┬─────────────────────────┤
│                                  │ 任务板                   │
│  地图                             │ ┌ 进行中 ─────────────┐ │
│  ┌──┐袋 ┌──┤将 ┌──┘缘(1)         │ │ ‹手柄› 上庸·兵营 训练 │ │ ← 队首大卡片
│  └──┘   └──┘   └──┘              │ │ 品质5 · 武力 · 绝    │ │
│                                  │ └──────────────────────┘ │
│                                  │ ┌ 2 街市 交易 ───────┐   │
│                                  │ ├ 3 农田 耕种 ───────┤   │
│                                  │ ⋮                        │
│                                  │ 事件流                   │
│                                  │ ◆ 偶遇 蜀·赵云（初识）   │ ← 按稀有度着色
│                                  │ ● 洛阳·街市 交易完成(佳) │
│                                  │ ▸ 开发者 ▾（收起）       │
└──────────────────────────────────┴─────────────────────────┘
```

**关键改动**
1. 当前状态从侧栏卡片升为**顶栏下方的当前任务条**（最大字号 + 8px 粗进度条）。
2. 顶栏右侧改**指标胶囊**：背包容量（预警变色）、已结识人数、技能最高级、当前倍率；技术元信息移入开发者抽屉。
3. 侧栏精简为「任务板」+「事件流」两块；调试/自检折叠进 `▸ 开发者`。
4. **事件流取代普通日志**：按稀有度分色（普通 / 稀有 / 传说），新事件淡入高亮，承载 C1–C7 全部惊喜反馈。
5. 左菜单加**红点提示**（关系面板有新增初识/升阶时）。
6. 弹窗改造：关系加筛选分组（A7）+ 加宽；背包/角色用真物品名（A1）+ 技能区（A3）+ 图纸名品陈列（A4）。

**配色**：沿用现有暗色 + 金色主色；新增 3 档稀有度色（灰 / 蓝紫 / 金橙）+ 1 个警示色。色相克制。

**优点**：改动集中在架构与层级，视觉风险低；符合挂机"安静、不打扰"的气质；加载/重渲染成本低。
**代价**：一次能看到的信息少，想"全览"仍需点开弹窗。

---

### 方案 B：驾驶舱（Dense Dashboard）

**理念**：把界面做成**驾驶舱**——地图退居背景，常驻展示角色 / 技能 / 关系 / 背包 / 事件，一屏看完所有状态。信息密度优先，用色相区分信息域。

```
┌──────────────────────────────────────────────────────────────────┐
│ 闲逛   [进行中]赶路·上庸兵营训练 ▓▓▓▓░░ 2分30秒       ×10  背包12/20│
├──────────┬──────────────────────────┬────────────────────────────┤
│ 角色      │                          │ 任务板                       │
│ 武12 统7  │      地图 canvas          │ ┌①上庸·兵营 训练 品质5 武力┐  │
│ 智9  政5  │                          │ │ 赶路中 5格 2分30 ────────│ │
│ ────────  │                          │ └ 2 街市 交易 品质3 智力 ──┘ │
│ 技能       │                          │ ⋮                            │
│ 采掘 Lv7▓ │                          │ 背包 12/20 ▓▓▓▓▓▓░░░░       │
│ 锻造 Lv4▓ │                          │ 关系 已结识 5/23             │
│ 拜访 Lv3░ │                          │ ─────────────────────────    │
│ ────────  │                          │ 事件流                       │
│ 关系       │                          │ ◆偶遇 蜀·赵云（初识）        │
│ 攻略:赵云  │                          │ ★获得名品「和氏璧」          │
│ 赵云 初识▓ │                          │ ●洛阳·街市 交易完成(绝)      │
│ 关羽 未识░ │                          │ ▸开发者▾                     │
└──────────┴──────────────────────────┴────────────────────────────┘
```

**关键改动**
1. **三栏布局**：左 240px（角色 + 四维 + 9技能迷你条 + 关系 Top3/攻略对象）、中地图、右 380px（任务板 + 背包/关系容量条 + 事件流）。
2. 技能、四维、背包、关系**常驻可见**，不再藏进弹窗（直接解决 A3/B4/B2）。
3. **事件流独立成栏**，稀有度着色 + 新事件淡入（C1–C7）。
4. **配色体系化**：品质 1–9 色阶、四阵营色（魏蓝/蜀赤/吴青/群褐）、稀有度色（白/蓝/紫/橙/红），金色留给"当前任务"和传说事件。
5. 底部保留开发者抽屉（D1/D2）。

**配色**：在金色主色外引入完整语义色板（品质色阶 + 阵营色 + 稀有度色）。信息辨识度高。

**优点**：信息全展开，一屏看懂全部状态；技能/关系/背包不再需要点开弹窗；色相帮助快速定位。
**代价**：信息密度高、视觉更"吵"，与挂机"安静"的气质有冲突；地图被压缩；实现量与重渲染成本更大。

## 四、建议与待定

- **倾向方案 A**：V2 是挂机游戏，"克制 + 焦点"更贴合气质，且改动风险低、能先解决 A/C 类硬伤（物品名、技能不可见、惊喜无反馈）。
- 但 A 的"技能常驻不可见"是真实损失 → 可选**混合**：采用 A 的架构，但把"技能"做成顶栏胶囊可展开的迷你面板（A3 的折中）。
- 无论选哪版，**A1（物品真名）、A2（产物口径）、C5/C6（属性/技能升级反馈）** 都应优先修，属于"信息错误/静默"级问题，不是风格问题。

3. 是否保留"配置与路网自检"等开发者信息的常驻入口（还是全部收起）
