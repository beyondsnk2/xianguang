# V3 地图渲染开发文档（codeBuddy 开发规格）

> **用途**：codeBuddy 实现地图写实化渲染的输入。目标是把现有点阵/格子地图换成「写意背景 + 城块拼图 + 城际曲线道路」的观感（参考《三国志13》势力地图），**逻辑层零改动**。
> **配套文档**：本篇只管渲染。玩法系统见 `V2功能开发_v1.md`（T 系列）；地图数据设计见 `设计_V2地图_42城14州_v1.md`。
> **视觉参照**：可交互原型 `tools/out/map_v2_blocks.html`（已用真实配置数据实装全部效果，实现细节可直接抄）。
> **建立**：2026-10-06。配置基线：`firstShow_V3.xlsx`。

## 〇、如何验收

- 每次改动后跑 `npm run typecheck`（tsc 门禁）+ `npm run check`（全量自检，当前基线：路网基准全中、cityLink 66 条全对拍一致、183 任务/天）。
- `npm run dev` 打开游戏，对照视觉验收清单（§八）逐项检查。
- **逻辑层红线**：`src/game/` 目录一行不改。渲染只能消费 `GameConfig` / `Graph` / `GameState` 的只读数据。

## 一、架构总则（先读这段，防止做歪）

1. **格子是唯一真相，曲线只是影子的形状**。角色移动、任务耗时、距离计算全部基于 60×45 逻辑网格的 Dijkstra（`src/game/graph.ts`），渲染层**只负责把格子世界画得不像格子**。
2. **去格子感的两个来源必须都消除**：① 每格填矩形的色块 → 换成有机场；② 网格线 → 默认不画（可留 `?debugGrid=1` 调试开关）。
3. **一切重计算离屏缓存**：地形/城块/道路曲线只在「配置加载 / 视口尺寸变化」时烘焙，主循环只 `drawImage` + 画动态元素（路径、角色、光圈）。
4. 对外接口保持：`MapRenderer` 类的 `setMapSize / fit / zoom / pan / draw / resize / pointAt` 签名不变，`main.ts` 理论上零改动。

## 二、渲染分层规格

自底向上 5 层，L0–L3 烘焙进离屏 canvas，L4 每帧画：

### L0 背景层

- 读 `config.mapBgImg`（`public/` 下文件名）：有值 → `Image` 加载后 cover 铺满，压暗处理（叠一层 `rgba(10,12,8,0.35)` 保证上层可读）；空/加载失败 → 程序化占位：深色底（`#23261F` 一类）+ 26 个低频径向光斑（云纹，alpha≈0.16）+ 晕影。
- **不用任何真实地理轮廓**（合规：虚构世界，不描摹真实边界/海岸线）。大陆形状完全由 L1 城块的并集自然构成。

### L1 城块层（"城市+周边空地被框起来"）

- **文明区**：多源 BFS 距离场——源 = `mapNode` 全部格 ∪ `mapRoad` 全部格，四邻域扩散，**距离 ≤ 4 格**的区域为文明区（即"城市和它周边的空地"）。块的并集自然构成大陆形状。
- **着色**：文明区内每格取「最近城（BFS 先到者）」的 `city.state` → `state.color`。等价于在文明区限制内的 Voronoi，天然把 42 城拼成 14 个州块。
- **边界有机化（domain warp）**：采样格坐标前加低频噪声位移（fbm 2~3 octave，空间频率 ≈0.09/格，幅度 ≈3.4 格）。⚠ 幅度不可过大：会把贴着文明区边缘的城块扭碎（原型实测 4.5 会出问题，3.4 稳定）。
- **层次感**：距文明边缘越近 alpha 越低（城心 0.66 → 边缘 ≈0.30），叠加细噪声（幅度 ±7）做笔触感。
- **烘焙参数**：分辨率取目标画布 CSS 尺寸的 1/3 左右（原型用 480×360），`imageSmoothingQuality='high'` 放大 —— 边界柔和正好符合手绘感。烘焙耗时实测 <100ms。

### L2 道路层（城际曲线，"仅表示连通关系和距离长短"）

- 数据源：`cfg.links`（cityLink 表，66 条）。**每条 link 跑一次 `findPath(城A任一格, 城B全部格)`** 拿真实格子路径 → 平滑成曲线。**不要画城心直连的示意直线**——那样道路形状与实际绕行不符（图又说了一次谎）。
- 平滑：格子序列 → Douglas-Peucker(容差 0.28 格) 去共线点 → 每段中点沿法线加低幅弯曲（幅度 ≤0.3 格，`sin` 相位避免相邻段同向）→ Catmull-Rom 采样。⚠ 环检测：平滑/延伸必须带 visited 集，闭环路网曾出现被绕成 2000 格长链的 bug。
- 描边双层：底层 `rgba(92,68,38,0.34)` 宽 = 路宽×1.5；上层 `#EADCB4`（alpha 0.95）宽 = `max(1.6, s×0.16)`（s=像素/格）。**线宽只在此一处换算，不得二次放大**。
- 全部曲线合并为一个 `Path2D` 一次 stroke（66 条 × 2 层 = 2 次 stroke），启动烘焙缓存。

### L3 节点层

- 城（`name==='city'`，2×2）：城郭图标——米白圆角矩形 + 顶部 4 个垛口 + 中央朱红块，黑描边；右侧/下方城名（描边字，`s>7` 时显示）。2×2 中心为锚点。
- 州名：`s < 14` 时在每州城块质心画州名（大号、低对比度），放大后隐藏（城名接管）。
- 设施（1 格）：小圆点（半径 `max(1.6, s×0.14)`），`s > 16` 时才显示设施名首字。

### L4 动态层（每帧）

- **当前路径**：`phase.kind === 'moving' | 'returning'` 时，取 `phase.path`（格子序列）→ 平滑（同 L2 算法，**按 path 引用缓存**）→ 分两段着色：已走过（`progress` 之前，alpha 0.35）/ 未走（亮色）。
- **角色**：位置 = 沿平滑曲线按 progress 取点（取点规则见 §三）。
- **目标光圈**：path 末端格画脉冲圆环；`working` 状态在当前设施画脉冲。
- 这些每帧重画（路径平滑结果缓存，不动）。

## 三、角色移动的取点规则（关键实现，防止视觉与逻辑脱节）

移动的真相链路（**全部已有，勿改**）：`findPath → phase{path,total,remain} → tick 推进 remain → progress = 1-remain/total → pointOnPath(path,progress)`（`src/game/tick.ts`）。

渲染取点要求**视觉位置严格对应逻辑进度**：

1. 对 `phase.path` 构建平滑曲线时，**每个曲线控制点携带「累计格数」标签**（原格子序列的下标）。
2. 取点：`g = progress × (path.length - 1)` → 找到 `g` 落在的格段 → 该段两端控制点间按小数部分插值。
3. 禁止按曲线弧长均匀取点——平滑切角会让弧长 < 格子折线长，角色观感时快时慢。

## 四、配置依据（全部已落地，勿改结构）

| 表/字段 | 内容 | 渲染用途 |
|---|---|---|
| `cityLink`（66 行） | `tagA, tagB, dist`（dist=城心 Dijkstra 格距，生成器写入） | L2 画哪些曲线；`dist` 供 UI 显示"距目标 X 格"（**不进耗时计算**） |
| `state`（14 行） | `tag, name, color` | L1 州块着色 + L3 州名 |
| `city.state` 列 | 所属州 tag | 城 → 州归属 |
| `config.mapBgImg` | 背景图文件名，留空=程序化占位 | L0 |
| `mapNode` / `mapRoad` | 不变 | L1 距离场源、L2 findPath 素材 |

⚠ 城市名 → 州色的解析链：`cfg.cityByTag[tag].state → cfg.stateByTag[state].color`。旧配置（V1/V2）无 state/cityLink 表时渲染器**必须可降级**：无 links → 不画曲线；无 state → 城块用单色中性色。用 `check:v1` 验证不崩。

## 五、任务清单（codeBuddy 执行）

### R1 渲染层骨架 + 视觉参数集中

- **做什么**：重写 `src/render/map.ts`（对外接口不变）。视觉常量（配色、线宽系数、warp 幅度、烘焙分辨率、文明区半径 R=4）集中到新文件 `src/render/mapStyle.ts`，不散落魔法数。
- **验收**：`main.ts` 无改动编译通过；游戏可打开，画面至少有 L0 占位底。

### R2 背景层

- **做什么**：按 §二 L0 实现 `mapBgImg` 加载与程序化占位，离屏缓存（失效条件：画布尺寸变化 / mapBgImg 变化）。
- **验收**：配置空值出占位底图；往 `public/` 放图并在 config 表填文件名后显示该图且被压暗。

### R3 城块层

- **做什么**：按 §二 L1 实现距离场 + 州色 + warp + 烘焙。烘焙入口在 `setMapSize` 后惰性触发。
- **验收**：42 城拼成 14 个州色块、边缘是有机曲线、无网格线痕迹；`check:v1`（无 state 表）降级为单色块不崩。

### R4 道路层

- **做什么**：按 §二 L2 实现 link→findPath→平滑→双层描边，Path2D 合并绘制，启动缓存。
- **验收**：66 条曲线全部可见且贴合道路走向（对照原型）；晋阳-上党间无曲线、河内-上党有；放大 3 倍线宽比例正确。

### R5 节点层

- **做什么**：按 §二 L3 实现城郭图标/城名/州名/设施点，随缩放分级显示。
- **验收**：缩放全程文字可读、无重叠灾难；设施点不挡城名。

### R6 动态层（角色与路径）

- **做什么**：按 §二 L4 + §三取点规则实现。接任务后：亮色曲线沿路延伸、角色贴线移动、到达后光圈消失、`returning` 用绿色系区分。
- **验收**：角色任何时刻都在平滑曲线上而非格锯齿上；视觉进度与任务面板剩余时间一致（走一半 ≈ 剩一半时间）；跨城长路径角色平滑穿过途经城块不跳变。

### R7 调试开关与降级

- **做什么**：URL 参数 `?debugGrid=1` 叠加原网格线与格心点（校验用）；旧配置降级路径（§四 ⚠）。
- **验收**：debug 模式下可核对曲线与格子路径的贴合度；`check:v1` + dev 钉 V1 不崩。

## 六、性能预算

- 主循环每帧：1 次 `drawImage`（L0-L3 合成的离屏层）+ L4 矢量绘制（<100 条 path）+ 文本。目标 60fps（中端核显）。
- 烘焙（首次 + 尺寸变化）：总耗时 <300ms（原型实测城块 <100ms）。烘焙期间可先出 L0 占位。
- 缩放平移：L0-L3 缓存按「内容尺寸 = 视口 × 当前缩放档」重烘（节流 200ms），缩放中允许临时拉伸旧缓存。
- ⚠ 任何逐像素计算必须查表化：fbm 高度/噪声每像素全量重算 ≈ 5s/70 万像素（原型实测），烘焙进低分辨率数组后 <70ms。禁止在 draw 循环里调 fbm。

## 八、视觉验收清单（产品视角）

1. 第一眼无格子感（无网格线、无矩形色块）。
2. 14 个州色块可辨，块边缘是有机曲线，像"城市和周边空地拼起来的拼图"。
3. 城际道路是自然弯曲的浅色曲线，走向与实际路网绕行一致。
4. 角色沿曲线平滑移动，位置与剩余时间严格同步。
5. 放大到城市级别：城郭图标清晰、设施点可见、无文字重叠。
6. 缩放/拖动流畅无卡顿。

## 九、明确不做（本轮边界）

- 不做 3D / 倾斜透视（曾评估，挂机场景可读性优先，砍）。
- 不做地形逻辑阻挡（山川不进 Dijkstra；`roadType` 字段仅为未来官道/小路速度差预留，本轮不实现）。
- 不做地图点击交互（当前地图纯展示 + 缩放平移，任务发起都在任务板）。
- 不做程序化写实地形（山脉/河流纹理）——用户已裁定方向为"背景 + 城块拼图"，地形交给背景图素材。
- 不改 `cityLink.dist` 的语义（它不是耗时来源；耗时 = 逻辑层 Dijkstra 总格数 × speed）。
