# V2 随机事件系统设计 v1

> **定位**：在线层核心内容系统。挂机层（移动/任务/技能/产出）全自动推进；**事件层承担「过程内容 + 属性成长 + 内容丰富性 + 即时决策 + 重复登录拉力」**。
> **内容包装**：光荣历史模拟类（三国志 / 太阁立志传）为主 —— 见闻典故、人物交游、术业修业、名所收集。
> **小游戏**：参考更广泛游戏，但遵循太阁的正反两面经验（见 §六）。
> **前置依据**：`调研_太阁.md`、`对比_san13与太阁5.md`（交叉验证的因果 A/B/C/D/E/F）；V2 功能清单 F16 / F19b / F19c / F31 / F32 / F33 / F54；Q11。
> **建立**：2026-10-04（第一版，待提问修订）。

## 〇、一句话定位与三条红线

**事件层与挂机层正交**：

| 层 | 谁驱动 | 产出 | 玩家在做什么 |
|---|---|---|---|
| **挂机层** | 自动（在线/离线同引擎） | 技能经验、材料/制成品/好感 | 出发前配置（拖任务顺序、路线） |
| **事件层** | **在线时触发，需交互** | **属性经验**、名品、见闻、钱粮、事迹 | 阅读、抉择、玩小游戏、打战斗 |

**继承调研因果（本设计的立论）**：

| 因果 | 内容 | 对事件系统的要求 |
|---|---|---|
| **因果 A** | 重复动作必须换皮；自动任务不给过程内容 → 比"等圆圈"更空 | **路途事件是必需品，不是装饰品** |
| **因果 B** | 成长不靠操作精度（太阁修业经验累积制，失败也涨） | 事件结算与小游戏必须**保底**，不卡玩家 |
| **因果 C** | 技巧点只能前置到"出发前配置" | 事件补上**即时技巧点**（抉择 / 小游戏），与前置配置形成两段 |
| **因果 D** | 跨存档元进度是长线动力关键 | 本地化为**见闻录**（存档内长期收集，不依赖"重开一局"） |
| **因果 E** | 权限扩张比内容扩张省成本 | 见闻录的解锁优先给"新事件池/新交互"，而非单纯新文本 |
| **因果 F** | 个人经济线是"不打仗也能玩"的基础 | 盘缠类事件给经济线提供**玩法**（不只是数字） |

**三条红线**（继承 F16 / V2-5 / 不剥夺主体性）：

| # | 红线 | 含义 |
|---|---|---|
| ① | **只惩罚机会层，绝不惩罚资产层** | 过期/超限失去的是"这次机会"，**永不倒扣已有属性/物品/钱粮** |
| ② | **损失必须明示、严禁暗扣** | 错过的事件进日志明确列出；不偷偷扣 |
| ③ | **事件必须可抉择 / 可跳过** | 玩家永远有"不处理"的出口；不强制、不卡流程 |

## 一、功能结构（六层）

| 层 | 职责 | 关键机制 |
|---|---|---|
| **① 容器层** | 事件列表（牌堆） | 容量 ≤10（可养成提升）、时限分层、过期、超限、highlights |
| **② 类型层** | 事件分类 | 七类 + 战斗类（F31） |
| **③ 内容层** | 单条事件 | 触发条件 + 呈现（人物/地点/文本）+ 交互 + 结算 |
| **④ 交互层** | 玩家怎么参与 | 纯文本 / 二选一 / 多选项 / **小游戏** / 战斗 / 对话-送礼 |
| **⑤ 结算层** | 给什么 | **属性经验（主力）** / 好感 / 物品名品 / 钱粮 / 事迹 / 见闻录 |
| **⑥ 元系统层** | 长线收集 | **见闻录**（图鉴）→ 集齐解锁新事件池 / 新交互 / 称号 |

### 1.1 单条事件的标准结构

```
[触发条件] 标签: 地点/人物/技能/称号/季节/持有物/前置事件/已解锁
    ↓
[呈现] 标题 + 地点/人物 + 文本（三国典故包装）+ 可选插图/头像
    ↓
[交互] 纯文本 | 二选一 | 多选项 | 小游戏 | 战斗 | 对话-送礼
    ↓
[结算] 属性经验 + 好感/物品/钱粮 + 事迹 + 见闻条目
    ↓
[归档] 进旅途日志；重要者进 highlights
```

## 二、事件类型（七类 + 战斗类）

> 七类沿用 F31；每类的"时限"按 F32 分层（越基础越长、越偏收集越短）。

| 类型 | 定位 | 触发源 | 时限 | 交互 | 主结算 | 内容示例（三国味） |
|---|---|---|---|---|---|---|
| **① 风土见闻** | 地理/典故/名所，纯收集 | 首次造访城/设施/道路 | **无限** | 纯文本 | 见闻录 + 少量政治/智力 | 望泰山而"小天下"；琅琊诸葛氏故里；西凉"凉州大马"；交趾薏苡明珠之谤 |
| **② 路人遭遇** | 途中人物交集 | 移动中（时间/行为源） | 4–8h | 对话 / 二选一 | 好感 + 属性 | 贩马商人、游侠、流民、方士、乞丐（**可能是微服的名士**） |
| **③ 旅途二选一** | 即时取舍（技巧点） | 移动中 | 1–4h | **二选一** | 得失并存 | 官道（安全耗时）vs 小路（快捷遇匪）；渡船 vs 绕桥；救助病人（耗盘缠）vs 赶路 |
| **④ 奇遇** | 低概率惊喜 | 条件触发（地点+时间+持有/技能） | 1–4h | 多选项 / 小游戏 | 稀有（名品/秘技/大量属性） | 夜遇老者授书（黄石公）；山中隐士（水镜/卧龙）；拾得遗物 |
| **⑤ 随行家臣** | 羁绊与建议 | 有家臣随行时 | 4–8h | 对话 / 二选一 | 家臣好感 + 属性 | 家臣谏言（给建议）；家臣间矛盾调解；家臣立功 |
| **⑥ 地盘事件** | 城市/设施相关 | 到达城/设施 | 4–8h | 多选项 / 小游戏 | 好感 + 钱粮 + 属性 | 洛阳太学风潮；成都锦官城织造；建业造船；邺铜雀台传闻 |
| **⑦ 盘缠波动** | 经济线（消耗侧玩法） | 时间源 / 到达城 | 4–8h | 多选项 | 钱粮 ± | 米价涨跌（低买高卖）；行商推荐；被窃；赏赐 |
| **⑧ 战斗类** | 接战斗系统 | 移动中（低概率）/ 特定地点 | 可积攒 | **战斗**（F40-50） | 功勋 + 粮草消耗 | 山贼劫道；猛兽；黄巾余党；关隘盘查 |

> **⑧ 战斗类**是 F31 新增项，与 F54（积攒/超限/粮草不足可跳过）对齐；频率待 F53 数值反推。

## 三、随机出现逻辑（核心）

### 3.1 双源触发

| 源 | 机制 | 说明 |
|---|---|---|
| **时间源** | 在线每 **T 分钟**（建议 10）累积 1 个"事件点"，满 1 点触发一次机会 | 每日在线预算上限 **N 条**（建议 12–16，其中战斗类 ≤2） |
| **行为源** | 到达城/设施、完成任务、首次造访某地、携带特定物品 → 立即触发一次机会 | 让"到达"这件事有即时反馈（对应地盘/见闻类） |

> 结合 V2 实测：单任务周期 ~8.8 分钟、167 任务/天 → 每 ~7–8 个任务出现 1 个事件，密度不打断挂机节奏。**具体数值归后续反推。**

### 3.2 权重闸门（多层筛选 → 加权抽取）

```
候选池
  ↓ ① 标签筛选（地点/人物/技能/称号/季节/持有物/前置事件/已解锁）
  ↓ ② 类型基础权重（七类 + 战斗类，可调）
  ↓ ③ 偏向修正（称号 / 技能 / 属性补偿 / 人物好感）
  ↓ ④ 冷却去重（同 tag 冷却、同类连出抑制）
  ↓ 加权随机抽取
```

**③ 偏向修正的四路闸门**：

| 闸门 | 依据 | 作用 |
|---|---|---|
| **称号** | F10c / F21 | 影响高品质事件、奇遇、战斗类概率（称号 = 剧情钥匙，参照太阁"报上姓名"） |
| **技能** | **Q11（本设计定案建议：是）** | 见 §3.3 |
| **属性补偿** | F19c | 属性落后预期 → 提高"给属性"类事件权重；**≤ 当日事件总数 ×10%**；只给属性；不追平 100% |
| **人物好感** | 关系四段漏斗 | 好感高 → 提高该人物专属事件概率（让关系变"钥匙"而非装饰） |

### 3.3 🔴 Q11 定案建议：**技能影响事件偏向（建议「是」）**

> Q11 此前留到讨论随机事件时定 —— 现在定。

**建议方案**：技能等级修正「事件的属性偏向」与「类型偏向」，**只改权重、不改内容、不硬锁**。

| 玩家技能偏向 | 事件偏向 | 例子 |
|---|---|---|
| 采掘/采药/猎奇（A）高 | 更多**武力**向事件、更多地盘/见闻类 | 常去名山大川 → 遇隐士、遇猛兽 |
| 锻造/丹鼎/机巧（B）高 | 更多**智力**向事件、更多修业/制作小游戏 | 常驻工坊 → 遇匠人切磋、遇丹方 |
| 访道/结义/出使（C）高 | 更多**政治**向事件、更多人物/奇遇 | 交游广 → 遇名士、被引荐 |

**为什么是"是"**：这是**挂机层 → 在线层唯一的反馈闭环**。挂机养的技能会在在线事件里"长出内容"，玩家感到"我练的采集真的让我多遇到山野奇遇"。若不为"是"，挂机与在线两条线各自封闭，因果 C 的技巧点就只剩出发前配置、缺少个性化。
**为什么是"只改权重"**：保持 F10d「表现随机 + 后台伪随机」原则，玩家感知仍是随机，不会觉得被系统安排。

### 3.4 时限分层与过期（F32 / F16 / F54）

| 层 | 时限 | 过期后果 |
|---|---|---|
| 基础（风土见闻） | **无限** | 不过期（纯收集，不制造压力） |
| 一般（路人/地盘/盘缠） | 4–8h | 失去机会 |
| 收集/机遇（奇遇/二选一） | 1–4h | 失去机会 |
| 战斗类 | 可积攒 | 超限失去；粮草不足→标注、玩家主动跳过（F54） |

- 容器容量 **≤10**，可养成提升；**超限 = 失去内容**（F16）。
- 失去的**只是这次机会**（红线①），已获得的属性/物品永不倒扣（红线②）。

### 3.5 ⚠ 离线处理（关键决策点，我的建议）

**问题**：事件需要交互 → 只能在线生成。那离线时，容器里未处理的事件怎么办？

**我的建议：离线时限冻结**

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（建议）** 离线冻结 | 事件只在线生成；**下线后事件不再计时**，不会因睡觉全部过期 | ✅ 不惩罚离线（挂机品类中离线是常态）<br>✅ 在线期不处理才过期 → 激励方向正确<br>✅ 符合红线①"不惩罚不操作的人" |
| B 离线继续计时 | 离线也走时限 → 睡一觉全过期 | ❌ 因"不在线"而惩罚，且是**隐性**的（玩家下线时不知情），与红线②冲突 |

> **代价与补偿**：方案 A 削弱了 F16 的部分压力 → 改用「**容量 ≤10 + 超限失去**」补：在线久不处理会溢出，压力仍在，且压力落在"在线时不处理"而非"不在线"。
> ⚠ **此项与 F16 原文存在张力，请你拍板**（见 §十 Q-E1）。

## 四、游玩体验

### 4.1 在线一天的典型节奏

```
挂机自动推进（移动→作业→结算，~8.8分钟/任务）
   ├─ 每 ~7-8 个任务 → 弹出 1 个事件（红点提示在事件列表）
   ├─ 玩家随时点开处理：阅读 → 抉择/小游戏/战斗 → 结算
   └─ 未处理者按 F32 时限倒计时；溢出/过期 → 明示"错过了什么"
```

### 4.2 两段技巧点（因果 C 的完整形态）

| 段 | 位置 | 玩家决策 | 依据 |
|---|---|---|---|
| **出发前** | 挂机层配置 | 带什么、路线怎么排、任务怎么拖、先见谁 | 因果 C 原结论 |
| **事件内** | 事件层即时 | 二选一取什么、小游戏怎么玩、要不要打、要不要跳过 | 本设计补充 |

> 两段合起来 = 挂机游戏里"技巧点"的完整分布：**配置是长线策略，事件是短线反应**。

### 4.3 离线与 highlights（F33）

- 离线**不播放**事件演出；上线后**只播 highlights**（重要事件的摘要卡片），其余折叠进旅途日志。
- 日志分类：**已完成 / 已错过（明示）/ 见闻录条目**。

### 4.4 惩罚边界（红线①②落地）

| 情况 | 处理 |
|---|---|
| 事件过期 | 进日志"错过了 XX"，**不扣任何已有资产** |
| 容器溢出 | 明示被挤掉的事件 |
| 战斗类粮草不足 | 标注，玩家主动跳过（F54），不惩罚 |
| 小游戏失败 | **仍给保底经验/少量收益**（因果 B / 太阁经验累积制），永不倒扣 |

## 五、事件内容（丰富性 + 可扩展）

### 5.1 内容分层（扩展的骨架）

| 层 | 内容 | 特性 | 扩展方式 |
|---|---|---|---|
| **L0 基础常驻池** | 通用见闻/遭遇/二选一，与地点弱相关 | 量大、可复用 | 新增 tag 即新增 |
| **L1 人物专属** | 绑定具体人物（30 人池） | 个体差异做实（因果：铺量会稀释个体） | 加人物即加一批 |
| **L2 地理专属** | 绑定城/州/设施（42 城 14 州） | 强化"到过哪里"的意义 | 加地点即加一批 |
| **L3 节庆时令** | 节气/节日（元日、上巳、寒食、端午、重阳、冬至） | 时间限定，制造回访理由 | 加节令即加一批 |
| **L4 势力线** | 魏蜀吴相关剧情事件 | 与势力好感（零和）联动 | 随剧情版本扩 |
| **L5 扩展包** | 后续版本追加的独立事件组 | 框架不变，只加数据 | 直接追加 |

> **可发现性设计**（吸取太阁"不查攻略几乎无法触发"的教训）：
> - 见闻录里**明示"未收集"条目 + 模糊提示**（如"传闻西凉有异马"），而非全隐藏；
> - 已解锁的触发条件在日志中留痕，让玩家能反推"怎么再来一次"。

### 5.2 内容量估算（v1 目标）

| 层 | 首版建议量 | 说明 |
|---|---|---|
| L0 基础池 | 80–120 条 | 保证前期不重复感 |
| L1 人物专属 | 30 人 × 3–5 条 = 90–150 | 个体差异做实 |
| L2 地理专属 | 42 城 × 2–3 条 = 84–126 | 到过的城有意义 |
| L3 节庆 | 6 节令 × 5 条 = 30 | 限定回访 |
| L4 势力线 | 3 势力 × 10 = 30 | 后期 |
| **合计** | **约 320–460 条** | 内容量主要靠 L1/L2 的"人物×地点"标签组合撑起 |

> 关键：**不是写 450 条独立文本**，而是「模板 + 标签变量」→ 同一模板在 42 城复用（如"XX 的织造/XX 的学风"），实际文本量远小于条数。**这是可扩性的核心。**

### 5.3 内容示例（三国味，每类 2 条）

| 类型 | 示例 |
|---|---|
| 风土见闻 | 「过琅琊，乡人指一陋巷曰：诸葛氏三兄弟，一仕魏、一仕吴、一在草庐」→ 政治+，见闻+ |
| 风土见闻 | 「至西平，见羌人牧马，马皆高大，胡商言'凉州大马，横行天下'」→ 武力+，见闻+ |
| 路人遭遇 | 「道遇一贩马客，言语豪迈，临别赠良马筋一束」→ 武力+/物品 |
| 旅途二选一 | 「岔口：官道多盘查但安稳；小路近半日却传闻有匪」→ 抉择 |
| 奇遇 | 「夜宿破庙，遇老者箕踞而坐，授书一卷而去，不知所之」→ 智力++/秘技（黄石公典） |
| 奇遇 | 「山中有庐，童子言'先生昼寝未醒'，候之不得」→ 政治+/见闻（卧龙典） |
| 随行家臣 | 「家臣进言：主公久在路上的，不如先屯粮于XX」→ 好感+/建议 |
| 地盘事件 | 「洛阳太学，诸生聚议朝政，有人邀你题名于卷末」→ 政治+/势力好感 |
| 盘缠波动 | 「XX 米价腾贵，行商劝你尽出所储」→ 钱粮抉择 |
| 战斗类 | 「山道遇黄巾余党劫道，索要过路钱」→ 战斗 / 可破财免灾 |

## 六、小游戏（对应事件）

### 6.1 原则（来自太阁的正反两面经验）

| 太阁经验 | 我们的做法 |
|---|---|
| ✅ **正面**：小游戏 = 给重复动作换皮（"避免枯燥刷级"） | 继承：小游戏用于**会反复发生的事件类型**（修业/切磋/制作） |
| ✅ **正面**：**经验累积制**（即使一次都没成功，攒够也升级）→ 刻意降低技巧门槛 | 继承：**失败也涨（保底）**，与 V2-5 波动外置一致 |
| ❌ **反面**：16 个小游戏 → "来回点点点让体验割裂" | **克制数量**（首版 3–4 个，上限 6–8），且**统一交互节奏** |
| ❌ **反面**：表现形式过杂 | 小游戏是**事件的可选插件**，不是独立系统；同一事件可选择"直接结算（少收益）"或"玩小游戏（多收益）" |

### 6.2 小游戏与在线的关系（拉动登录的关键）

- 小游戏**必须在线操作** → 天然是"在线专属内容"，是拉动重复登录的有效手段。
- **但必须可跳过**：事件提供「直接结算（保底收益）」与「玩小游戏（争取更高收益）」两条路 → 不卡玩家、不剥夺主体性（红线③）。

### 6.3 小游戏清单（首版建议 3–4 个，后续扩至 6–8）

> 包装：光荣历史模拟类；形态参考太阁修业小游戏 + 更广泛的休闲游戏。

| 小游戏 | 对应属性/技能 | 形态 | 参考来源 | 首版 |
|---|---|---|---|---|
| **舌战**（辩论） | 智力 / 辩才 | 词组对拼、节奏点击选词 | 太阁辩才、三国志舌战；更广：文字对战 | ✅ 建议首版 |
| **算筹**（算术） | 智力 / 政务 | 四则运算填空（限时） | 太阁算术 | ✅ 建议首版 |
| **较艺**（武艺/射） | 武力 | 固定靶、角度+力度 | 太阁弓术/铁炮；更广：弹道休闲 | ✅ 建议首版 |
| **配药**（医术） | 智力 | 药材配对 / 称重 | 太阁医术；更广：合成配平 | ✅ 建议首版 |
| 投壶（礼法/宴） | 政治 / 交游 | 投掷角度与力度 | 更广：弹道 / 体育休闲 | 后续 |
| 相马（骑马） | 武力 / 统帅 | 跨栏躲障（有惯性） | 太阁骑马 | 后续 |
| 品鉴（名物/茶） | 政治 | 辨真伪 / 记忆配对 | 太阁茶道；更广：找不同 / 记忆翻牌 | 后续 |
| 筑城（工程） | 政治 / 政务 | 堆砌 / 连连看 | 太阁建筑 | 后续 |
| 六博 / 围棋 | 智力 | 极简三连棋 | 更广：休闲棋 | 后续 |

### 6.4 难度与保底

| 项 | 规则 |
|---|---|
| 难度 | 随玩家对应属性/技能**自适应**（属性越高越难，但收益也越高） |
| 保底 | **失败仍给经验与少量收益**（太阁经验累积制）；**永不倒扣**（V2-5） |
| 收益差 | 玩小游戏（争取）> 直接结算（保底）—— 让"玩"有额外回报，但不玩也不亏 |
| 频率抑制 | 同类小游戏有冷却，避免连续弹出造成割裂（太阁教训） |

## 七、可扩展性框架

### 7.1 事件 Schema（配置列，标签驱动）

```
event:
  tag, name, type(七类+战斗), 
  title, text,                      # 文本（支持 {city}/{npc} 变量占位）
  condCity, condState, condFacility,# 地点标签
  condNpc, condFavorMin,            # 人物标签
  condSkill, condSkillLv,           # 技能标签（含 Q11 技能偏向）
  condTitle(称号), condSeason(节令),
  condItem(持有), condPrevEvent(前置),
  weightBase, weightTitle, weightSkill,   # 权重（基础/称号/技能）
  ttl(时限), coolDown(冷却), onceOnly,
  attr(主属性), attrXpMin/Max,      # 属性经验（可含随机区间）
  favorNpc, favorDelta,             # 好感
  giveItem, giveItemNum, giveMingpin,
  moneyMin/Max, foodMin/Max,
  jianwen(见闻录条目),
  optionRef(交互类型: none/binary/multi/minigame/battle/gift),
  miniGameTag(小游戏), 
  logHigh(是否进 highlights), note
```

### 7.2 扩展的三条通路

| 通路 | 加什么 | 成本 |
|---|---|---|
| **加数据** | 往 event 表追加行（模板 + 标签变量） | 最低，日常扩内容走这条 |
| **加标签维度** | 新增 cond 字段（如"天气""时辰""队伍人数"） | 中，框架层扩一次，之后持续复用 |
| **加交互类型** | 新增小游戏 / 交互插件（挂到 optionRef） | 较高，但一次投入长期复用 |

### 7.3 UGC 兜底（太阁 / San13 都有事件编辑器）

- 中期提供**简易事件编辑器**（网页端）：填文本 + 选标签 + 选结算 → 生成 event 行。
- 长期看这是内容长尾的最低成本来源（两款都验证了这条路）。
