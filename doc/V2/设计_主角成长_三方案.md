## 方案 A：熟练度直通（技能自动涨，自由点点属性）

```
做任务 ──→ 技能经验（细密，1→100）──→ 该类任务产出倍率 ↑ / 高阶产物解锁
   │
   └──→ 属性经验 ──→ 四维属性（独立成长）
                          ↑
个人等级 ──→ 自由点 ───────┘（补短板 或 强化倾向）
```

| 层 | 来源 | 粒度 | 玩家操作 |
|---|---|---|---|
| 技能 | **只靠做对应任务** | 细密（连续经验条） | ❌ 无 |
| 属性 | 做任务 **+ 自由点** | 细密 | ✅ 分配自由点 |
| 称号 | 技能/属性达标 | 阶梯 | ✅ 随时切换 |
| 官职 | 功勋 | 阶梯 | ✅ 在线 3 选 1 |

**优点**
- 最符合挂机品类：**零决策负担**，"做啥涨啥"直觉最强
- 技能纯粹是正反馈，天然规避 P7（不会想降级）
- 与 V1 已实现的"任务发属性经验"完全兼容，**改动最小**

**缺点**
- ⚠ **一次任务发两份经验**（技能 + 属性），玩家要理解两套并行数值
- 技能成长**完全没有玩家表达**——主角成长的决策点全在称号与自由点上
- 技能与属性的职责容易重叠（都在说"完成得怎样"）

---

## 方案 B：研修加速（技能自动涨，自由点点「成长速度」）

```
做任务 ──→ 技能经验（细密）──→ 产出倍率 ↑
              ↑
个人等级 ──→ 自由点 ──→ 投入「研修方向」：该技能成长速度 ×N（不直接给等级）

做任务 ──→ 属性经验 ──→ 四维属性（独立成长，不受自由点影响）
```

| 层 | 来源 | 粒度 | 玩家操作 |
|---|---|---|---|
| 技能 | 做任务（基础速度）**× 研修倍率** | 细密 | ✅ **选研修方向**（加速谁） |
| 属性 | **只靠做任务** | 细密 | ❌ 无 |
| 称号 / 官职 | 同 A | 阶梯 | ✅ |

> 🔑 自由点**不买等级，只买速度** → 技能曲线仍然是连续的（符合 P5），
> 但玩家有了**"我想先练哪个"**的表达渠道。

**优点**
- 保住"细密"，同时**给了玩家表达**——这是 A 缺的东西
- 配合 P9（洗点免费），玩家可随时改研修方向 → 与"称号可随时切换"同构，**两套切换系统呼应**
- 属性回归单一来源，不再有"两种经验"

**缺点**
- "加速"比"直接加数值"**体感弱**——玩家投入自由点，看到的反馈是斜率变化，不如数字跳变直观
- 需要额外的 UI 来解释"研修 = 加速"，教学成本高于 A
- 若研修倍率太强 → 最优解变成"永远只研修一个"，与"可练满所有技能线"(P8) 张力大

## 方案 C：派生制（技能自动涨，属性由技能派生，自由点点修正）

```
做任务 ──→ 技能经验（细密，7 个）
              ↓ 派生
         四维属性 = f(相关技能)        例：武力 = f(训练, 讨伐)｜智力 = f(读书)｜政治 = f(交易)
              ↑
个人等级 ──→ 自由点 ──→ 属性【修正偏移】（在派生值上 ±，补短板/强化倾向）
```

| 层 | 来源 | 粒度 | 玩家操作 |
|---|---|---|---|
| 技能 | **只靠做任务** | 细密 | ❌ 无 |
| 属性 | **由技能派生** + 自由点修正 | 细密 | ✅ 分配修正点 |
| 称号 / 官职 | 同 A | 阶梯 | ✅ |

**优点**
- ✅ **消除 A 的核心缺点**：不再"一次任务发两份经验"，只有技能经验一条线
- ✅ **属性有了叙事来源**：练武涨武力、读书涨智力——比"做交易莫名涨政治"更自洽
- ✅ **技能 → 属性 → 战斗/跑商门槛** 一条链贯通，主角成长是**一个**系统而不是两个
- 挂机友好（技能自动涨），且"想变强就去挂机"的动机最纯

**缺点**
- ⚠ **属性上限被技能绑定** → 不挂机就打不过；对挂机品类是好事，但要确认这是你要的
- 改动最大：V1 的属性经验体系要**整个替换**
- 自由点的空间要小心：派生值已随技能水涨船高，再叠加自由点修正，**数值容易失控**
  → 建议自由点修正做成**比例上限内的偏移**（如 ±10%），而不是无上限加点

## 三方案对比

| 维度 | A 熟练度直通 | B 研修加速 | C 派生制 |
|---|---|---|---|
| 技能来源 | 做任务（自动） | 做任务 × 研修倍率 | 做任务（自动） |
| 属性来源 | 任务 + 自由点 | 任务 | **技能派生** + 自由点修正 |
| 自由点去向 | **属性** | **技能成长速度** | **属性修正偏移** |
| 玩家表达强度 | 弱 | **中** | 中 |
| 是否符合"技能细密" | ✅ | ✅ | ✅ |
| 是否双重成长（冗余） | ⚠ **是** | ✅ 否 | ✅ 否 |
| 属性叙事自洽性 | 一般 | 一般 | ✅ **强** |
| 挂机友好度 | ✅ 最高 | ✅ 高 | ✅ 高 |
| 改动量 | **最小** | 中 | **最大** |
| 主要风险 | 两套并行数值、技能零表达 | 加速体感弱、易退化为单修 | 属性与挂机强绑定、数值易失控 |

---

## 我的推荐：**C（派生制）**，备选 A

**推荐 C 的理由**
1. 它一次性解决了"技能与属性职责重叠"这个从 V1 就存在的老问题（V1 §4.4 就警告过职责耦合）
2. 主角成长从"两条平行的经验线"收敛成**一条链**：挂机 → 技能 → 属性 → 战斗/跑商
3. 属性有了来源叙事，这对三国题材尤其重要

**但 C 有两个必须同时答应的条件**：
- 自由点修正**必须设比例上限**（建议 ±10%），否则派生 + 加点会滚雪球
- 接受"**不挂机就变弱**"——这在挂机品类里我认为是优点，但需要你确认

**备选 A 的理由**：如果这一版想**最快落地、最小改动**，A 是唯一不需要重构属性体系的方案，代价是接受"技能零表达 + 双份经验"。

**我不推荐 B 的原因**：它试图兼顾细密与表达，但"加速"的反馈太弱，且很容易退化成"永远只研修一个"，反而同时丢掉 A 的简洁和 C 的自洽。**除非**你很看重"自由点不能直接买数值"这条原则——那 B 值得再聊。
