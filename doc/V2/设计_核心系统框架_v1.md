## 一、总览

```
┌────────── 玩家意图（前置决策）──────────┐
│ 排序 / 称号切换 / 自选目标 / 势力过滤 /   │
│ 攻略对象 / 家臣派遣与编队                 │
└──────────────────┬──────────────────────┘
                   ↓
   随机任务 ──执行──→ 任务评价（保底+增量）──→ 多线结算
      ↑                                         │
   职业称号（刷出什么）                         ├→ 个人经验 → 等级 → 自由点
   个人属性（完成得怎样）                        ├→ 属性经验 → 属性
   官职（额外加成什么）                         ├→ 势力功勋 → 品级 → 官职（需上线）
                                               ├→ 事迹传播 → 人物关系
                                               └→ 资源（货品 / 金钱 / 名品 / 粮草）
                                                      │
   主角做任务 = 供给方（产货品）                       ↓
         └────────→ 货品 ──按趟消耗──→ 家臣商队 = 变现方 ──→ 金钱 ──→ 俸禄 / 培养 / 商路升级

   家臣池（3 → 15）─┬─→ 派遣商队（经济）
                    └─→ 上阵打仗（战斗）   ← ✅ V2-37：**两者可同时进行，不互斥**
                                            取舍在「带谁上阵」（上阵 5 位 vs 池子 15 人）
```

**两条贯穿全局的原则**：

| 原则 | 内容 | 已出现的场合 |
|---|---|---|
| **波动外置** | 随机性只作用于外层进阶线，不污染底层基础进度 | 任务评价（§3.2）、派遣结果（§4.2） |
| **时限外置** | 越基础越不受时限伤害，越外层越受时限约束 | 随机事件时限（§8.2） |

## 二、成长体系（四层）

### 2.1 职责分层（不可推翻）

| 层 | 职责 | 一句话 |
|---|---|---|
| **职业称号** | **刷出什么** | 决定任务池与高品质任务 / 奇遇的概率 |
| **个人属性** | **完成得怎样** | 决定基础产出与成功率 |
| **官职** | **额外加成什么** | 特定任务 / 互动事件 / 比试的额外倍率与特殊结算项 |
| **个人等级** | **总量** | 提供自由点，玩家自由分配 |

> 保证"刷什么"与"有多强"解耦——**绝不能让玩家产生"我想把等级降下来"的念头**。

### 2.2 个人等级

| 项 | 规则 |
|---|---|
| 来源 | 挂机时长 / 完成任务数量，**持续成长、速度放缓** |
| 限制 | **不受其他系统限制**（不因技能卡等级上限而卡住） |
| 产出 | **自由属性点 / 技能点**，自由分配 |
| 设计目标 | 用于**强化倾向性**或**补短板** |
| 数值约束 | ⚠ **必须保证不存在"全点满"的解**（用数值控制，非结构上限） |

### 2.3 个人属性

| 项 | 规则 |
|---|---|
| 来源 | 主要由**完成任务与事件**积累属性经验 |
| 作用 | ① 提供成长偏向；② 影响**完成任务的效果**（基础产出与成功率） |
| 与称号的区别 | 属性**不改变刷出什么**，只改变做得怎样 |

### 2.4 职业称号

| 项 | 规则 |
|---|---|
| 作用 | 解锁高品质任务；决定某类高品质任务 / 奇遇的**刷出概率** |
| 上位关系 | ✅ **包含 + 新增**（不替换） |
| 定位 | ✅ **称号不是"身份路线"，而是"已养成成果的可切换加成套装"** |
| 切换 | ✅ **随时可切换，一般无代价** |

**切换的唯一约束——高品质任务锁定"必须 X 职业完成"时**：

| 情形 | 规则 |
|---|---|
| 任务**进行中** | ⏸ **暂时不可切换** |
| 任务在**列表中未开始** | ⚠ 提示"XX 任务与职业相关，会消失"；玩家确认 → **删除该任务 → 走正常空槽补充流程** |

配套：① 锁定类任务**接取时即标示"需 X 职业"**；② 可随时切换使"称号管刷出什么"变成**实时可控**，是自动执行下玩家表达意图的又一个渠道。

### 2.5 势力好感与官职

**势力好感（功勋前置）**

| 项 | 规则 |
|---|---|
| 势力数量 | ✅ **魏 / 蜀 / 吴 3 势力** |
| 前提 | **必须先加入势力**，才会有该势力的相关任务 |
| 变化 | 增加本势力好感的任务，会**降低其他 1–2 个势力**好感 |
| 是否全满 | ❌ **不存在**（设计上零和 / 负和） |
| 格局最优解 | ✅ **1 满 + 1 中 + 1 仇**（3 势力下收敛） |
| 可见性 | ✅ 任务卡**前置明示**"此任务将降低 X 势力好感" |
| 过滤 | ✅ **必须提供过滤机制**——玩家可设定"不做会伤害 X 势力的任务" |

> 🔴 **过滤机制是必要配套，不是可选项**：自动执行下玩家没有"执行时"这个时刻。

**品级与官职**

| 项 | 规则 |
|---|---|
| 前置 | 在该势力的功勋 → 品级 |
| **品级** | ✅ **上线后才提升**；🔴 **不带独立数值加成**，只作进度条与官职前置 |
| 授予 | 结合**职业 + 属性**授予，**每次变化给 3 个自选** |
| 触发 | ✅ **必须玩家在线**（势力声望积累后的强反馈节点） |
| 作用 | 对特定任务 / 互动事件 / 比试结果有加成（**官职是加成主要载体**） |
| 官职池 | **大量复用**，不按"职业 × 属性 × 品级"全展开 |

**🔴 上线才提升必须满足的两条（否则变成惩罚不在线）**：

| # | 必要条件 |
|---|---|
| ① | **品级不带独立数值加成**（加成挂官职）→ "离线不升品级"只延后进度条，零损失 |
| ② | **离线期间功勋照常积累**，上线后**一次性补结算到对应品级**（可连升数级），绝不丢失已积累功勋 |

> 效果：上线 → 补结算品级 → 立刻触发官职 3 选 1 → **两个强反馈节点连成一个完整的「升迁时刻」**。
> 配套：UI 要能演出"连升 X 级"；品级达标需红点 / push 引导。

## 三、任务链

### 3.1 三层结构

| 层 | 内容 |
|---|---|
| ① 自选目标 | 随机任务之上，**玩家自选**的成长/资源目标（**做一件事得两份结果**），不完成不惩罚 |
| ② 随机任务 | 主循环，自动执行 |
| ③ 评价结果 | 分档评价影响产出 |

### 3.2 任务评价与「波动外置」

| 项 | 规则 |
|---|---|
| 实现 | **实际奖励 = 保底 (1×) + 增量 (0~1×)** |
| 影响范围 | **越基础的成长线影响越小，越外层的越大**：个人经验不受影响，功勋最高可翻倍 |
| UE | **浅层模糊提示 + 深层完整信息**（"不费吹灰之力" / "前途未卜"） |

> 随机只加在外层，**不污染基础进度**——这是挂机品类与"评价系统"共存的前提。

### 3.3 自选目标

| 项 | 规则 |
|---|---|
| 形态 | **常驻 + 定期更换**，需玩家**在线确认结果与换目标**（兼作拉动在线的定时器） |
| 到期不换 | ✅ **自动续期**，绝不惩罚离线 |

## 四、家臣与派遣（执行者 → 分配者）

> 决策：**不做城主、不打破体制**；用家臣拿到"执行者 → 分配者"的核心价值。

### 4.1 基本规则

| 项 | 规则 |
|---|---|
| 人物池 | ✅ 与关系人物**共用同一池**（关系达阶段 → 可招募）；**人物池总量 30 人** |
| 数量上限 | ✅ **3 → 15 人**（随统帅 / 等级等养成进度提升） |
| 维持成本 | ✅ **只要是家臣，无论是否使用都要发俸禄** |
| 派遣性质 | ✅ **长期派驻**，不是每件任务派人 |
| 产出 | 直接进资源层（**不做独立新资源**） |
| 培养 | 玩家花**额外资源定向培养**（时间机会成本 + 名品 / 信物） |
| 强度 | 家臣自身成长（打工与战斗）+ 主角技能加成 |

**🔴 上阵数量与家臣上限的比例（待确认，见 D28）**

> ⚠ **上阵数量必须明显小于家臣上限**（建议 **1/3 ~ 1/2，即 3–6 人**）。
> 若上阵数接近 15，"派遣队 vs 战斗队"的**调度冲突就消失了**，家臣池的策略深度直接归零。

### 4.2 派遣小队制与跑商（经济线）

| 要素 | 规则 |
|---|---|
| 派遣单位 | ✅ **一支小队**（不是一个人） |
| 内容 | ✅ **用物品换钱**（跑商） |
| 货品 | ✅ **消耗品**，按趟消耗；**持续供给 → 商队持续跑** |
| 门槛 | ✅ **关键项最低门槛 = 硬要求** |
| 结果 | 由 **属性（含技能加成）+ 特殊技能** 共同影响 → **达线后给额外奖励**（模糊语言预告） |
| 缺货 | ✅ **停摆即可**（产出 0、无任何损失、UI 提示"待货"） |

**吞吐量模型**：

```
主角做任务（一类任务主产物）──供给──→ 货品 ──按趟消耗──→ 家臣商队 ──→ 金钱
                                                                    │
                                                 俸禄 / 培养 / 商路升级 ←┘
```

> **主角的任务选择持续影响经济线**（做哪类任务 = 供什么货），两条线始终咬合。
> 玩家的决策变成"**我的供给够养几条商队**"——多开商队但货不够，就白付俸禄。

**跨州依赖的复用**：各州特产不同 → 去产出州取货、到高价州卖出 → **路网距离 = 商路成本**
→ **V1 的 TSP 排序操作第一次有了经济意义**（拖动排序 = 优化商路）。

### 4.3 家臣的四维（含战斗侧）

| 维度 | 作用层 |
|---|---|
| **属性** | 通用 + 压制 + 派遣门槛 |
| **战法** | 战斗层（**地形适应含在战法内**，不单列） |
| **兵种** | 战斗层 |
| **特殊技能** | **派遣层**（影响跑商结果）；✅ **与关系系统共用一张技能表** |

> ⚠ 内容量：20–30 人覆盖"兵种 × 战法"的组合空间，容易"谁也不突出"。
> 原则：**每名家臣都要有明确的强项与弱项，不做全能**。

## 五、与历史人物的关系

| 项 | 规则 |
|---|---|
| 提升方式 | ✅ **事迹传播**——完成任务 / 达成自选目标的**行为副产品**，一对多（体现武力 → 重视武力的人物都提升） |
| 玩家意图 | 可选定**攻略对象**，提高该角色相关事件的概率（**含初识事件**） |
| 偏好标签 | 每个人物 **1 主偏好 + 1 次偏好** |
| 衰减 | 关系值**不衰减**；"最新事迹"**有时效**（防刷满毕业） |
| 介绍朋友 | ✅ **限次**（防关系网指数爆炸） |
| **初识** | ✅ **随机触发**（包装成偶遇事件），不由前置选择决定 |
| 反馈 | 学技能 / 训练属性 / 介绍朋友 / 战斗加成 / **招募为家臣** |
| 比试 | 🔴 **不做实时小游戏**（属性对抗 + 简短演出） |

## 七、资源层与消耗侧

| 原则 | 内容 |
|---|---|
| 成长维度 | **只增不减**（靠多维度拉长周期） |
| 有增有减 | 集中在**资源层** |

| 层 | 资源 | 消耗场景 | 特征 |
|---|---|---|---|
| 一 | **盘缠** | 每次出行 / 任务 | 日常小额、高频 |
| 二 | **金钱 → 俸禄** | 每周期 × 家臣数量与强度 | **周期性、随规模同步放大** ← **地基** |
| 三 | **矿产 / 名品** | 家臣培养、**商路 / 商队升级**（常驻）、装备打造（排在战斗之后） | 一次性大额、可囤积 |
| 四 | **粮草** | 出战，规模相关 | 战略级 |

> 🔴 **俸禄是消耗侧能否成立的地基**：只有"随规模同步放大的消耗"才追得上产出增长。
> 🔴 **判断标准：「赚的钱刚好不够养所有人」应是常态**——玩家必须持续做取舍。

**俸禄曲线**：✅ **随人数超线性增长**（第 N 个更贵）+ **待命 / 闲置打折**。
→ 让"深池"成为**有意识的高投入选择**，同时避免弃用惩罚过重。

## 八、过程内容与随机事件

### 8.1 定位

> **既不是需要全程集中精神的在线游戏，也不是纯离线挂机。**
> **目标场景：上班摸鱼时的娱乐选项；手机端方便"收菜"（处理事件）。** → 可以存在较长的在线时间。

### 8.2 随机事件：七类清单

| 类型 | 形式 | 奖励性质 | 频率 | 内容成本 |
|---|---|---|---|---|
| **风土见闻** | 文本 + 小图（类名所卡） | 纯收集，非数值 | 高频 | 低（模板） |
| **路人遭遇** | 短暂互动 | 关系（结构不同） | 中频 | 中 |
| **旅途二选一** | 遇到事，选 A / B | 总量同、结构异 | 低频 | 中 |
| **奇遇** | 稀有、解锁性 | 解锁 / 称号线索 | 极低频 | 高 |
| **随行家臣** | 带家臣时触发对话 | 家臣关系与成长 | 中频 | 低 |
| **地盘事件** | 经过某势力地盘 | 好感微调 | 中频 | 低 |
| **盘缠波动** | 路上花钱 / 省钱 | 资源层（第一层） | 高频 | 极低 |

### 8.3 时限分层（「时限外置」）

| 事件倾向 | 持续时间 |
|---|---|
| **越偏向数值** | 越长，**可无限**，仅受随机事件总数上限约束 |
| **越偏向收集** | 越短（**1 ~ 4 小时**）→ 制造 urgency，未来可做手机 push |

**过期语义**：~~✅ 过期 = 失去选择权，不失去内容~~ → 🔴 **已被 V2-36 推翻**
✅ **现定：过期 = 失去内容**（溢出同样失去内容）。设计意图是**维持上线频度，太久不上线有惩罚**，时长交数值。
❌ **铁律：损失必须明示，严禁暗扣**（见 §10.7 配套 ②）。

### 8.4 触发与展示

| 项 | 规则 |
|---|---|
| 触发密度 | 挂在**移动格数**上（复用 V1 路网，零新增配置）→ 长途 = 内容更多 |
| 离线 | ❌ **不播放**；上线只播 **highlights** |
| 其余 | ✅ 折叠进**旅途日志**（V1 已有此功能，是天然容器） |
| 数量级 | ⚠ 130 任务/天 × 30 格 ≈ **3900 格/天** → 必须多为**可重复模板**，唯一内容靠前置选择 + 部分随机 |

### 8.5 跑路时间占比存在一个「可行区间」

| 边界 | 约束来源 |
|---|---|
| **上限** | 路上内容撑不住太久；太久则无聊 |
| **下限** | **V1 最具辨识度的操作是"拖动任务排序（TSP）"。赶路时间太少，这个操作就失去意义** |

> 91% 是临时品质数据，不是最终形态；但最优解下仍可能维持 **60% 以上**。
> **调优目标：落在区间内，而不是一味压缩。**

### 8.6 上线操作预算（结论）

| 项 | 结论 |
|---|---|
| 必要操作 | ✅ **只有处理随机事件**是必要的（换技能 / 分配点数只在"有升级/有点数"时必要；分配家臣只在获得新家臣时需要） |
| UI 指标 | **待处理事件列表 ≤ 10 条，单条处理 ≤ 30 秒** |
| 自愿观看时长 | 不设上限 |

## 九、长线定位与 V1 范围

### 9.1 长线（社交版，非 V1）

- 玩家组成势力，**从属魏蜀吴**；大地图打**势力战**，以**占领城池**为结果
- 养成自己 / 家臣 / 资源 → 在社交中取得势力首领地位，在势力战中验证战斗能力

### 9.2 V1 范围

| 项 | V1 目标 |
|---|---|
| 内容 | **只做单人养成 / 成长内容** |
| 时长 | **约前 30 日**；前期 ~2 小时/天，后期 ~20 分钟/天，**总计 15–30 小时** |
| 社交 | ❌ **不做** |
| 内容目标 | ✅ **30 天内"看完全部系统、但没练满"**（否则第 31 天只能靠无限爬升续命） |

**V1 必须为社交版预留的两个接口**：

| 接口 | 为什么必须预留 |
|---|---|
| **势力归属（魏 / 蜀 / 吴）** | 后期社交的组织骨架 |
| **战力的可量化** | 势力战要"验证战斗能力"就必须可跨玩家比较（战斗可简化，战力必须可算） |

### 9.3 排行榜：两层（属社交版）

> ✅ **战力不做排行榜**——它只是给玩家自己看的成长反馈（且必须**单调不减**，若引入损耗则用"满编战力"口径）。

| 层 | 定位 | 例子 | 特点 |
|---|---|---|---|
| ① **细分榜**（大众向） | 多而细，分得够细 → 大部分人都有榜可上 | "出战最多的郝昭""智力最高的赵云" | 参与感；榜位数量巨大 |
| ② **荣耀榜**（行为 × 实力） | 少而重，突出成就感与荣耀 | "本周蜀国势力获得功勋最多的玩家" | 含金量；周期长、有展示位与奖励 |

**三条必须预先定的规则**：① 两层榜的**周期与奖励必须显著不同**；② 细分榜要有**最低样本量门槛**；③ 榜名目是**配置表**不是动态生成。
**按势力分榜**时：各势力任务供给不同、横向不可比 → **必须在选势力时讲清口径**，否则污染势力选择决策。

> 🔑 **人物池 = 榜单生成器**：20–30 个家臣 × 3–5 个指标 ≈ **60–150 个榜位，近乎零内容成本**，
> 且比抽象战力榜有叙事质感——这是两款原作都不具备的结构优势。

### 10.5 ✅ 战斗形态已定：排位迎敌 + 瞬时判定 + 五局定档（2026-10-02）

**流程**

```
战斗事件触发（跑路随机事件：剿匪 / 练兵 / 切磋）
   ↓ 出战前
看敌方排布（可见度见 10.6）→ 从家臣池选人 → 拖动排序（我方 N 位 vs 敌方 N 位）
   ↓ ✅ 拖动时【实时预览最终结果】（V2-32，随拖动即时改变）
   ↓ 每对瞬时判定
属性 + 羁绊 + 战法 + 兵种克制 + 地形 + 相克 → 一对一结果
   ↓ 汇总
完胜(5) / 大胜(4) / 惨胜(3) / 败(≤2)
   ↓
演出层：可看的 N 场对战动画（可加速 / 可跳过 / 离线不播）
```

| 项 | 规则 |
|---|---|
| **判定时机** | ✅ **一瞬间出结果**，无过程操作 |
| **战果档次** | 赢 **5 = 完胜 / 4 = 大胜 / 3 = 惨胜 / ≤2 = 败** |
| **平局** | 仅可能出现"2 胜 2 负 + 属性完全一致"的极端情况 → ✅ **判玩家惨胜** |
| **羁绊** | ✅ **三国武将的原生羁绊**（复用人物关系网，不新增 N² 配置） |
| **上阵人数** | ✅ **初期 3 人 → 后期 5 人**；**主角可上阵**；新手阶段**赠送 2 名新手武将** |
| **离线** | ✅ **不存在离线战斗**——战斗事件**离线积攒，玩家上线后处理**；单条处理 **≤ 1 分钟** |
| **战果预览** | ✅ **布阵时实时显示最终结果（几胜几负 / 什么档位），随拖动即时改变**（V2-32） |

> 由此 D28 收敛：**上阵数量 3 → 5**（家臣上限 15 → 上阵 5，正好 1/3，与 §4.1 的比例要求吻合）。
> ⚠ 规模阶梯已进一步细化，见 **§10.12（1V1 → 3V3 → 5V5）**。

### 10.5-bis ✅ 战前实时预览（V2-32，2026-10-02 定案）

**「参谋建议」的教学定位（V2-30 补充）**

### 10.7 🔴 由此产生的一个必答题：事件积攒上限与超限处理

战斗**不在离线结算、只积攒** → 离线越久积攒越多 → 上线处理时间线性增长。

**§10.7 / D29 已定案（V2-33，2026-10-02 用户拍板）**

| 项 | 定案 |
|---|---|
| **积攒上限** | 建议复用 §8.6 的 UI 指标：**待处理列表 ≤ 10 条**（初始值） |
| **超限处理** | ✅ **超出的事件直接消失，不堆积**（推翻上一版"自动按最低档结算并进日志"） |
| **容量可成长** | ✅ **玩家可通过养成提升列表容量** → 容量本身是一条成长线 |

> | 原建议 | 用户拍板 |
> |---|---|
> | 超限 → 自动按最低档结算进日志（**不消失**） | 超限 → **消失** |

> 🔴 **两条配套（"挂机越久越亏"现在是设计意图，配套改为"让它可控、可见"）**：
>
> | # | 配套 | 说明 |
> |---|---|---|
> | ① | **实现上建议"满了就不再生成"，而不是"生成了再丢掉"** | 两者数学等价，但前者玩家看到的是"这段期间就遇到 10 件事"，后者是"我丢了 5 件事"。既然惩罚已是有意为之，**这条降级为可选**（叙述更温和，但不再是为了规避红线） |
> | ② | **容量将满 / 已错过多少必须明示**（红点 / push / 日志） | **升格为铁律**——惩罚可以存在，但**暗扣绝对不行** |

> ⚠ **性质已由用户明确（V2-36）："消失"就是消失——失去的是内容，不是选择权。**
> ✅ **同时适用于「溢出」和「过期」**（D38 关闭，推翻 §8.3「过期 = 失去选择权，不失去内容」）。
>
> | 原 §8.3 | 现 V2-36 |
> |---|---|
> | 过期 = 失去**选择权**，**不失去内容** | 过期 = **失去内容** |
>
> **设计意图（用户原话）**：**维持玩家一定频度的上线频率。太久不上线就是会有惩罚。** 具体时长交给数值控制。

> 🔴 **这是一条红线级变更，必须显式标记**：
>
> 本项目此前**从未允许"不上线 = 有损失"**（V1 决策 #6「绝不惩罚不操作的人」、§4.6 在线独占红线、V2-16 在线加成叙述）。
> V2-36 是**第一次明确引入惩罚**，且是**真实内容损失**而非叙述差异。
>
> **建议划清惩罚的边界（我的读法，待确认）**：
>
> | 层 | 是否可被惩罚 | 理由 |
> |---|---|---|
> | **机会层**（尚未领取的随机事件 / 战斗事件） | ✅ **可以**（V2-36） | 它是"机会"，机会有时效是玩家能理解的 |
> | **资产层**（金钱 / 货品 / 名品 / 功勋 / 等级经验 / 已养成维度） | ❌ **绝不可以** | 已经到手的东西被偷走，是体验最差的一类设计 |
>
> → 若这条边界成立，则 V2-20「离线功勋照常积累、上线补结算」**不受影响**（功勋是资产层）。
> → 但**战斗事件消失 = 该场战斗的功勋也不会产生** → 这是机会层的损失，可接受。

> 🔴 **配套铁律：损失必须可见。**
> 既然是真的惩罚，就不能暗扣。→ 必须**明确显示"离线期间错过了 N 个事件"**，
> 并给出可行动出口（"提升列表容量可减少错过"），与 V2-33「容量可养成提升」形成闭环。
> → **容量养成 = 惩罚的缓解阀**，这是 V2-33 与 V2-36 咬合的地方。

### 10.9 ✅ 战斗属性定位已定：三角克制 + 团队属性比（2026-10-02）

**① 三角克制（✅ 定案：乙版，2026-10-02）**

| 方式 | 对应属性 | 克 | 被克 | 直觉 |
|---|---|---|---|---|
| **用计** | 智力 | 猛攻 | 坚守 | 以计破力，诱敌深入 |
| **猛攻** | 武力 | 坚守 | 用计 | 强攻破僵持 |
| **坚守** | 统帅 | 用计 | 猛攻 | 坚壁清野，计无所施 |

> 循环：**用计 → 猛攻 → 坚守 → 用计**
>（甲版「猛攻→用计→坚守→猛攻」已被否决；乙版的"坚守克用计 = 我龟缩不出，你的计没处使"直觉最强）

**② 作战方式由武将自身决定**（不是由最高属性决定）

> 例：曹操三属性都高，但作战方式固定为**用计**。
> → 作战方式是一个**人物固有标签**，与属性数值解耦 → 人物辨识度高、配置成本低。

> ✅ **唯一例外：主角**（V2-26）
> **主角的作战方式由「称号」切换**（联动 V2-19 称号可随时切换、一般无代价）。
> → 主角成为**万能填空位**：阵容缺哪种类型，切称号就补哪种。
> → 同时让"称号"这个纯数值系统在战斗里有了**实感**（切换 = 换打法，不只是换数字）。

**③ 单对判定公式（已定稿 2026-10-02）**

```
单对判定 = 自身对应属性值 × 克制系数 × 团队优势系数
```

| 乘区 | 定案 |
|---|---|
| **自身对应属性值** | 该单位作战方式对应的那个属性（猛攻→武力 / 坚守→统帅 / 用计→智力） |
| **克制系数** ✅ | **只计算一次**：克制方 ×**1.2**，被克方 ×**1.0**。**不双向叠加**（禁止 ×1.2 与 ×0.83 同时上，否则是平方级） |
| **团队优势系数** ✅ | `clamp( 该属性 我方平均 / 敌方平均 , 1 , 2 )`<br>**只计算优势，不计算劣势** → 高的一方拿该系数，低的一方固定 ×**1.0** |

> **用户给的标准算例**（用计克猛攻）：
> ```
> 我方用计方：智力 × 1.2 × 我方智力优势
> 敌方猛攻方：武力 × 1.0 × 敌方武力优势
> ```
> **战报表层显示**（用户定）：
> `我方猛攻 +18% / 坚守 +3%　｜　敌方用计 +8%`
> → 三个属性各自独立结算，**双方可同时分别获得优势**，劣势方永远只显示 `—`（×1.0）。

> ✅ **这条设计符合 V1「不惩罚」红线**：劣势方的最低值是 1.0，**永远不会被团队乘区扣分**，
> 与 §4.6「在线独占只能是数值等价、结构不同」同源。

| 边界说明 | 内容 |
|---|---|
| 上限 2 的死区 | 硬夹断 → 平均属性领先超过 2 倍后**边际收益为 0**。5 人小队下 2 倍差距属极端情况，V1 可接受；若后续发现常见，改为软曲线（如 `1 + (r−1)/(r−1+1)`） |
| "平均"而非"总和" | 🔴 **必须确认用平均**：若对阵规模不对齐（我方 3 人 vs 敌方 5 人），用总和会直接判死我方。建议**对阵规模随我方上阵人数对齐**（3v3 → 5v5），此时二者等价，但一律取**平均**以面向未来 PvP |

> 🔑 **这条公式最漂亮的地方：非对应属性也不会浪费。**
> 曹操（用计型）的高统帅不参与自己的单对判定，但会进入**我方全军统帅池**，
> 从而**给我方所有坚守型武将带来优势**。
> → **三种属性永远都有用**，且每个家臣的每一维都有意义。

**由此形成两层博弈，且都是战前决策（零实时操作）**：

| 层 | 博弈内容 |
|---|---|
| **排位** | 我这个人对他这个人 → 利用克制 |
| **配池** | 我方的属性结构 & 类型构成 vs 敌方 → 决定团队乘区与是否会被整体克制 |

> ⚠ **平衡提醒**：统帅已决定家臣上限与上阵数量（§4.1），战斗内定位为**坚守 / 辅助**，不抢输出位。
> 🔑 **政治的出口已定（V2-27）：战后报功倍率**

### 10.9-ter 定案后的三个结构性发现（评审补充）

**发现 A：团队乘区对「排位」是中性常数 → 两层解耦，反而干净**

> 团队比的分母/分子只取决于**这一对的类型**（猛攻就比全军武力、坚守就比全军统帅），
> 与"我这个人对他这个人"无关 → **同一类型的所有对局共用同一个团队系数**。
>
> | 影响 | 说明 |
> |---|---|
> | 对排位决策 | **无影响**（全局常数，排位时可直接忽略）→ 排位只需算克制 |
> | 对配池决策 | **全部影响**（带谁上阵 → 决定三个团队系数） |
> | 对 UE | 好消息：**团队层每场战斗只需显示 3 句话**（"我方猛攻占优 +18% / 用计 −8% / 坚守 +3%"），不用每对都算 |
>
> ✅ 结论：这不是缺陷，是**两层博弈互不干扰**的保证，建议保留。

**发现 B：克制系数只能在一方生效一次，否则是平方**

> 若 猛攻克用计 = ×1.3，同时对用计方再 ×0.77，实际差 = 1.69（平方级）。
> ✅ 建议：**全局只乘一次**（只给克制方加成，不给被克方减成），系数值按"净差"标定。

**发现 C：极端阵容会让两个属性池空转 → 天然惩罚单一阵容**

> 团队池 = **全军**该属性平均（不论该单位是不是这个类型）→ 只要阵中有 ≥1 个坚守型，全员的统帅就都有用。
> 但若阵中**一个坚守型都没有**，统帅池完全不参与判定 → 全员的统帅浪费。
>
> | 面 | 效果 |
> |---|---|
> | 正面 | 与三角克制同向施压 → **鼓励混编 / 鼓励收集不同类型武将**（正好服务家臣收集体验） |
> | 负面 | 若团队系数过强，会退化成"必须每种类型带一个"的硬规则 |
>
> ✅ 建议：**不设保底规则**，靠数值把团队系数压到"锦上添花"（见 ① 的 0.8~1.25），让混编是**倾向**而非**强制**。

### 10.11 ✅ 战斗结算与败北处理（2026-10-02 定案）

**① 五局定档与奖励结构**

| 胜场 | 档位 | 定位 |
|---|---|---|
| 5 | **完胜** | 最优解 |
| 4 | **大胜** | — |
| 3 | **惨胜** | 及格线 |
| ≤2 | **败** | 无奖励（但**不倒扣**，见 ②） |

> ✅ **奖励结构沿用 V2-5「波动外置」，待战斗奖励明确后再细分**（用户已同意先按此骨架）：
> ```
> 战斗收益 = 保底（不倒扣） + 增量（0~1）×（完胜档 − 惨胜档）
> ```
> **保底 = 最坏也只是 0 收益，不会变负**（V2-28）；
> **增量 = 排位优化 → 从惨胜爬到大胜 / 完胜**。

**「参谋建议」一键排位（2026-10-02 定案）**

| 项 | 定案 |
|---|---|
| 做什么 | 一键完成排位，**贪心匹配：让尽量多的人对上自己克制的敌人** |
| 不做什么 | ❌ **不保证输赢**（只优化克制对位，不承诺档位） |
| 定位 | **降低操作成本的工具**，不是保底机制 |

> ⚠ 因此**保底不是"惨胜"**（我上一版的"保证不劣于惨胜"已被否决）。
> 用了参谋建议仍可能败 → **保底只能落在"不倒扣"上**（②）。

**② 败北处理（V2-28）**

| 项 | 定案 |
|---|---|
| 资源 | ❌ **不倒扣**、**不额外扣**（出战前已付的粮草**视为已消费**，不退还也不追加） |
| 奖励 | **没有奖励**（最低 = 0） |
| 家臣 | ❌ **无伤兵 / 无阵亡 / 无损耗**（§10.10 清单项已关闭） |
| 事件 | 正常标记为**已处理**，不返还、不重试 |

> ✅ 与 V1 决策 #8「任务必成功」一脉相承：**战斗事件可以打不赢，但永远不会亏出新损失。**

**③ ✅ 出战需粮草（V2-29，2026-10-02 用户拍板：确定要）**

| 项 | 定案 |
|---|---|
| 扣除时机 | **出战那一刻即扣除**（前置的"开战成本"，不是战后结算） |
| 可回避 | ✅ **不想打可以不出战** → 不付粮草、不触发战斗 → 因此**不是"额外损失"，是玩家主动选择的成本** |
| 败北 | ✅ **不再额外扣**（与 ② 不冲突） |

> 我上一版"战斗不额外消耗资源"的推断**已被推翻**，理由成立：
> 粮草是**明示的、可回避的、前置的**成本 → 玩家是在**知情**下选择承担风险，
> 这与"失败后被倒扣"是两回事，不触碰决策 #6 / #8。

> 🔴 **由此新增一条红线：出战前必须能预判**（否则玩家会觉得被坑）
> 粮草已付 + 败北无奖励 = **决策质量直接决定收益** → 那么"值不值得打"必须是**出战前可见**的。

> 与 §10.6 情报分层联动——**情报越完整，预判越准**（深层情报由主将能力解锁）。

> 🔴 **由此新增一条待定（D34）**：粮草不足时，已积攒的战斗事件怎么处理？
> 建议：**保留在列表、显示为"粮草不足"** → 玩家可主动跳过（不惩罚，事件消失进日志），
> ❌ **不自动消耗、不自动失败**（否则等于离线期间被扣东西，触碰决策 #6）。
