# 「闲逛」关键机制可行性分析

> 基于 2026-09-30 轮次确认的 4.1–4.5 设计说明
> 代号：闲逛　｜　第一版：纯前端网页挂机

---

## 零、结论摘要

| 条目 | 判定 | 一句话 |
|---|---|---|
| 4.1 自动移动 + 移速成长 | ✅ 方向正确 | 解决了 AFK Journey 的操作成本，但远距离任务不能用"价值"区分，要用"资源类型"区分 |
| 4.2 超载缓冲 + 完成后回城 | ✅ 正解 | 中断点对齐任务自然边界；补一条"超载减速"曲线 + 任务排队即可 |
| 4.3 低成本取消任务 | ⚠ 需要加时间维度 | 纯资源成本会导致刷到满意为止，稀有度体系崩塌 + 点击地狱 |
| 4.4 自由技能点 + 临时降级 | ⚠ 需要解耦 | "想降级"说明职责耦合错了；拆成工具（即时）+ 倾向（长期）后不需要降级系统 |
| 4.5 在线离线收益一致 + 纯前端 | ⚠ 需处理三点 | 时间可被篡改、多标签冲突、**以及最重要的：在线离线完全一致会让核心卖点变成装饰** |

## 一、4.1 自动移动与移速维度

### 肯定
- **自动寻路把操作成本降为零**，同时保留了"看得见的行走表现"——这是产品差异化的外壳，也规避了 AFK Journey 最大的失败模式（手动跑图 → 跑完就变背景板）。
- **"可接任务距离"作为移速的函数 = 内容解锁**。建议在地图上画可见的**活动半径圆环**，这是"看得见的成长"，比纯数值升级有效得多。

### 必须处理的两点

**① 远处任务不能用"更高价值"来区分，否则没有取舍。**
若远处任务收益严格更高，最优解永远是叠移速跑远门，近处资源点沦为废内容。
→ 建议用**资源类型**区分：近处出大宗基础材料（量大价低），远处出稀有材料（量小价高，多为高级配方关键配料）。近/远是**产能结构选择**，不是等级阶梯。

**② 玩家真正在优化的是收益率，要把它作为数值校核基准：**
```
净收益率 = 单次产出 ÷ (旅行时间 + 作业时间 + 摊薄回城时间)
```
所有成长线（移速、属性、技能、背包容量、坐骑）都要放进这个分式校核，防止出现"堆到某值后边际收益断崖"或"某条线明显碾压其他线"。

### 表现层建议
任务卡显示 `路程 2:30 / 作业 4:00 / 预估产出`。把物流死时间变得可读 → 挫败感下降、移速升级的正反馈变具体。

## 二、4.2 背包超载缓冲与回城节奏

### 肯定
**这是整套设计里最漂亮的一处。**中断点被对齐到任务的自然边界上，动作不打断，符合直觉，消除了"正在爽被掐断"的挫败。原报告的"背包硬打断风险"基本解除。

### 补充建议

**① 超载用"减速"而非"丢弃"，参考 Albion Online 的负重曲线：**

| 负重率 | 移动速度倍率 |
|---|---|
| ≤100% | 1.00 |
| 150% | 0.85 |
| 200%（硬上限） | 0.70，再超无法获得新物品 |

贪心多装 → 回程慢，代价与贪心程度成正比且是玩家自己选的。
**绝对不要做"超出部分丢弃"**——丢东西在挂机游戏里是重罪，会直接引发差评。

**② 必须允许任务排队**，否则每个任务后都回城，物流占比会超过 40%。
玩家可以一次排多个任务，系统按序自动执行，背包满载时自动插入一次回城。"排几个、排什么顺序"就是玩家的核心优化空间。

**③ 野外寄存点**（邮箱 / 驮兽 / 公会小屋）作为中后期解锁。天然的养成线，也能承载非数值付费点。

## 三、4.3 任务列表的取消机制

### 风险
若取消成本**只有资源**，玩家最优策略 = 反复取消直到刷出秘银。
后果：稀有度体系崩塌 + 游戏从挂机变成点击地狱（反挂机）。

### 建议：用刷新周期做天然节流，而非纯资源付费
- 任务板 3–5 个槽位，**按固定周期（约 60s）补满空槽**，而不是一次性刷一批。
- 取消一个任务 → 该槽留空 → 要等下一个刷新周期补人。
- 决策从"要不要花代价"变成"这个空窗值不值得"，资源成本可以设得很轻甚至免费。

### 必须守住的准则
**不操作应拿到约 80% 收益，精细操作最多 120%。**
挂机游戏的天条是不能惩罚不操作的人。（参考 Idleon 差评、AFK Journey 好评口吻："这游戏不绑架时间"）

## 四、4.4 自由技能点与「临时降级」——需要拆掉的耦合

### 问题诊断

**如果一个系统让玩家频繁产生"我想把自己技能等级降下来"的念头，说明技能等级承担了它不该承担的职责。**

当前耦合：技能等级同时管三件事——
1. 产出能力（正反馈）
2. 解锁门槛（正反馈）
3. **任务出现概率（专精场景下是负反馈）**

前两件是"升级=变强"，第三件导致"挖矿高→全是挖矿任务→内容窄化"。于是需要"降级"来对冲。但**玩家极度厌恶降低自己的数值**——Idleon、Melvor、Albion 都没有任何降级设计。

### 解法：不是加降级，而是职责解耦

| 维度 | 负责 | 调整成本 | 表现 |
|---|---|---|---|
| **技能等级** | 单次产出 + 解锁门槛（有多强） | 不可逆积累 | 数值成长 |
| **手持工具** | 任务出现概率（短期偏好） | 随时切换，零成本 | **角色手上拿什么看得见** |
| **专精倾向点数** | 任务出现概率（长期权重） | 可洗点，低频 | 天赋盘 / 倾向条 |

这套结构的三个好处：
1. **不需要任何降级系统**——想要少刷某类任务，换工具或改倾向即可。
2. **工具递档天然适配可视化表现**：角色手握矿镐站在地图上，与"看小人走"的核心卖点高度一致。这是 4.1 自动移动带来的独特红利，别浪费。
3. 倾向点数（就是你说的每 2 级发的自由点）保留了"一定自由度"的原始意图，但不再和"变强"冲突。

### 自由点数节奏建议
- 若技能上限 100 级、每 2 级给 1 点 → 50 点，足以把其他技能也养起来，会稀释"专精"的意义。
- 建议**投放显著慢于主技能成长**（如每 4–5 级 1 点，或"里程碑式"发放），并考虑**账号共享点数池**而非单技能给点，强化全局取舍。

### 概率模型草案
```
P(任务 i) ∝ Base_i × (1 + α·Tool_i) × (1 + β·Pref_i) × γ^连续次数 × Unlock_i
```
- `Tool_i`：手持对应工具 = 1，否则 0　（α ≈ 1.0）
- `Pref_i`：专精倾向占比　（β ≈ 0.8）
- `γ`：同类任务连续出现的降权系数，γ ≈ 0.6，下限 ≈ 0.35（防止内容饿死）
- **`Unlock_i` 为 0 表示该类型未解锁；保底每种已解锁类型保留 floor 权重，避免彻底消失**

### 稀有度设计要点
秘银替代铁矿 = **同类型任务的档位升级**，不是新类型。必须有 gate，否则经济崩坏：
- 解锁条件：技能等级 + 属性阈值 + 前置次数（如完成 20 次普通铁矿任务）
- 稀有任务应当**更久 / 更远 / 更难**，不能是白给
- 可直接搬运 Idleon 的 Efficiency Requirement 模型：每个矿有解锁效率阈值，达到后才可能在任务池中出现，超过阈值部分转化为多倍产出

## 五、4.5 在线/离线一致、MMO 终态与纯前端实现

### 5.1 第一版的三个技术问题

| 问题 | 说明 | 建议 |
|---|---|---|
| **时间篡改** | localStorage + `Date.now()`，改系统时间即可刷离线收益 | 第一版可接受（单机信任）。但必须①记录 `lastSaveAt` 并检测时间回拨，回拨则不结算；②**离线收益设上限（建议 8–12h）**，既是限损也是品类惯例。后续迁移服务端时，做过量 progress 的存档清洗会容易得多 |
| **多标签/多设备冲突** | 两个标签页互相覆盖存档 | 用 `BroadcastChannel` 抢占 active tab，非活跃标签只读并提示 |
| **后台标签节流** | 浏览器会把隐藏标签的 `rAF` 降到 ~1fps 甚至暂停，帧累加式模拟会停摆 | **逻辑必须与渲染解耦**：`位置 = f(绝对时间戳)`，渲染只做插值 |

### 5.2 ⚠ 最关键的一点：在线/离线完全一致，会让核心卖点变成纯装饰

如果在线和离线在"资源、经验、属性"上完全一致（这是正确的承诺，必须守），那么**在线的唯一价值就只剩"看"**。而"看"撑不住长期留存。

→ **解法：把在线从「产出窗口」改造成「决策窗口」。**

| | 在线 | 离线 |
|---|---|---|
| 资源 / 经验 / 属性成长 | 一致 ✅ | 一致 ✅ |
| 任务队列编排、换工具、改倾向、取消任务 | 可操作 | 按上次设定自动跑 |
| 偶发事件（路上遇到商人 / 支线） | **可选停顿处理** | 自动走默认分支（不亏进度） |
| 观察型收集（旅途见闻日志、风景图鉴） | 在线专属 | 不产出 |

关键红线：**在线独占的东西必须是非数值、非进度的**，且"不在线"的进度损失必须很小。一旦让玩家觉得"不开网页就亏了"，就背叛了挂机品类的核心承诺（AFK Journey 的口碑命脉）。

### 5.3 实现层面最重要的一条：用期望值驱动，而非逐 tick 随机

```
❌ 每秒 roll 一次：if (random() < p) 产出一份
✅ 每秒产出 = p × 单次量   （把概率写进确定性的产出期望）
```

这样做的好处是决定性的：
1. **时间粒度无关** → 在线按 1s tick、离线按 60s 大步长推进，结果期望一致 → **在线/离线天然统一，不需要写两套逻辑**
2. **离线计算 O(1)**，12 小时不需要跑 43200 次循环，秒级返回
3. 后续迁移服务端时，同一套 `tick` 函数可复用

### 5.4 为 MMO 预留的架构口
- **纯数据 state + 纯函数 `tick(state, dt) → state`**，渲染只读 state，不把 DOM 混进逻辑层。服务端未来直接跑同一个 tick。
- 任务点建议**实例化**设计（每个玩家自己的任务），但**可见性共享**（能看到别人的角色走过）。第一版纯前端可以是单机，但概念层不要锁死。
- MMO 会引入玩家经济 → 届时"背包—银行—运输"的价值会被放大，Albion Online 的物流经济是终局参考。

## 六、第一版数值骨架草案

```
移动：
  移速 v = v0 × (1 + 0.05×移速等级) × 坐骑倍率 × 负重惩罚
  旅行时间 t = 距离 d / v
  可接最远距离 d_max = f(移速等级)   → 地图上画可见半径圆环

产出：
  单次产量 = Base × (1 + 0.02×主属性) × (1 + 0.01×技能等级) × 稀有度系数 × 完成度
  完成度 = 当前属性 / 任务要求属性   （可 >1 → 多倍产出，Idleon 式）

背包：
  容量 C = C0 + 背包升级 + 坐骑/驮兽
  执行期间允许溢出至 2.0C；>2.0C 停止累积（不丢弃）
  完成后 Load > C → 强制插入回城；回程按负重-速度曲线减速
```

## 七、第一版时间尺度建议

| 环节 | 建议值 | 备注 |
|---|---|---|
| 任务刷新周期 | 45–90 s | 任务板 3–5 槽，每周期补空槽 |
| 单程移动 | 15–90 s | 近任务短；远任务长但材料稀有 |
| 单次执行 | 40–180 s | 主产出段 |
| 一轮完整任务 | 1.5–4 min | |
| **需要玩家干预的间隔** | **8–15 min** | 背包满载 / 任务池需要调整。太短反挂机，太长无反馈 |
| 离线收益上限 | 8–12 h | 品类惯例 + 防作弊限损 |

## 八、MVP 范围建议（第一版纯前端）

**必做**：地图与自动移动、任务板与刷新周期、3–5 类技能任务、背包超载 + 回城、银行、属性与技能成长、本地时间戳离线结算（含上限）、一个可见活动半径圆环。

**可以砍掉**：MMO 可见性、手持工具系统（可留接口）、倾向点数盘（可先用固定权重）、野外寄存点、观察型收集图鉴、特殊收集品。

**必须先做对的架构**：`state + tick(state, dt)` 分离、期望值驱动、离线上限。这三件事后期返工成本极高。

## 10.1 三国十三州：好消息与两个问题

### 好消息
东汉十三州正好对应你的 13 个区域：**司隶、豫州、兖州、徐州、青州、凉州、并州、冀州、幽州、扬州、荆州、益州、交州**。题材自带区域人格，不需要硬造。

| 州 | 定位 | 倾向任务 | 特产 |
|---|---|---|---|
| 司隶 | 王畿 | 采矿 / 锻造 | 铁、铜 |
| 凉州（西凉） | 边地 | 剿匪 / 养马 | 马匹、皮革 |
| 并州 | 边地 | 剿匪 / 狩猎 | 皮毛 |
| 幽州 | 北境 | 伐木 / 狩猎 | 木材、貂裘 |
| 冀州 | 粮仓 | 农耕 / 织造 | 粮、布 |
| 青州 | 海疆 | 渔盐 / 煮盐 | 盐、鱼 |
| 兖州 | 中原 | 农耕 / 锻造 | 粮、铁器 |
| 豫州 | 腹心 | 商贾 / 货运 | 通货、商货 |
| 徐州 | 淮泗 | 农耕 / 渔 | 粮、鱼 |
| 扬州 | 江南 | 打渔 / 造船 | 鱼、木材 |
| 荆州 | 江湖 | 航运 / 采药 | 船材、药材 |
| 益州 | 天府 | 织锦 / 采矿 | 蜀锦、铁矿 |
| 交州 | 南海 | 采珠 / 香料 | 珍珠、香料 |

### 问题一：缺少「驻所」概念
区域倾向 + 移动成本 → 玩家的最优解必然是"住在最想去的那州附近"。这是好玩法，但需要一个显式的**驻所/营地**去承载：
- 驻所决定"家在哪个州"，回城 = 回驻所
- 驻所可迁移（消耗资源 + 冷却），迁移是重大的战略性决策
- 驻所本身可升级（仓库容量、兼作野外寄存点）

### 问题二：没有跨州需求，13 州会退化成 1 州
这是整套区域设计能不能立住的关键。必须做出**强制的跨州依赖**，否则玩家只在一个州活动，12/13 的内容浪费，第二层移动技能也失去意义。
→ 建议：**高级配方跨州集料**。例：锻造需「铁矿（司隶）+ 木材（荆州）+ 盐（青州）」；造船需「木材（扬州）+ 蜀锦（益州）」。
这会形成漂亮的闭环：**跨州需求 → 长途移动（第二层技能有价值）→ 装载量压力（背包/坐骑）→ 回城决策（4.2）→ 运输路线规划**。四个系统串成一条链。

### 问题三：三层权重叠乘会让任务池塌缩
区域（×1.5~2）+ 手持工具（×2）+ 专精倾向（×1.8）三层叠乘后，单一任务类型的概率会冲到 60–80%，其余内容被饿死。
→ 建议：① 区域倾向控制在 ×1.5~2，**不要排他**；② 对最终概率做 **clamp（上限 ~55%）**；③ 每种已解锁任务保留 **floor 权重**；④ 保留"连续降权"机制（γ≈0.6，下限 0.35）。

---

## 10.2 两层移动技能与对数式时间曲线

### 肯定
区分"州内短途"与"跨州长途"是正确的，跨州需求存在时，第二层才有内容支撑（见 10.1 问题二）。

### 注意事项

**① 对数曲线需要有渐近下限，不能趋近于 0。**
"减少时间成本"的属性比"提升产出"更容易失控——时间趋近 0 时收益率会发散。
建议：给移动时间设下限保护，如"不得低于原始耗时的 25~30%"。
自平衡天然存在：解锁更远的任务意味着距离也在增长，速度提升不一定降低旅行时间。把这条显式写进数值表。

**② 纯对数体感会"越升越没感觉"。**
建议采用 **对数型连续成长 + 离散里程碑阶跃解锁**：
里程碑可以是传驿/官道/渡口/坐骑/舟船，每到一个等级解锁一个，并配一次可见的画面变化（驿道上多一段路、角色换匹马）。连续曲线提供抽象成长，离散里程碑提供情绪锚点。

**③ UI 不要做成"大地图 / 区域地图"两层切换。**
两层切换会打断"看着角色走"的核心表现。
建议：**单张连续地图 + 自由缩放**。角色始终在同一张地图上移动，缩放级别由玩家控制；13 州是地图上的 13 块连续区域，跨州是真实的长途位移，视觉上可以看到角色走了一段时间。

## 10.3 刷新预算的算术：供给 4 倍于消耗

已知：24h ≈ 120 任务 → **平均 12 分钟/任务**；补槽周期 3 分钟。

- 消耗速率 ≈ 0.083 个/分钟
- 补充速率 ≈ 0.33 个/分钟（每 3 分钟补 1 槽）
- **供给 ≈ 消耗的 4 倍**

结果：**任务板长期恒满**，玩家永远有得挑——这本身是好事（不惩罚挂机），但有两个后果：

1. **"选择"取代了"接受"**：玩家只会做板子上最好的任务。因此任务**不能用单一维度排序**（否则低质量任务全是废内容）。要让"最好"取决于玩家当下缺什么——远矿产高但慢、近任务快但少、稀有任务给收集品但不给资源。
2. **"主动取消"的真实价值被稀释**：如果放弃一个任务只需等它 TTL 过期，那么主动取消的真实收益就是"省掉等待时间"。建议**把取消的定价锚定在时间而非稀缺资源**：取消 = 立即腾槽 + 短 CD（~1 分钟），每日次数仅作为兜底上限。语义会清晰很多。

## 10.4 任务有效期：结论为「不需要」，但有一条前提条件

上一版我担心"不想要的任务永久占槽"导致任务板死锁。用户澄清后这个担心不成立：

- **执行全自动**（回城、存放、再出发都不用玩家管）
- **玩家最终要练满所有技能线**，因此不存在"永远没用的废任务"

→ 只要这两条成立，任务不会因为"没人做"而卡住，**不需要 TTL**。

### 但仍需守住一条前提：**只生成当前可执行的任务**

任务生成时必须过滤，否则会出现无法消费的槽位：

| 过滤项 | 说明 |
|---|---|
| 技能等级门槛 | 不生成技能等级不足的任务 |
| 属性门槛 | 不生成属性要求达不到的任务 |
| 可达距离 | 不生成超出当前活动半径的任务（受移速等级 / 已解锁州限制） |
| 工具要求 | 若引入手持工具，不生成无对应工具的任务 |

补充建议：保留取消预算的**可累积**（上限约 24 次），照顾一天只上线 2–3 次的休闲玩家。取消的定位是**资源优先级调节**（我现在急需木料，把打渔任务换掉），而不是"剔除垃圾任务"。

## 10.5 回城全自动：已确认 ✅

用户确认：**回城存放、执行任务、再出发全部是全自动行为**，不需要玩家操作。

这条确认后有两个重要推论：

1. **离线与在线完全同构**——角色在离线时同样能"完成 → 回城 → 存放 → 接下一个"，4.5 的在线离线一致承诺得以成立。
2. **物流不再是玩家的脑力负担**——玩家的注意力被释放出来，投向真正的策略层。

于是「什么全自动、什么留给玩家」彻底分清：

| 类别 | 内容 |
|---|---|
| **全自动（离线也跑）** | 接取 / 寻路 / 执行 / 满载自动回城 / 存放 / 再出发 / 事件走默认分支 |
| **玩家核心操作** | ① 拖动任务顺序，压缩赶路时间　② 调整装备与专精，改变刷新概率　③ 处理事件列表 |
| **在线专属** | NPC 二选一、武将切磋小游戏、见闻图鉴、限时州域事件（不给资源效率） |

注意「玩家核心操作」只有三项，且都不是高频点击——这是很健康的挂机操作密度。

---

## 10.6 在线事件的红线

NPC 二选一、武将切磋这是解决"在线价值"的正解，但有一条硬红线：

**在线事件可以改变「产出结构」，但不能改变「产出效率」。**

| 做法 | 判定 |
|---|---|
| 在线事件给额外资源 / 经验 / 属性 | ❌ 违背在线离线一致，会把游戏变成"必须挂网页" |
| 二选一：**总量期望相同，结构不同**（100 铁 vs 50 铁 + 1 稀有材料） | ✅ 离线不吃亏，在线有按需优化空间 |
| 武将切磋给好感度 / 图鉴 / 解锁内容 | ✅ 非数值非进度资源 |
| 离线时事件自动走默认分支 | ✅ 且**默认分支期望 ≈ 分支平均值**，不能明显更差 |

**事件永不过期，只积累。** 用户确认：事件不会过期，堆积到上限后停止生成新的。✅ 这是正确的处理——不会因为离开而损失任何东西，符合挂机品类"不绑架时间"的承诺。

三点补充建议：
1. **上限值建议 8–12**（不要太小）。太小会让休闲玩家长期处于"满载停生成"状态，在不知不觉中错过内容。
2. **满载前必须在界面上明显提示**（徽标 + 首次满载时的一次性说明），避免玩家不知情地损失内容生成机会。
3. **支持"一键全部按默认处理"**，把每次上线的处理时长压到几分钟。参考 AFK Journey 的好评命脉："五分钟清完日常"。

# 十一、第三轮结论（2026-10-01 晚）

> 用户补充：全自动回城与执行；取消任务是低频操作；玩家核心操作三项；任务不需要有效期；
> 强制跨州依赖（顶级配方需七八州独占材料）；第一版单角色可练所有技能线；事件只积累不过期。

## 11.1 设计闭环的确认

三条澄清组合后，整套设计形成了自洽闭环：

```
单角色要练满所有技能线
      ↓
顶级配方需要七八个州的独占材料      ← 强制跨州需求
      ↓
跨州需要第二层移速 + 装载量 + 回城节奏  ← 移速 / 背包 / 坐骑成为真实需求
      ↓
多种任务都能产出价值 → 没有"废任务"    ← 因此不需要 TTL，也不怕随机刷出
      ↓
玩家的乐趣从"做不做"转向"怎么做更快"   ← 核心操作只剩三项
```

其中"把物流全自动 + 强制跨州集料"是关键组合：**它让运输物流从打扰变成了策略层**，这是整套设计与一般挂机游戏拉开差距的地方。

## 11.2 玩家核心操作三项的落地要点

### ① 拖动任务顺序（路线优化）
这是本作**最具辨识度的操作**，本质是小型 TSP（旅行商问题）。三个落地前提：
- **任务点应固定在地图上**（矿区 / 渔港 / 林场 / 匪寨），而不是随机坐标。固定点位玩家才记得住地图，路线优化才有**可学习的策略深度**；随机坐标会让排序退化成掷骰子。
- **拖动时实时显示"总耗时 / 总收益"**，让优化成果可见。
- **必须提供"一键最优排序"**（贪心即可），手动拖动作为进阶优化。否则每次上线手动排 5–8 个格子很快会变成负担。
- **队列容量建议做成成长线**：初期 3 个，可成长至 8–10 个。容量越大，路由优化的策略空间越大，这是很好的养成投放点。

### ② 调整装备与专精（概率调节）
- 按 §四 的解耦方案：技能等级管"有多强"，装备 / 工具管短期偏好，倾向点数管长期权重。
- **强烈建议洗点极低代价甚至免费**。既然目标是练满所有技能线，倾向只是"节奏工具"而非"永久路线"，锁死它只会带来选错焦虑。可以做成"每次升级赠送一次免费调整"。

### ③ 处理事件列表
- 见 §10.6，永不过期 + 上限 8–12 + 满载提示 + 一键默认。
