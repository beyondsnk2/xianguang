## 〇、如何验收每一次改动

- 改 `src/` 后**必须**跑 `npm run check`（先 `_bundle` 再 node 执行）。只跑 `tsc` 不算数。
- 命令：
  - `npm run typecheck` → `tsc --noEmit`
  - `npm run check [配置集@版本]` → 全量自检：路网 Dijkstra 基准 + cityLink 对拍 + 24h 模拟 + 配置告警
  - `npm run calib` → 成长校准（1/2/3/7/14/30/60/90/120 天）：技能档位 → 品质窗口 → 最高产出品质 → **B 缺料率**
  - `npm run sim [角色数[,小时数]] [输出路径]` → 批量模拟导出 xlsx（默认 100 角色 × 24h → `out/sim_100char_24h.xlsx`）
  - `npm run check:v1` / `check:v2` → 回跑旧版（**V4 改完必须验证 V1/V2 旧配置不崩**：无 price 表 → 价格回退 0 且市集禁用）
- 🔴 **改动前先录基线**：跑一次 `npm run check` + `npm run calib`，把结果贴到 §六「数值基线」表（本文档底部的表格留空待填）。**V4 会新增 RNG 调用（商队/市集波动），序列会平移，基线必然变化** —— 变化是允许的，但要能解释。
- 存档：`SAVE_VERSION` V4 升到 **3**。版本不符直接弃档重开，不做迁移（项目约定）。

### 1.1 与 V4 直接相关的现状要点

- `GameState` **没有** 金钱/粮草/商队字段；`GameConfig` **没有** 价格/供需/商队表。
- `ItemDef`：`cat`（材料/稀有/成品/名品）、`subCat`、`tier`（**名品为 NaN**，`tierRaw='名品'`）、`stack`、`source`。**无价格列**。
- `produce.ts::settleCraft`（B 类）：按 `recipeByResult[mainOutput]` 反查配方 → `cycles = min(rollRange(getItemNum), floor(matOwn/matPer), floor(rareOwn/rarePer))` → **稀有按件消耗**（`rarePer * cycles`）。缺料计 `stats.starvedTasks`。
  **2026-10-08 已改为四项投入**（基础料 / 基础稀有 / 额外料 / 额外稀有），见 §2.4。
- `produce.ts::settleSocial`（C 类）：`q >= RARE_MIN_QUALITY(4)` 时产稀有（随机 subCat 之一）。
  ~~每次固定 1 个~~ → **2026-10-08 改为按品质 1~3 个**（`rareCountByQuality`），见 §2.4。
- `tick.ts`：主循环 `while (dt > 1e-9)`，事件数上限 `MAX_TICK_EVENTS`。**商队推进要放在 while 外面单独处理 dt**，不要塞进循环。
- ~~`ATTR_LEAD_CHANCE`~~ → **已改名 `DEED_LEAD_CHANCE`（R1 完成）**，仍被 `generals.ts::propagateDeed` 复用（判断本次事迹是否展示统帅）。它是武将关系常量，不是属性桥残留。
- `simulate()`（自检/校准用）默认 `autoEvents: true`：会生成随机事件并代玩家点掉。**关掉它四维就没有来源**（属性只由事件给），校准出来的评价分布是失真的。
- 左菜单 DOM id：`menu-bag / menu-char / menu-rel / menu-event`（在 `index.html`），新增菜单需改 `index.html`。

### 2.4 制造物结构重构（2026-10-08，替代旧「35 族 × 9 品质」）

**配置侧（`gen_v2_content.py` 全量重写）**

- 结构函数：`seg_of(q)=(q-1)//3+1`、`rank_of(q)=(q-1)%3+1`、`qname()` → 全名格式 `{名}·{段名}{阶名}`
- `PRODUCT_FAMILIES`：3 技能 ×（初段 2 / 中段 4 / 上段 4）= **30 物品族**，段内三阶 → **90 成品**
- `A_MATS`：**按段固定材料类型**（铁/铜/玉、草药/异草/灵芝、兽皮/野味/兽骨）→ 3 × 3 段 × 3 阶 = 27
- `C_RARES`：每 C 技能 2 种，**每种覆盖 q4-9 全部 6 个品质** → 36 item
  （⚠ 不可按段切分：后期 C 任务全在 q7-9，抽到中段稀有时 `sub_q` 不存在 → 该次产出作废）
- 额外层组合：4 族时 `(其他A[idx%2], 其他C[idx//2])` 取 2×2 全组合；2 族时取对角 `(oa[idx], oc[idx])`
- 三城互异用 `assert` 兜底（B 城 + 配对 C 城 ×2，三城集合两两不相交）
- `gen_v4_econ.py` 成品定价纳入额外层：`(料1×n1 + 稀有1 + 料2×n2 + 稀有2) × 1.5`

**代码侧**

| 文件 | 改动 |
|---|---|
| `types.ts` | `RecipeDef` +`needItem2`/`needItem2Num`/`needRare2`；`Task` +`outputTag?`（B 类锁定制造目标） |
| `parse.ts` | 读 recipe 三列新字段（旧配置无此列 → 空，不参与消耗） |
| `taskGen.ts` | 新增 `unlockedFams()`——返回已解锁族数组，**`null` = 老配置 → 不启用新逻辑**（兼容关键）；`genTask` 用 `pickOne` 锁定 `outputTag`；`pickTaskDef` 过滤 B 类无解锁族的候选 |
| `produce.ts` | `settleOutput` 加第 5 参 `task?`；`settleCraft` 改**基础层门槛 + 额外层加成**（见下）；`settleSocial` 稀有产出按 `rareCountByQuality(q)`（1~3），且 `weightedPick` **先过滤该 q 不存在的 subCat** |
| `tick.ts` | `settleOutput(..., task)` 传任务实例 |

| `event.ts` | `randomItemTag` 堵漏洞：成品只从**已解锁**（天生会 or 已持图）里抽，避免没图白拿神兵 |

**两个实现边界**

1. **图纸门槛**：`BLUEPRINT_MIN_QUALITY` 下移到 4（制造侧 q4 起全要图，掉图却从 q7 开始会让中段长期空转）；
   `settleSocial` 由 `find(第一张)` 改为「该 C 技能**未拥有**的图纸里 `pickOne`」（每 C 技能 8 张）
2. **无解锁族兜底**：`pickTaskDef` 中 B 类若候选全被图纸卡住 → **回退该技能初段（q≤3，天生会）**；
   连初段都没有才 `return null`

**`settleCraft` 的开工判定（2026-10-08 定稿）**

```
基础料 + 基础稀有 齐备 → 开造（缺任一项 = 停产，计 starvedMat / starvedRare）
cycles = min(rolled, ⌊matOwn/matPer⌋, ⌊rareOwn/rarePer⌋)
额外层**不是门槛**：齐备 → bonus = min(cycles × EXTRA_BONUS_RATIO, ⌊mat2Own/mat2Per⌋, ⌊rare2Own/rare2Per⌋)，消耗并额外产出
                    缺了 → bonus = 0，不消耗、不停产
产出 = resultNum × (cycles + bonus)
```

⚠ 曾做成「四项齐备才开造」，实测缺料率冲到 51% —— 两个稀有**独立稀缺、缺料率按乘法叠加**
（各约 0.7 → 0.7² ≈ 0.5）。改为加成后停产只由基础层决定。`EXTRA_BONUS_RATIO`（默认 1.0）可手调。

### 2.5 校准实测（120d，结构重构后）

**✅ 最终值（2026-10-08 定稿）**

| 周期   | 完成任务/天 | 缺料率            | 稀 28% / 料 0% |
| ---- | ------ | -------------- | ------------- |

**三轮修复的演进**

| | ① 重构初版 | ② 抬 C 产出 + 稀有全品质 | ③ 额外层改加成 |
|---|---|---|---|
| 120d 缺料率 | **75%** | **51%** | **29%** |
| 供需比 | 0.12~0.21（两极分化） | 0.84~0.93 | — |

三轮各自修掉的根因：

1. **稀有按段切分 → 产出作废**：后期 C 任务全在 q7-9，抽到中段稀有时 `sub_q` 不存在 → 该次产出直接作废
   （中段供需 0.08、上段 0.82）。改为每种覆盖 q4-9 全部品质。
2. **总量不足**：额外层让每笔制造多要一个稀有，C 侧恒产 1 撑不住。改为 `rareCountByQuality`（1~3）。
3. **额外层当门槛 → 缺料率乘法叠加**：两个稀有独立稀缺，各约 0.7 有货 → 0.7² ≈ 0.5。
   改为加成后，停产只由基础层决定（见 §2.4）。

🔴 **仍存在的结构性约束（可接受）**：额外层要 **(q−1) 阶**的料，而后期品质窗口恒为 q7-9，
C 任务只产 q7-9 的稀有 → **q7 制造所需的 q6 稀有无人生产**。
因为额外层已改为加成（缺了照造），这只影响「能否拿到加成」，不再导致停产。
q−1 阶材料同理，但 A 类产出量大（8~16 件/次）且有囤积，所以材料侧完全不缺（料 0%）。

若后续要让加成也能稳定吃到，三个方向：
① 继续抬 C 产出（`rareCountByQuality` 实测阶梯：恒1→75% / 1~3→51% / 2~5→31%，边际递减）
② 额外层的**稀有**改为同阶 q（只材料保持 q−1），供给与需求天然对齐，但偏离「Q6 要 Q5」原设计
③ C 类产出同时给本阶 + 低一阶的稀有（保留 q−1 语义，但需改产出结构）

> ❌ **不做「仓库超限自动折现」**：玩家无法预判哪些物品会被折现，逐个物品设上限操作成本太高。

> 工钱本身就是对当次产出的折算，**不绕过产出链**（原字面是在「有市集」的前提下写的，本版市集已后置）。

- ✅ **实现落地**：`constants.ts`（`INIT_MONEY=500` / `WAGE_RATIO=1.0` / `BOUNTY_MULT=10`）、`tick.ts`（`settleTask` 工钱）、`event.ts`（5 个事件加 `money` 选项 + `resolveEvent` 赏金结算）、`state.ts` / `types.ts`（`money` / `moneyEarnedWage` / `moneyEarnedBounty` 统计）、`selfcheck.ts` / `calib.ts` / `check.ts`（统计与展示）。`tsc` 0 报错，`npm run check` 全绿。
- 🔴 **校准口径坑（已修，2026-10-07）**：事件计时原本用真实 `Date.now()` 做「每日上限 / 冷却 / TTL」，但快速校准 sim 里 `Date.now()` 不随模拟时间推进，导致 `EVENT_DAILY_CAP=9999` 在首次真实日内耗尽、之后整个长周期 sim 不再生成事件（赏金 / 属性在 ~60 模拟天处**冻结**）。改为事件计时跟随 `state.simNow`（随 tick 的 dt 推进）：真实游玩时 `simNow` 仍贴合真实时间（行为不变），校准时按模拟日正确重置上限。修复后长周期数字可信（见 §6.1）。
- 📊 **实测工钱:赏金（随机选选项的模拟器上界，BOUNTY_MULT=15）**：24h ≈ 92:8 / 30d 83:17 / 60d 73:27 / 120d **70:30**。早期赏金事件少（占比低），长周期精确贴合设计 7:3；偏离更小是因为模拟器对「钱选项」均匀随机（真实玩家会策略性多选钱、且后期大额赏金占比更高）。`BOUNTY_MULT` 由 10→15（2026-10-07）即把校准口径抬到 30%，本版临时调平、后续重做紧张经济时整体回调。

**E0a 任务工钱**

- 触发点：`tick.ts::settleTask`，与物品奖励**同一次结算**、写进同一条事件流；**不新增 UI**
- 口径：**统一按 `price[材料|tier]`，与任务所属 A/B/C 类别无关**。
  （B 类产物是成品、C 类是稀有，若按各自实际产物估价会导致「B/C 工钱远高于 A」；工钱的语义是**跑腿费**，只认活儿的品质）
- 公式：`wage = round(price[材料|tier] × WAGE_RATIO)` ；✅ **Q-V4-11 已定：`WAGE_RATIO = 1.0`**（候选③「锚定基准价」，推导见产品文档 §4.4）
- 🔴 **校准顺序：R5（Q21 重配）→ E3（补货）→ 最后调 `WAGE_RATIO`**。
  Q21 把缺料率从 60% 压到 20% 后，补货需求只剩约 4 成，收支比会整体上升（q7 约 0.52 → 1.3），
  届时须回调系数，否则钱过剩。**E3 的系数不能先于 R5 定**。

**E0b 事件赏金**

- 只给**部分**事件加钱选项（委托 / 悬赏 / 馈赠类），不是全量事件
- 🔴 **同一事件至多一个选项给钱**（红线⑤ 附则）：另一个选项给属性 / 物品 / 好感 → 选钱 = 机会成本，天然限制金钱流入
- 单次：`bounty = round(price[材料|tier] × BOUNTY_MULT)`，`BOUNTY_MULT` 初值 **10**（≈ 10 倍单笔工钱，保证「单次明显」）
- 实现：`event.ts` 的 reward 结构需支持「钱」类型选项（先查现有 60 条事件是否已有 money 字段，没有则扩）

- **涉及**：`constants.ts`（`INIT_MONEY` / `WAGE_RATIO` / `BOUNTY_MULT`）、`tick.ts`（工钱）、`event.ts`（赏金）、`state.ts`（`money`）、`config` 表

  4. **成品**：`price = (材料价 × needItem1Num + 稀有价 × 1) × CRAFT_MARKUP`

  5. **名品**：`price = 0`、`sellable = 0`（⚠ `tier` 是字符串「名品」，必须走 `tierRaw === '名品'` 分支，否则 NaN 污染）

  - `basePrice(cfg, itemTag): number`（读 `item.price`，缺失回落到 `priceByKey[cat|tier]`）

  - `restockForCraft(state, cfg, recipe, cityTag, matTag, deficit): {bought: number; spent: number}` —— **核心**：
    ① 只接受 `cat === '材料'`（红线⑦；稀有直接返回 `{bought:0, spent:0}`）
    ② 买的是**同品质材料**（`tier === 成品 quality`，守红线④ 投喂下界）
    ③ 受 `dailyBuyLimit` 与 `money` 双重上限：`bought = min(deficit, limitLeft, floor(money / unitPrice))`
    ④ 扣钱、加库存、写事件流一行、累加 `stats.moneySpent / stats.restockCount`
    ⑤ 金钱永不为负（扣减前校验）
- **调用点**：`produce.ts::settleCraft` 里算出 `cycles` 后，若 `cycles < 期望` 且**缺的是材料** → 调 `restockForCraft` → 用补到的量重算 `cycles`。
  ⚠ 稀有缺口**不调**（红线⑦），直接走原 `starvedTasks` 分支。
- **不做的**：卖货、限购 UI、价格波动（F78 随市集后置）、商队、粮草。
- **验收**：
  - 缺材料且钱够 → 自动补齐，制造满额产出，事件流可见，金钱正确扣减

  - 钱不够 → 补部分，剩余仍缺料，金钱不为负
  - 超限购 → 只补到上限
  - `calib` 里 `restockCount` 有数、`starvedRate` **下降**（只降材料部分，稀有部分不变）

### 5.2 坑

- **RNG 序列平移**：E3 会在 `settleCraft` 里引入新分支（不掷骰则不平移；若引入掷骰）会整体平移随机序列 → `npm run check` 的任务数/评价分布等基线数字会变。**先录旧基线再改**，改动后能解释差异即可。
- 🔴 **缺料必须分「缺材料 / 缺稀有」两个计数**（`starvedMat` / `starvedRare`）：F72 只补材料（红线⑦），混在一起就看不出补货效果，红线⑦ 也没法验收。
- ~~**`MAX_TICK_EVENTS`**：商队推进必须放在 `tick()` 的 while 之外~~ ➖ 商队后置 V5（该约束 V5 实现时仍成立）。
- **~~`ATTR_LEAD_CHANCE` 不能删~~ → 已改名 `DEED_LEAD_CHANCE`（R1 已完成）**：`generals.ts::propagateDeed` 用它判断本次事迹是否展示统帅。它是**武将关系**的常量，不是属性桥残留，勿再当桥删。
- **`npm run calib` 的基线必须先确认跑的是哪版配置**：R11 之前它硬编码 V3，与 `check` 不同源。看输出第一行的「版本：V?」。
- **模拟器是否跑事件决定校准成不成立**：`simulate()` 默认 `autoEvents: true`。关掉它四维会断供（属性只由事件给），评价塌成佳+绝 ≈ 0 —— 那是测量失真，不是配置问题。
- **名品 `tier` 是 NaN**：价格表与市值估算必须走 `tierRaw === '名品'` 分支，否则 NaN 污染金钱。
- **旧配置降级**：V1/V2 无 `price`/`cityDemand` → 自动补货禁用（买价 0 → 按原缺料处理），不得崩（`check:v1` 验证）。
- **补货只从仓库视角判定**：B 类制造吃的是「背包 + 仓库」总量，补货买来的料直接进**背包**（避免制造完还要回城取）。
- ~~**背包 vs 仓库**：商队取货只从仓库取~~ ➖ 后置。
- ~~**离线与商队**：商队进度随 dt 推进……~~ ➖ 后置。
- **自动补货离线也要生效**（红线 3：在线/离线同一套推进），但**不写事件流的逐条提示**（离线回来一次性汇总一行，否则刷屏）。
- ~~**index.html 菜单**：新增 `menu-market` / `menu-caravan`~~ ➖ 本版无市集/商队界面，**不需要新菜单**；补货记录挂在事件流里。
