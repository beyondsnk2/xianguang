# 挂机游戏竞品分析（大地图 + 随机任务 + 背包/银行 + 技能/属性耦合）

> 分析日期：2026-09-30　｜　范围：PC / 网页 / 手机　｜　第一版聚焦 PC + 网页

---

## 一、诉求特征拆解

把你的设计拆成 5 条可检索的特征，用来做竞品匹配：

| 编号 | 特征 | 说明 |
|---|---|---|
| F1 | 大地图真实移动 | 角色在地图上缓慢移动是**可见的核心表现**，不是过场 |
| F2 | 随机任务驱动 | 系统随机刷任务，任务决定"去哪儿"，玩家不直接指定行为 |
| F3 | 背包容量 → 银行往返 | 背包满了必须中断当前循环去银行，构成节奏约束 |
| F4 | 技能 → 任务生成 | 技能影响任务**出现概率**与**稀有度**（挖矿高→更高概率刷出秘银） |
| F5 | 属性 → 任务产出 | 力量等属性影响**完成度/产量**，与技能分离 |

**一句话结论：F1+F2+F3 三件套，市面上没有任何一款热门产品同时具备。** 最接近的是 Idleon（有 F1、F3、F4/F5 的雏形，但 F2 缺失）和 Melvor（有 F4/F5 的完整数值骨架，但完全放弃 F1）。

### C 层｜设计源头（不直接竞品，但机制是祖宗）

| 产品 | 借鉴点 |
|---|---|
| **RuneScape / OSRS** | "走路 + 技能 + 银行"这套三角的原型。Melvor、Idleon 都直系出自它。 |
| **Albion Online** | **背包容量约束设计的最佳参考**：物品有重量，基础负重 50kg，背包/坐骑（马/骡/牛）扩容；**超重不是"禁止"，而是移动速度乘数递减**（100%→1.0，130%→0.8，160%→0.5，200%→0.15，800%→0）。城市银行分区存放、跨城运输有风险与价差。→ 把"容量上限"从**硬打断**改造成**速度-容量权衡曲线**，是 F3 的关键解法。 |

## 四、五条关键设计启示（含风险）

**1. 移动是纯时间成本，玩家第一诉求会是"跳过移动"。**
AFK Journey 的教训最直接：大地图做出来后，玩家跑完就再也不打开。Idleon 的应对是给传送/瞬移。
→ 建议：让移动本身产生产出（路上事件、探索值、移动经验、风景/见闻收集），或把"提速/传送/坐骑"包装成**成长解锁奖励**——把"消除成本"变成"成长目标"，而不是一开始就给。

**2. 背包满 = 强制打断，在挂机品类里是负体验。**
挂机品类的核心承诺是"不用管"。硬打断天然与之冲突。
→ 建议：参考 Albion 的**负重-速度曲线**替代硬上限（"多装还是快跑"成为决策），并把扩容拆成养成线：背包升级、坐骑/驮兽、银行分级、远程邮寄/委托。第一版可以先做硬上限，但必须把上限设得足够宽松并留扩容接口。

**3. 随机任务 + 技能控制稀有度，最优解会退化成"干等"。**
"挂机"品类里，"等待"是最差的体验（AFKJ 玩家戏称"最大氪点是睡觉"）。如果高技能玩家的最优策略是等刷出秘银任务，游戏就死了。
→ 建议：必须给玩家**主动出口**——任务板（同时挂 3 个任务可选其一）、刷新券/冷却刷新、拒绝任务、多任务队列自动接取。让"刷"变成可操作资源，而非纯运气。

**4. F4 会造成内容窄化：挖矿技能高 → 只刷挖矿任务 → 其他内容被饿死。**
→ 建议：任务池用**加权 + 冷却 + 保底轮转**（同一技能连续刷 2 次后降权）；引入**跨技能复合任务**（"锻造 × 采矿：需要铁矿 + 5 级锻造"），强制技能协同；稀有度不只提升奖励，也要提升**难度/时长/前置**，避免高技能无脑滚雪球。

**5. "在线可视化表演"是卖点，但和"离线结算"存在结构性矛盾。**
你的核心差异化是"看角色在地图上慢慢走"——这要求在线。但挂机玩家要求离线也涨。
→ 建议：离线按"自动接取最近任务"结算但**收益打折**（如 60%），在线观看给满额 + 偶发观赏事件。折扣率是第一版最需要调的数值，调不好就变成"必须挂网页"，与挂机品类的"不绑架时间"承诺冲突。

## 五、参考优先级建议

1. **Legends of Idleon** — 抄它的"地图移动 + 技能点 + 属性→效率 + 银行/负重"结构（**效率门槛模型**：每个矿有 Efficiency Requirement，低于阈值只有概率获得，≥100% 必得且超额转化为多倍产出——这个模型可以直接搬来做你的"力量→矿石数量"曲线）。
2. **Melvor Idle** — 抄它的长线骨架：20+ 技能的交互网络、精通系统、宠物/收集品、离线进度与云存档。
3. **Albion Online** — 只抄它的负重曲线与银行分区，用来解决 F3 的手感问题。
4. **Adventure Land** — 验证"网页端跑 2D 地图 + 多角色 + 银行"的技术可行性与性能边界。
5. **AFK Journey / 放置江湖** — 作为反面教材（大地图一次性化）与正面参考（随机奇遇的内容组织）。
