> 建立日期：2026-10-01　｜　适用项目：闲逛（三国挂机）

---

## 一、目录结构

```
sanWalk/
├── config/     所有配置文件（xlsx / json / …）
└── doc/        所有文档（md）
```

根目录不放文档、不放配置。

---

## 二、文件版本规则

- 文件名格式：`{配置集名}_V{版本号}.xlsx`，例：`firstShow_V1.xlsx`、`firstShow_V2.xlsx`
- `V1` 中的 `1` 即版本号，正整数，无补零
- **同一目录下，同名（同一配置集）的文件只读取版本号最大的那个，其余全部忽略**
- 版本号比较按数值而非字符串（`V10` > `V9`）

例：目录下同时存在 `firstShow_V1.xlsx` / `firstShow_V2.xlsx` / `firstShow_V10.xlsx` → 只读 `firstShow_V10.xlsx`。

---

## 三、Excel 读取规则

1. **忽略所有以 `$` 开头的标签（工作表）**
   → 用于放草稿、示意图、临时数据。`$caogao`、`$map` 即属此类。

2. **每个标签内，只读取第 1 行有字段名的列**
   → 第 1 行空表头的列整列跳过。用于在同一张表里随手做备注、画矩阵、留空白列而不污染数据。

3. 第 1 行有字段名、但下方全空的列：随规则 2 读入但内容为空（见"待确认 Q1"）。

4. **扫描目录时跳过以 `~$` 开头的文件**（Excel 打开时生成的临时锁文件），否则会因文件被占用而读取失败。

5. 跳过的典型情况（V1 首轮实测）：
   - `city` 表右侧 Q~AY 列的 1~35 编号矩阵（无表头）→ 忽略
   - 已随后续修订补上表头，不再被忽略：`task.name`、`city.name`

### `mapRoad` 字段语义（现行方案）

由 `$map` 页签 **B2:AJ31**（36×30）中值为 `1` 的格子**逐格生成**，不压缩成线段。

| 字段 | 语义 |
|---|---|
| `tag` | 道路格 id，`1`–`80`，按「先 Y 后 X」排序（在表中从上到下即地图上从上到下） |
| `name` | 固定 `road` |
| `position` | 单格坐标 `x:y` |
| `roadType` | **预留扩展列**，当前全为 `plain`。将来填 `mountain` / `forest` / `official`（官道）等，用于按格设置移动成本 |

**路网构建规则（边不落表，由坐标推导）：**

1. 节点 = `mapNode` 的 16 个设施/州府 + `mapRoad` 的 80 个道路格 = **96 点**
2. 设施占多格（州府 2×2）时**合并为一个超节点**，内部移动成本 0
3. 两节点**四邻域相邻即连边**，边权 = 1 格（`roadType` 启用后改为按格成本）
4. 任意两点距离 = **Dijkstra 最短路**，禁用曼哈顿估算

> 已验证：该方式与旧的 `$mapRoute`（压缩边表）在 120 对设施两两最短路上**结果完全一致**。

**路网基准值（实现对拍用，Dijkstra 真值）：**

| 起点 → 终点 | 格数 |
|---|---|
| 兵营/上庸 → 农田/上庸（同城） | 6 |
| 兵营/上庸 → 矿山/新野 | 22 |
| 州府上庸 → 州府襄阳 | 31 |
| 兵营/上庸 → 矿山/襄阳 | 37 |
| 酒馆/新野 → 矿山/襄阳（最远） | 55 |

同城平均 4.42 格 / 跨州平均 37.33 格 / 全部平均 **30.75 格**，最大 55，全图连通。

> **新野是有意保留的偏远州**（2026-10-01 决策：不补路）。它只有一条出路回上庸，
> 构成地图的距离梯度，是「远州高价值 / 长途物流成本」设计的载体。

### ⚠ 路网近乎树：影响「路线选择」类玩法

96 点 97 边 → **独立环数 = 2**，任意两点路径基本唯一。
将来想做「官道长而安全 / 捷径快而危险」的选择，必须先让路网成环（多在 `$map` 上画路）。

### ⚠ Q1：`mapNode` 仍有重复表头
第 1 行为 `['tag', 'tag', 'name', 'position', 'belong']`，A 列表头也是 `tag` 但整列为空。
若加载器按表头建字典，会出现**同名字段互相覆盖或解析报错**。
→ 建议：删掉 A 列的表头文字（留空即被规则自动忽略）。

### ⚠ Q7：分隔符是否同义
| 出现位置 | 写法 | 分隔符 |
|---|---|---|
| `task.getItemNum` | `5,7` / `2,4` | 逗号 |
| `task.getAttrXpNum` | `10;20` | 分号 |
| `config.initForce` 等 | `2;5` | 分号 |

→ 请确认：逗号与分号**是否都表示"区间随机"**？还是分号代表别的意思（如多档位、等级段）？
若两者同义，建议统一为分号（分号已用于分隔多个坐标 `10:10;11:11`，逗号留给区间内），避免解析时猜错。
