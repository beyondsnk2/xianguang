## 一、交付目标与技术选型

### 1.1 第一版交付物

一个**纯前端单页网页**，打开即运行：角色在大地图上自动跑任务，玩家可拖动任务排序，
关掉再打开能结算离线收益。无服务端、无账号、无商业化。

### 1.2 推荐技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **TypeScript** | 配置字段多、状态机复杂，类型能挡住大量低级错误 |
| 构建 | **Vite** | 零配置，`npm run dev` 即可 |
| 渲染 | **Canvas 2D**（地图）+ 原生 DOM（UI 面板） | 地图只需画格子和角色，不需要 WebGL；UI 用 DOM 更好做拖拽 |
| 框架 | **不用**（原生 TS） | 第一版 UI 极简，引入框架只会增加负担 |
| 存档 | **localStorage** | — |
| Excel 解析 | **构建期转换为 JSON**（见 §3.3） | 避免前端引入 3MB 的 SheetJS；`$` 规则在脚本里实现一次 |

> 若希望"改完 Excel 刷新即生效"，可改为前端用 `xlsx` 包运行时解析（把 xlsx 放 `public/`）。
> 代价是包体积与解析耗时。**建议先用构建期转换**。

## 二、配置加载规范（必须先实现）

> 完整字段表见 `配置读取规范.md`，本节只列实现要点。

### 2.1 版本规则

```
config/{配置集}_V{版本号}.xlsx
```

同一目录下同名配置集**只取版本号最大的**文件（`firstShow_V2` 出现时 `firstShow_V1` 自动作废）。
版本号按**数值**比较（`V10 > V9`，不是字符串比较）。

### 2.2 Excel 解析规则

1. **跳过 `$` 开头的标签**（整表忽略）：`$caogao`、`$map`、`$mapRoute`
2. **每张表只保留第 1 行有字段名的列**；无表头的列整列丢弃
3. 空行（首列为空）跳过

### 2.3 构建期转换（推荐）

`tools/export_config.py` 职责：

1. 扫描 `config/`，按版本规则选出最大版本的 xlsx
2. 按上述规则解析所有有效表
3. 输出 `src/config/generated/data.json` + `meta.json`
4. 解析 `position`（`x:y` 或 `x1:y1;x2:y2` 矩形对角）、`a;b` 分隔的多值

调用：

```bash
# 用已装好 openpyxl 的隔离 venv
C:/Users/beyondsnk/.workbuddy/binaries/python/envs/default/Scripts/python.exe tools/export_config.py
```

建议接入 `package.json`：

```json
"scripts": {
  "gen:config": "python tools/export_config.py",
  "dev": "npm run gen:config && vite",
  "build": "npm run gen:config && vite build"
}
```

### 2.4 ⚠ 必须处理的坑

| 坑 | 处理 |
|---|---|
| `~$firstShow_V1.xlsx` | Excel 打开时生成的锁文件（约 165 字节）。**扫描目录时必须跳过 `~$` 开头的文件**，否则会在文件被占用时崩溃 |
| `city` 表右侧的 1–35 编号矩阵 | 无表头，按规则自动丢弃，无需特殊处理 |
| 字段名大小写 | 用 **`itemStacking`**（小写 i）。曾为 `ItemStacking`，按老名字取会拿到空值 |
| 分隔符 | 统一用 **`;`**（分号）。区间用 `min;max`，多值用 `a;b;c` |
| 两套 id 不可混用 | `mapNode.tag` 是**数字** 1–16；`city.tag` 是**英文**（`shangyong`）。通过 `mapNode.belong === city.tag` 关联 |

## 三、数据模型

### 3.1 配置侧（从 JSON 读入，只读）

```ts
interface RawTask {
  tag: 'train'|'trade'|'farming'|'banquet'|'read'|'mining';
  name: string;        // 训练 / 交易 / 种植 / 宴会 / 读书 / 采矿
  nodeType: string;    // barrack / market / farmland / tavern / academy / mine
  nodeName: string;    // 兵营 / 街市 / 农田 / 酒馆 / 书院 / 矿山
  needTime: number;    // 60
  getItem?: string;    // grain | mine
  getItemNum?: string; // '5;7'
  getAttrXp?: string;  // force | politics | leadership | intelligent
  getAttrXpNum?: string; // '10;20'
}

interface RawCity { tag: string; name: string; taskType: string[]; } // taskType = 'barrack;farmland;market' 拆开
interface RawMapNode { tag: number; name: string; position: Cell[]; belong: string|null; }
interface RawMapRoad { tag: number; name: 'road'; position: Cell; roadType: string; }
interface RawAttrLv  { lv: number; num: number; }   // num = 本级升到下一级所需
```

`position` 解析：
- 单值 `'8:9'` → 1 格
- 双值 `'10:10;11:11'` → **矩形对角**（左上 + 右下）→ 展开为 2×2 = 4 格

### 3.2 运行侧（存档状态）

```ts
type Cell = { x: number; y: number };

type TaskSlot =
  | { kind: 'empty';   refillIn: number }        // 补位倒计时（秒）
  | { kind: 'pending'; task: Task };             // 待执行，可拖动

interface Task {
  id: number;
  taskTag: RawTask['tag'];
  cityTag: string;      // 上庸…
  nodeTag: number;      // mapNode.tag
  needTime: number;
}

type Phase =
  | { kind: 'idle' }                                  // 队列空（理论上不会发生）
  | { kind: 'moving';   path: Cell[]; remain: number } // remain 秒
  | { kind: 'working';  remain: number }
  | { kind: 'returning'; path: Cell[]; remain: number };

interface GameState {
  version: number;
  lastTickAt: number;           // 绝对时间戳（ms），用于离线结算
  seedState: number;            // 可选
  // 角色
  cell: Cell;                   // 当前所在格
  phase: Phase;
  currentTaskId: number | null; // 队首任务（锁定，不可拖动）
  // 任务板
  slots: TaskSlot[];            // 长度 = initTaskListSlot
  // 背包与仓库
  bag: Record<string, number>;  // { grain: 12, mine: 4 }
  storage: Record<string, number>;
  // 属性
  attrs: { force: number; leadership: number; intelligent: number; politics: number };
  attrXp: { force: number; leadership: number; intelligent: number; politics: number };
}
```

## 四、核心算法

### 4.1 路网构建（`graph.ts`）

```
节点 = mapNode 的 16 个设施/州府  +  mapRoad 的 80 个道路格  =  96 点
```

规则：

1. **设施占多格时合并为一个超节点**（州府 2×2 的 4 格视为同一个点，内部移动成本 0）
2. 两节点**四邻域相邻即连边**（上下左右，**不含对角线**），边权 = 1 格
3. 边**不落表**，由坐标推导（旧 `mapRoute` 已废弃为 `$mapRoute`）
4. 距离一律走 **Dijkstra**，**禁止用曼哈顿距离估算**

```ts
buildGraph(nodes: RawMapNode[], roads: RawMapRoad[]): Graph
findPath(g: Graph, fromNodeTag: number, toNodeTag: number): { cells: Cell[]; cost: number }
```

`findPath` 返回的 `cells` 是**逐格序列**（含起点与终点），渲染直接沿它插值；
`cost` 是总格数，乘 `speed` 得秒数。

**启动时建一次图即可**，之后复用。设施只有 16 个，可选优化：预计算 16×16 路径表（3.8 ms）。
但实测单次寻路只要 **15.7 微秒**，一天 128 次 = 2 毫秒，**不缓存也完全够**。

### 4.2 时间推进（`tick.ts`）★ 核心

**在线与离线共用同一个 `tick(state, dt)`**，这是整个架构的地基。

```ts
function tick(state: GameState, dt: number): void {
  while (dt > 0) {
    // 1) 推进所有空槽的补位倒计时
    let next = advanceRefill(state, dt);          // 返回 dt 是否被补位事件截断
    // 2) 推进角色当前阶段
    next = Math.min(next, state.phase.kind === 'idle' ? Infinity : state.phase.remain);
    if (!isFinite(next)) {                        // 无事可做，全部吸收
      state.lastTickAt += dt * 1000; return;
    }
    if (dt < next) {                              // 不足以完成任何事件：只推进进度
      consume(state, dt); dt = 0;
    } else {                                      // 结算一个事件
      consume(state, next); dt -= next;
      settleCurrentEvent(state);
    }
  }
}
```

要点：

- **离散事件推进**，不逐秒 tick。在线每帧调用 `tick(state, frameDelta)`；
  离线一次性调用 `tick(state, offlineSeconds)`。
- **期望值驱动，不要每 tick roll**：`每秒产出 = p × 单次量`。
  只有任务**结算的瞬间**才 roll 一次 `getItemNum`（一天约 130 次，开销可忽略）。
- **位置 = f(绝对时间戳)**，渲染只做插值。**绝不能用帧累加**——后台标签
  `requestAnimationFrame` 会被节流到 ~1 fps 甚至暂停，帧累加会直接跑偏。

### 4.3 单任务生命周期（状态机）

```
空槽 ──(180s)──→ 待执行 ──(成为队首)──→ 移动中 ──(到达)──→ 执行中 ──(needTime)──→ 结算
                    │                      │                │                      │
                 可拖动                 锁定              锁定            ┌─────────┴─────────┐
                                                                      背包未满            背包已满
                                                                          │                   │
                                                                          └──→ 回州府存仓 ←────┘
```

| 状态 | 进入条件 | 玩家可拖动 | 逻辑 |
|---|---|---|---|
| 空槽 | 任务结算完成 | — | **每槽独立**倒计时 180 s，到点生成新任务 |
| 待执行 | 生成成功 | **是** | 排队等待 |
| 移动中 | 成为队首（开始移动那一刻） | **否**（锁定） | 沿路径走，消耗 `cost × speed` 秒 |
| 执行中 | 到达 | 否 | 消耗 `needTime` |
| 结算 | `needTime` 归零 | — | 发道具 + 属性经验 → 释放槽 → 触发 180 s 补位 |
| 回州府存仓 | 结算后背包超容 | 否 | 自动走到**最近州府** → 全部入仓 → 清空背包 |

> **拖动锁定点是"开始移动"，不是"到达"。** 若锁在"到达"，玩家可在半路拖走队首，
> 角色掉头、已走的路白费——挂机游戏里这是很强的不适感。

**超载规则（必须严格遵守）**：
正在执行的任务产出**必定完整入包**（不截断、不丢弃），做完后再判超容 → 回城。
不允许出现"装了一半"的中间态。

### 4.4 任务生成（`taskGen.ts`）

```
1. 按权重选一个 task.tag            （V1：6 类等概率 1/6）
2. task.nodeType → 筛选 city.taskType 包含它的城市  （每类恰好 2 座城）
3. 在城市内定位 mapNode（name === nodeType && belong === city.tag）
4. 生成 Task
```

V1 每类任务恰好分布在 2 座城 → 12 个任务点位**等概率**（各 1/12）。

> V2 会引入技能 / 装备 / 倾向的权重叠乘。**届时必须做 clamp + floor**：
> 多层权重叠乘后单类型可能冲到 60–80%，导致任务池塌缩。
> 建议：区域倾向控制在 ×1.5~2 且不排他，最终 **clamp 到 55%**，并保留 floor 权重。

### 4.5 背包与回城

```
容量 = backPackSlotNum × itemStacking = 6 × 5 = 30 个物品
占用格数 = Σ ceil(数量 / itemStacking)      ← 按「格数」计，与 backPackSlotNum 字面一致
超容判定：占用格数 > backPackSlotNum
```

回城目标 = **最近的州府节点**。实测每个设施到本州州府**恰好 3 格**，额外成本仅 0.86 格（17 秒）。

### 4.6 离线结算（`main.ts` 启动时）

```ts
const now = Date.now();
let elapsed = (now - state.lastTickAt) / 1000;

// 1) 时间回拨检测：elapsed < 0 说明系统时间被改小
if (elapsed < 0) elapsed = 0;                    // 直接丢弃，不做补偿

// 2) 离线收益上限
elapsed = Math.min(elapsed, OFFLINE_CAP);        // 建议 8–12 小时

// 3) 一次性推进（离散事件，不是跑 43200 次循环）
tick(state, elapsed);
state.lastTickAt = now;
```

离线 12 小时 ≈ 65 个任务 ≈ 260 次事件切换，**毫秒级返回**。

### 4.7 存档（`save.ts`）

- `localStorage` 存 `GameState` JSON，节流写入（如每 5 秒 + `visibilitychange` 时写）
- **多标签互相覆盖**：用 `BroadcastChannel` 抢占 active tab，
  非 active tab 停止 tick 与写入，否则后写的标签会覆盖先写的进度（真实丢档 bug）
- 存档带 `version`，结构变更时做迁移或重置

## 五、渲染与 UI（表现从简）

### 5.1 地图渲染（`render/map.ts`）

| 元素 | 画法 |

### 5.2 任务列表 UI（`ui/taskList.ts`）

- 7 个槽位，DOM 列表
- **拖拽排序**：HTML5 Drag & Drop 即可，拖 `pending` 状态的槽；
  `empty` 与"当前执行中"的槽**不可拖**
- 建议提供「**一键最优排序**」（贪心：从当前位置出发每次选最近的），
  否则每次上线手动排 7 个格子很快变成负担
- 任务卡显示：`城市 · 设施 · 任务名`、`路程 / 作业 / 预估产出`
- 显示背包占用与仓库总量

## 七、验收标准

### 7.1 路网对拍基准（Dijkstra 真值，必须全中）

| 起点 → 终点 | 格数 |
|---|---|
| 2 兵营/上庸 → 4 农田/上庸（同城） | **6** |
| 2 兵营/上庸 → 8 矿山/新野 | **22** |
| 1 州府上庸 → 13 州府襄阳 | **31** |
| 2 兵营/上庸 → 14 矿山/襄阳 | **37** |
| 6 酒馆/新野 → 14 矿山/襄阳（最远） | **55** |

| 统计 | 值 |
|---|---|
| 图规模 | **96 点 97 边**，单连通分量、无孤立点 |
| 同城设施间距 | 平均 **4.42** 格 |
| 跨城设施间距 | 平均 **37.33** 格，最大 55 |
| 12 个任务点两两平均 | **29.93** 格（含自身 0）/ 32.65 格（不含自身） |
| 独立环数 | **2**（路网近乎树，任意两点路径基本唯一） |

### 7.2 节奏验收（24 小时模拟）

| 指标 | 期望值 | 容差 |
|---|---|---|
| 单任务周期 | **约 660 秒（11 分钟）** | ±10% |
| 24 小时任务量 | **约 131 个** | ±15% |
| 回城次数 | **4–9 次/天** | — |
| 任务板稳态空槽 | 0.27（默认）/ 1.21（精排后） | — |
| 角色空转 | **永不发生** | 硬要求 |

### 7.3 功能验收清单

- [ ] 打开页面，7 个任务槽**立即是满的**（不需要等 3 分钟）
- [ ] 角色自动沿道路走向队首任务点，**不斜穿空地**
- [ ] 到达后开始作业，任务卡显示进度

## 八、实现红线（违反会导致返工）

| # | 红线 | 说明 |
|---|---|---|
| 1 | **逻辑与渲染彻底分离** | `state` + `tick(state, dt)` + `render(state)`。渲染层不得写状态 |
| 2 | **位置 = f(绝对时间戳)，禁止帧累加** | 后台标签 rAF 会被节流/暂停，帧累加必然跑偏 |
| 3 | **在线离线共用同一个 `tick`** | 写两套逻辑必定不一致 |
| 4 | **期望值驱动，不要每 tick roll** | `每秒产出 = p × 单次量`；只在结算瞬间 roll |
| 5 | **不要每帧重新寻路** | 接任务时算一次，缓存路径格子序列，之后逐帧插值 |
| 6 | **正在执行的任务产出必定完整入包** | 不截断、不丢弃；做完再判超容 |
| 7 | **拖动锁定在"开始移动"，不是"到达"** | 否则半路掉头 |
| 8 | **仓库全局共享** | 各城独立会造成"我的粮在永安、人在襄阳"的物流地狱 |
| 9 | **回城全自动，不允许需要玩家点击** | 否则离线时角色卡死，离线收益归零 |
| 10 | **离线收益有上限（8–12 h）** | 既是限损也是品类惯例 |
| 11 | **不要缓存边长** | 将来 `roadType` / 坐骑 / 官道解锁会改变边权，预计算的边长会失效。正确切分：**路径格子序列可静态缓存，耗时必须按当前能力实时算** |

### 8.1 性能参考（实测，Node 22）

| 指标 | 值 |
|---|---|
| 单次 Dijkstra（96 点，朴素 O(V²)） | **15.7 微秒** |
| 一天 128 次寻路 | 2.0 毫秒 |
| 离线 8 小时补算（约 43 次） | 0.7 毫秒 |
| 预计算 16×16 全表 | 3.8 毫秒（一次性） |

**结论：寻路开销完全可忽略，不要为它做优化。** 真正的性能风险在渲染与存档写入频率。
